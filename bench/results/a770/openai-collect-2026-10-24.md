# OpenAI 非流式工具参数收集（2026-10-24）

`serve/server.py:openai_collect` 原来每收到一块参数就拼接字符串，并通过 `setdefault` 创建一个通常用不到的嵌套默认字典。现在按工具索引创建一次状态，参数分块先保存引用、最后用标准库 `str.join` 合并一次；空参数块跳过，整块参数无需额外复制。推理文字也只合并一次。函数名仍按原有方式拼接，工具排序、调用 ID、截断过滤和响应字段不变。

只改这一个收集函数并补一个回归测试；没有增加生产依赖、正则或原生接口。参数分块引用会保留到合并时，不能据此声称内存占用更低或整个服务零复制。

环境：Windows 10 19045，Xeon E5-2696 v4，CPython 3.11.9 x64，固定逻辑 CPU 42。对比本轮改动前后的冻结源码，基线包含此前所有优化。每轮交错执行 7 组 A/B/A，以 B 中位数对比两个 A 中位数的几何平均；A 漂移绝对值超过 3% 弃用。最终两轮共 37/44 项通过漂移规则。该阈值不是置信区间；约 1%～2% 的小幅差异按用户约定视作噪声。

测了两个范围：单独 `openai_collect`；以及 `openai_chunks` 事件转换、完整收集、最终 JSON 序列化和 UTF-8 编码。下表展示后一种范围，负值表示耗时下降。事件与参数分块在计时外构造，排除了模型、分词、解析器、网络和外部工具执行；每次都重新生成协议分块并收集完整响应。正确性断言在计时外，生成链对照只排除每次自然不同的响应 ID 和时间戳。

约 68 KB 参数按 8 字符分块时，完整 CPU 流程两轮分别下降 54.27% / 53.35%，约省 19～20 毫秒；中文、emoji 和转义参数分别下降 80.63% / 79.15%，约省 54 毫秒。256 字符分块只有第二轮通过漂移规则，下降 45.73%。这些收益来自避免重复复制和默认字典分配，未改变模型执行。

全部 44 项计时（包括收集函数单独计时、弃用样本和每组原始时间）见 JSON。这些是合成参数与分块，未测真实请求的长度及分块分布；不能把局部 CPU 收益当成 prefill/decode、真实 HTTP 吞吐或模型端到端收益。README 模型吞吐表没有调整。

5,000 组新旧收集器随机对照全部一致，并验证输入分块不被修改；覆盖交错调用、稀疏/缺省索引、空值、多个工具、ID 更新、Unicode、MCP 数据、计时字段和不同结束原因。计时前还检查 11 个场景的完整协议转换与最终编码结果一致。新增回归测试按 1、7、64 字符及整块输入，覆盖分块函数名、转义/中文/emoji 参数、心跳、交错索引和截断调用过滤。

最终源码的基础回归套件运行 25 项，其中 23 项通过、2 项可选 schema 专项跳过；补充集成套件在前轮隔离安装的 jsonschema 环境运行 37 项，全部通过。覆盖强制工具选择、未完成调用、推理预算、结构化交付门控、usage/timings 和 MCP 工具回合；未重跑全部服务端测试。

首轮原型会保留空参数块，导致整块参数也要复制；最终版跳过空块，使用单元素 `join` 的原字符串路径。原型源码及原始计时仍保存在 `build-sycl-a770-openai-collect-20261024/`，最终冻结源码、变更补丁及证据保存在 `build-sycl-a770-openai-collect-final-20261024/`。原生扫描器源码/二进制、上一轮结构化解析、模型配置及生产引擎 EXE 均通过哈希检查保持不变。
