# 低位 LUT 替换筛查：层、专家、计算与带宽

2026-10-30，检查当前 IQ2_XS pack 与 Strata 的 SYCL 专家路径。机器为 Windows、Arc A770 16 GiB、Xeon E5-2696 v4、256 GiB RAM、PCIe 3.0；本轮新增实验只使用 CPU / NumPy 2.4.6，没有 GPU 性能、模型 PPL 或生成质量测量。

**目前没有找到经过验证、可以直接降到二值/三值的“不重要层或专家”。** 六个已有真实热点专家的数值筛查中，所测降位方案全部增加输出误差。未采到低贡献专家的输出，不能将这个结果推广到所有专家，也不能给出安全替换名单。下一项风险较小的计算优化是保留 Q2_0 权重，用激活 LUT 计算同一个点积；带宽优化则需要先测输出贡献和量化扰动，再选择固定的混合精度专家。

生产引擎、权重、配置未改。本轮新增一个独立检查器、[原始数值](lowbit-lut-2026-10-30.json)和本报告。

## 当前已经很低位

逐行读取本机 `G:/GitHub/Strata-data/packs/iq2_xs/native_experts.txt`，得到 48 层、每层 512 专家。每专家有三个 1,638,400 元素矩阵：gate/up 为 640×2560，down 为 2560×640。下表 bits/weight 包含块尺度等开销，来自 `tools/gguf_reader.py` 的块几何。

| gate/up 格式 | 层数 | 层号 | gate/up 实际 bpw | down | 每专家字节 |
| --- | ---: | --- | ---: | --- | ---: |
| IQ2_S | 34 | 其余层 | 2.5625 | Q2_0，2.25 bpw | 1,510,400 |
| IQ2_XXS | 11 | 1、4、9、10、11、14、18、19、27、29、30 | 2.0625 | 同上 | 1,305,600 |
| IQ1_M | 3 | 8、13、37 | 1.75 | 同上 | 1,177,600 |

专家载荷合计 **35,454,976,000 字节 / 33.0200 GiB**，不含 dense、PLE、MTP、KV 和缓存工作区。原量化器给第 8、13、37 层使用更低位格式，是现有分配事实，不能代替本模型的层消融证据。

源码中的 IQ2 查码本后仍执行 `dp4a`，见 `sycl/src/kernels/cuda/iq_kernels.dp.cpp:146`、`:220`。它已有权重解码 LUT；这与把点积换成激活 LUT 是两件事。Q2_0 的四个编码值为 `{-1,0,1,2}×scale`，不是三值权重，见 `tools/gguf_writer.py` 的 `dequantize_q2_0`。已有 `tools/q2_layout_probe.py` 的三值试验从 Q2_0 再量化；本轮直接使用原始 BF16。

## 容量预算，不是带宽或吞吐实测

独立原型使用每 64 权重一个 FP16 scale：二值权重 8+2 字节，即 **1.25 bpw**；三值将 5 个 trit 编为一个字节，每块填充到 65 个 trit，共 13+2 字节，即 **1.875 bpw**。没有新码本下载或依赖。

| 假设替换范围 | 新专家载荷 | 少占容量 | 相对现有专家载荷减少 |
| --- | ---: | ---: | ---: |
| 全部专家、全部矩阵 → 二值 | 17.5781 GiB | 15.4419 GiB | 46.765% |
| 全部专家、全部矩阵 → 三值 | 26.3672 GiB | 6.6528 GiB | 20.148% |
| 仅全部 down → 三值 | 31.2622 GiB | 1.7578 GiB | 5.323% |

这些假设均未通过模型质量验证。它们只计算载荷，未计格式头、对齐、分组、LUT 和工作区。三值 gate/up 会把 IQ1_M 的 1.75 bpw 提高到 1.875 bpw；保持原 down 时，这三层的完整专家反而增大 **4.348%**。

若只把某 token 的第 9、10 名 IQ2_S 专家整体三值化，且每个专家权重各读一次，该 token 的专家权重字节仅减少 `2/10×(1−1,152,000/1,510,400)` = **4.746%**。它不是整个请求的带宽收益，也未计多 token 复用和缓存缺失。若同时保留两份原/低位权重来动态选格式，还会增加模型容量；不能把运行时低路由排名直接当成离线可删除的专家。

## 新增真实输入数值筛查

复用[已有有效采集](u4-expert-replay-2026-10-27.md)：Code2K、Prose2K，各取第 0、24、47 层最忙专家。权重来自官方固定提交 `de4b8e4d43b917e7706784d8bb445c9af86a3540` 的已有 BF16 切片，输入是该专家实际收到的 FP16 激活。检查器核对输入头、形状、有限值和来源 SHA256。

每份输入事先固定均匀抽取 64 行，共 384 行。二值 scale 为组内绝对值均值；三值对每组排序，选择使平方重建误差最小的非零项集合，再将 scale 舍入为 FP16。没有使用激活拟合、训练或输出补偿。

所有对照使用同一 CPU 数学路径：FP32 点积、SiLU×up、生产范围的 FP16 饱和/舍入、FP32 down。参考使用原始 BF16 权重；当前格式从现有 IQ2_S/Q2_0 blob 解码。它隔离权重变化，**不模拟 decode 的 Q8_1 激活量化、GPU 累加顺序、router、共享专家、combine 或层间传播**。

二值完整专家误差为 **81.53%–88.71%**；二值单独替换 gate、up、down 也均比各自当前基线差。两种模式×四种替换范围×六份输入共 48 项，没有一项误差不增加。它说明朴素降位不是这些热点专家的无损替代，不能据此估算语义损失或认定所有低位量化算法都不可行。

每个真实矩阵还用前两行激活、八个输出维度，独立比较“预构建激活 LUT→按编码查表→缩放求和”和直接解码矩阵乘法。自检覆盖全部 243 个三值码字、末尾填充、零块、可精确表示的权重、载荷长度及非法输入。这里证明编码和 LUT 数学正确，未实现或计时 A770 LUT kernel。

## 冷门专家与低贡献专家

已有采集日志给出上述每层的全部 512 个路由计数。分别在每个请求、每层内按次数选最冷 256 个，得到：

| 请求 / 层 | 从未选中的专家数 | 最冷 256 个的路由次数 / 20,470 | 路由次数占比 |
| --- | ---: | ---: | ---: |
| Code / 0 | 171 | 103 | 0.503% |
| Code / 24 | 94 | 695 | 3.395% |
| Code / 47 | 174 | 100 | 0.489% |
| Prose / 0 | 229 | 27 | 0.132% |
| Prose / 24 | 127 | 426 | 2.081% |
| Prose / 47 | 226 | 30 | 0.147% |

这是三个层、两个构造提示的频率，既不是全模型分布，也不是按缓存缺失加权的 PCIe 流量。冷门专家压缩可以省 RAM；少执行的专家未必能明显减少计算。反过来，冷门专家更易不在显存，也可能占较高的传输比例，需要实际 miss 统计才能判断。它们还可能负责低频但必要的任务，不能仅凭次数判为不重要。

对可替换性，优先记录每次执行的 `p_e×||f_e(x)||`，再实际计算候选的 `||Σ p_e(f'_e(x)−f_e(x))||`；低 router 权重本身不够。最后用固定 teacher-forced 目标比较 NLL，并在独立任务上检查质量、MTP 接受率和完整请求速度。层级替换还需要记录残差/超连接后的变化及后续递归状态，现有热点输入不足以做层重要性排名。

已有[整模型 Top9/Top8 实验](../2026-10-15-a770-expert-prune-model-v3/README.md)也支持谨慎选择：其 502 个模型生成参考目标的 PPL 分别增加 0.293% / 0.676%，MTP 接受率由 72.464% 降到 67.763% / 64.333%。固定工作速度对照还存在一个场景漂移超门槛。这不是新实验，也不是广泛质量基准；它不能证明第 9、10 名安全可丢。

## 优先尝试哪条 LUT 路径

1. **减少计算：先保持 Q2_0 权重，试激活 LUT。** 对编码 `c=b0+2b1`，有 `c−1=0.5(2b0−1)+(2b1−1)+0.5`。因此两张二值位平面 LUT 加输入和的补偿就能计算同一组权重的点积，不需要先挑“不重要专家”，权重仍为 18 字节/64 元素。新增自检独立验证此恒等式，包括负 scale。它不减少权重带宽；GPU 浮点求和顺序与 Q8_1 的每 32 元素尺度仍须验证，不能声称逐位一致。
2. **减少带宽：先校准固定专家/矩阵的量化扰动，再混合精度。** 当前没有合格名单；只凭层号、冷频率或 router 排名不足。已是 IQ1_M 的 gate/up 不优先换成 1.875-bit；所测三值 down 虽有 5.323% 的全专家容量空间，也没有通过本轮局部误差比较。若继续对低贡献条目做实验，应保留 top10/原路由权重，避免把量化效果和删专家效果混在一起。
3. **按阶段测实际代价。** 当前 `NativeExpertLayout` 只有一份 gate/up 类型和一份 down 类型，verifier 按层构造它（`include/strata/kernels/iq_kernels.hpp:54`、`sycl/src/core/verify.cpp:1482`）。逐专家混格式、单独 up 降位需要新的分组/布局支持，不是改一个类型号即可。应先用独立算子比较低 T decode 的完整链，再做模型接入；不能把大 T prefill 的 XMX 倍数搬到 decode。

查表本身有成本。本检查器直接构造的三值 5 元素/243 项 FP32 表，K=2560 时每 token 约 493.6 KiB，K=640 时约 123.4 KiB；二值四元素/16 项表分别为 40 / 10 KiB。这是本检查器的朴素表规模，不是所有 LUT 实现的下限；分块、对称性和表量化可以缩小，但需要计入构表、共享内存、gather/shuffle、缩放与分组成本。现有整数点积每条指令可处理多个元素，不能按“少几次乘法”直接推吞吐。

[T-MAC](https://github.com/microsoft/T-MAC) 明确面向 CPU 混合精度 LUT 乘法，其 BitNet/ARM 或 Intel CPU 数字不能作为 A770 的承诺；[FLUTE](https://github.com/HanGuo97/flute) 是另一种查表量化引擎，现有构建使用 CUDA，也不是本 SYCL 项目的直接替换依赖。两者 README/构建说明于本轮只读检查，未安装。

本机已有[IQ4_XS 寄存器查表实验](iq4xs-register-lut-2026-10-28.md)两轮变慢。它是权重解码表，不是否定所有激活 LUT 的证据，但足以否定“只要 LUT 就超快”的假设。[实际 eager decode 剖析](decode-gpu-profile-2026-10-28.md)中专家链约占累计 kernel 时间的 35.94%；该比例也不能当作正常 graph 的可兑现加速比例。

## 复现

无需模型文件的检查：

```powershell
python -X utf8 tools/lowbit_lut_probe.py --self-check
```

本机已有切片/采集的完整重算；输出路径必须尚不存在，避免覆盖旧结果。运行复用项目的共享实验锁，只在锁内做 CPU 回放，未启动 GPU 或 API。

```powershell
$env:OPENBLAS_NUM_THREADS = '2'
python -X utf8 tools/lowbit_lut_probe.py `
  --weights build-sycl-a770-u4s4-expert-hot-weights-20261027/prepared.json `
  --inputs build-sycl-a770-u4s4-expert-hot-inputs-20261027/model/results.json `
  --native-experts G:/GitHub/Strata-data/packs/iq2_xs/native_experts.txt `
  --rows 64 --out build-lowbit-lut-20261030/recheck.json
```

JSON 保留每组抽样行号、48 个变体、相对 BF16 的误差、相对当前专家的扰动、载荷字节以及源/脚本 SHA256。首次开发自检发现二值 nibble 尚未合成字节，修正后载荷检查通过；首次读取激活时遗漏既有 24 字节头，添加头部核对后运行完成。补充 Q2 恒等式自检与来源元数据后的完整重算，48 个变体数值与首次完成结果一致；原结果保留在本机 `build-lowbit-lut-20261030/first64.json`。这两次是 CPU 数值重算，没有重复挑选性能样本。
