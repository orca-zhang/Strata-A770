# A770：当前 EXE 的缓存容量与运行时余量

A770 16GB / PCIe 3.0 / Windows / driver 32.0.101.9034 / DPC++ 2025.3.2。实际6297→6561槽：Code2K为+0.034%，属于约定的0.3%噪音区间；Prose2K为+1.460%。原冻结协议的联合筛选未通过；用户随后改为单场景验收，Prose达到1%初筛，但尚未独立确认。候选运行时采样最低空闲922.074 MiB，未达到固定1024 MiB门槛，仍不采用。生产EXE与配置不变，35/40 tok/s均未达到。

本组使用同一个当前原始FP32 Down-retry EXE，仅改变专家缓存容量。固定原始Code/Prose各2048输入、完整128输出、graph、FP16 K与packed4 V、context/prefill8192、chain ON/batch OFF、tail64、prompt-cache0、实验min-p0.5；生产min-p仍为0.8。没有修改权重、量化、解包或累加精度，不与旧EXE的6824槽增幅连乘。

先前请求6500对应实际6824槽，但READY空闲仅907 MiB，未达到1024 MiB，在任何候选Short或2K请求前停止。原A1八条完整2K输出匹配，两个引擎退出0，独立失败审计通过。该尝试没有候选测速，不能称为性能回退。

后继请求6250经独立Short16校准为实际6561槽，READY空闲1474 MiB、输出匹配、退出0。两次脚本失败分别发生在导入阶段和监测启动阶段，均为零模型请求，原记录保留。修正后的`finish.py`在新的`performance-v2/`收集正式结果，未覆盖校准、失败记录或冻结脚本。

正式组持共享GPU独占锁，A1/B1/A2均先Short16，再Code/Prose各一次预热、三轮交替保留。全部24条完整2K输出及3条Short与原参考匹配，三个引擎退出0。每条完整请求的48层Down扫描顺序核对通过，共1152次层扫描。所有预热与保留样本均保留。
