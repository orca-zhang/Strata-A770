# A770 生产对象集成 XMX：HTTP 复测（2026-10-25）

将已验证的原生 FP16/BF16 XMX GEMM 接入生产对象后，1,038-token 检索请求三次全部返回正确结果，HTTP 完整响应中位数 **28.595 秒**；旧生产 EXE 的同一请求在 **180.017 秒超时**。短工具请求的吞吐差异为 −0.79%～+0.55%，按噪音处理，没有确认 decode 提升。超时基线没有完成请求，不报告精确加速倍率。

## 条件与改动

硬件为 Arc A770 16 GB、Xeon E5-2696 v4、256 GiB DDR3、PCIe 3.0 ×16；Windows 10、驱动 32.0.101.9034、oneAPI DPC++ 2025.3.2 / oneMKL 2025.3。模型为 Qwen3.8-Flash-Next IQ2_XS pack，FP16 KV、MTP4、8192 上下文、temperature 0、关闭 thinking 和提示缓存。使用本地 Anthropic `/v1/messages` 非流式接口，不执行生成的工具调用。

复用[原生 XMX 实现](native-xmx-2026-10-24.md)，保留生产 main、MTP、verify、路由和量化等对象及静态 oneMKL。Gemm 新增成员会改变布局，因此重新编译匹配头文件的冻结 prefill 对象，工作区仍为原有 **32 MiB**。没有一起启用后续专家链、跨专家提交、HC inject 或 GDN 实验开关。新路径保留 FP16/BF16 输入和 FP32 累加；不适用的布局仍回退。

旧链接脚本引用的 Level Zero SDK 1.32.0 已不在本机，私有构建使用已安装的 1.33.1 import library；该变化也记录在构建清单中。本轮是冻结对象的局部重编译和重链接，未宣称完整重建当前工作区。

## 正式 HTTP 数据

固定请求 5500 个专家缓存槽位，四个测试进程的实际容量均为 **5771 slots / 7.74 GiB**。正式顺序为旧生产 A1 → 候选 B → 旧生产 A2，均使用 `--short-read 1024`。每进程先预热三次 255-token 工具请求，再分别保留三次 255-token、三次原始 258-token 工具请求。A1 的长输入只测一次、限时 180 秒；B 连续测三次长输入；A2 不重复长输入超时。没有重试或择样。

以下为候选 B 的三个正式请求中位数；HTTP 范围是完整最小值～最大值，不是置信区间。

| 场景 | 输入 / 输出 tokens | 等效 prefill tok/s | decode tok/s | HTTP 完整响应中位数 | HTTP 范围 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 短工具 | 255 / 17 | 22.40 | 24.97 | 12.087 秒 | 11.905～12.334 秒 |
| 原始工具 | 258 / 276 | 21.52 | 27.03 | 22.267 秒 | 22.222～23.267 秒 |
| 记录检索 | 1038 / 23 | **38.05** | 17.91 | **28.595 秒** | 28.339～28.839 秒 |

检索请求的引擎输入处理为 27.280 秒，decode 为 1.285 秒；分别以输入量、输出量除以引擎对应时间计算吞吐。HTTP 时间包含模板、分词、引擎计算和完整响应处理，排除服务启动。它不是流式首字延迟。23-token 短输出不代表持续生成吞吐，也不能与 276-token 工具回答直接比较 decode 速度。

两次旧生产基线取各自中位数的几何平均。吞吐变化为 `基线耗时 / 候选耗时 - 1`，基线漂移为 `A2 / A1 - 1`。

| 对照 | HTTP 吞吐变化 | 等效 prefill 变化 | decode 变化 | 三项中最大基线漂移绝对值 |
| --- | ---: | ---: | ---: | ---: |
| 255-token 工具 | −0.32% | −0.37% | −0.79% | 0.36% |
| 258-token 工具 | +0.39% | −0.43% | +0.55% | 0.052% |

18 次正式短工具请求的完整响应在删除随机消息／调用 ID 后一致，包含工具参数、用量和停止原因。三次长输入均自然结束，完整 JSON 都为 `{"first":113,"middle":80,"last":47}`。所有成功请求均 `cache_n=0`。正式轮次共 21 次保留成功、9 次预热成功，以及旧引擎的一次长输入超时。

## 正确性与启用条件

重链接候选通过 **1692 项**数值、布局、尾行、工作区及边界保护检查，没有失败用例。有界随机输入的 XMX 数值门槛为 0.005，回退和保护值要求精确一致；这不是对任意模型数值范围的误差保证。

正式计时前另开诊断进程，使用 `--short-read 256` 强制旧故障输入进入批量路径。255-token 初始化、258-token 工具和长检索均通过；日志确认实际执行了 59,812 次 FP16、536 次 BF16 XMX 调用。诊断轮次开启日志，不纳入性能表。强制批量的工具输出为 92 tokens，与窗口路径的 276 tokens 不同；这里只验证了工具结果合法，没有声称不同路径的回答全文一致。

预先约定：所有检查通过，短工具输出一致，六项对照的基线漂移绝对值均不超过 3%，候选吞吐均不低于基线 3%，才允许进一步做实际自动缓存配置验证。本轮正式对照满足这些条件。

## 实际自动缓存与本机启用

正式测量期间生产配置保持原样。随后另开私有服务，使用实际 `--expert-cache auto` 设置，仅切换 EXE、匹配的 `STRATA_SYCL_BIN` 和 `STRATA_PREFILL_NATIVE_XMX=1`。实际缓存为 **6399 slots / 8.57 GiB**，阈值仍为 1024。先做一次 255-token 初始化，再各做一次原始工具和长检索检查，三次均通过；原工具的完整响应与固定缓存对照一致，长检索 JSON 正确。

| 自动缓存兼容检查 | 输入 / 输出 tokens | 等效 prefill tok/s | decode tok/s | HTTP 完整响应 |
| --- | ---: | ---: | ---: | ---: |
| 原始工具 | 258 / 276 | 21.99 | 24.90 | 22.842 秒 |
| 记录检索 | 1038 / 23 | 37.91 | 16.34 | 28.816 秒 |

这是每项一次的切换前兼容检查，预热数量和缓存容量与正式对照不同，不据此推断性能变化。五个私有服务均以退出码 0 结束。

检查通过后，本机 `strata-iq2_xs.json` 已原子更新上述三个字段，**下次启动服务生效**。自动缓存、`--short-read 1024` 和其余设置保持原值。旧配置原始字节保存在 `build-sycl-a770-production-xmx-v2-20261025/measure/production-config-before.json`；新配置快照及两侧 SHA256 一并纳入离线复核。

## 范围与复核

这是本机 IQ2_XS、两个短工具输入及一个 1,038-token 检索任务的证据。没有验证更长上下文、独立 Q2 模型、PCIe 4.0、并发或通用生成质量；32 MiB 工作区不足等不适用情况仍可能回退至原路径。不能将此前独立算子、128 MiB 工作区或 Q8 KV 实验的倍率与本轮相乘。
