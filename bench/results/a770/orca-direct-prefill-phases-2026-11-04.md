# Orca Direct：2K／8K 预填充差距的分段定位

2026-11-04，Windows 10 22H2，Intel Arc A770 16 GB，驱动 `32.0.101.9034`，oneAPI 2025.3。

此前[无探针对照](orca-direct-dependency-only-2026-11-04.md)中，Direct 相对共用数学 pack 的 L0，
2K／8K 预填充分别少用时 14.15%／3.44%，但提交数量的优势没有随长度消失。
本轮用隔离诊断解释时间花在哪里，**不将诊断耗时发布为新吞吐或端到端收益**。

## 测量方法

每个后端只重编一个预填充 Host TU；运行时、其它 Host 对象、数学 pack、模型及参数复用冻结版本。
新对象显式参与链接，原库中对应对象不再需要提取；没有重烘数学模块或修改部署程序。
Direct 固定依赖合并开启、BCS1。进程顺序 **L0 → Direct → L0**，每进程先运行 15 次 Short，
再运行 2K／8K 各一次，共 51 次完整输出、草稿数量、结束和复用状态全部匹配。

每个长请求记录 495 个 GPU 原始时间戳，共 2,970 个标记、2,964 个相邻区间。
每标记使用独立 64 字节 host slot，检查全部已用 slot 的保护字与未用 slot；全部通过。
每请求 48 个 Host 分组、48 个整段专家链、48 个 combine、36 个 GDN recurrence 和 12 个 QSA attention 区间，
原始标记数量、36 位回绕和区间总和全部核验通过。

两条路径统一使用该 A770 已校验的名义 19.2 MHz，避免 L0 整数 52 ns 与 Direct 52.0833333 ns 的换算差异。
实际计数器相对名义频率的小幅偏差仍存在；本轮不重新校准或声称高精度绝对时钟。

时间戳前保留 queue barrier；省去逐专家的 wait／dequant／GU／Down 标记，合并到“聚集与专家链”。
已有 `pt.on` 还会在 chunk 开始和 embedding gather 后各等待一次，并输出少量 setup 日志；
Host 时间戳分配、这些等待、标记与日志都会改变调度。
**相邻标记间既有 GPU 工作，也可能有 CPU 派发、搬运和依赖空隙，不能解释为独占 kernel 计算时间。**

## 主要观察

“三段投影”仅合计 GDN 输入、GDN 输出及 QSA 投影；不把 HC 或 router／shared 计入其中。

| 输入 | 三段投影：L0／Direct | 三段投影占比：L0／Direct | 专家链占比：L0／Direct | 专家链差值 | 三段投影差值 | 总时间线差值 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| Code2K | 9.966s／10.586s | 36.33%／45.23% | 55.53%／45.37% | -4.614s | +0.620s | -4.027s |
| Long8K | 38.689s／41.436s | 54.02%／59.93% | 34.39%／27.23% | -5.802s | +2.747s | -2.478s |

这轮给出两条后续定位方向：长输入中，投影区间的占比明显上升；同时，Direct 专家链的节省
被较长的投影区间部分抵消。两者共同解释了为什么仅看提交数量的降低不能预测 8K 的净时间变化。
这里定位的是阶段区间，尚未区分其内部的 GEMM、反量化、参数放置、cache 或硬件调度成本，
不能把整个差值归给其中某一个机制。

Host 分组区间只占很小一部分，不能把数秒级差距归给该段分组工作。
它不覆盖专家链内部全部等待；当前依赖合并和专家配对也没有等待凑满批量的计时器。
下一步应优先隔离大 T 的 GDN／QSA 投影，再研究专家链内部；先核对实际形状、原生 kernel 和资源状态，
避免再次试验已经没有整模型收益的 polling、Point batch 或小 primary。

源码检查还显示：通用 FP16 XMX 路径仍用 M4，而双专家的 M16 仅覆盖专家配对；
通用大矩阵的寄存器复用是可验证的后续候选，**本轮没有实现或宣称它有收益**。

## 条件和复现

固定 5,771 专家槽、reserve1,536MiB、read256、decay0.95、margin1.5、MTP4、step／last min-p0.5、
cumulative0、suffix0、cost-window0、prompt-cache0。Short／2K／8K 输入分别为 28／2,048／8,000 token。
长请求每进程只有一次，没有建立稳态或跨日重复性；不外推 Linux GPU 或 PPL，原 8K 间歇异常仍未解决。
本轮没有运行时源码接入或默认配置改变，Orca L0 仍为推荐路径。
