# A770：GU 工作组大小的双基线对照

A770 16GB / PCIe 3.0 / Windows / driver 32.0.101.9034 / DPC++ 2025.3.2。**WG128 未通过混合驻留的重复 1% 收益门槛；没有接入模型，没有新增已验收的整模型收益。**

[实际 decode 采集](decode-gpu-profile-2026-10-28.md)确认当前冻结 IQ2_S GU 使用 WG256。旧 WG128 对象还包含其他代码差异，不能直接替换来解释工作组大小的作用。本组保留原 `iq.obj` 和公共符号，新增唯一导出，在同一 EXE 中比较原对象 A、新 helper 的 WG256 C、同一 helper 的 WG128 B。B/C 的计算、运行时维度、SG16、SwiGLU/Q8 和 Down 实例完全相同，只有 GU 工作组大小不同；C 相对 A 仍包含 helper 重编译差异，不能算作 WG128 的收益。

真实 IQ2_S GU/Q2_0 Down，240 个专家、八组物理权重、N2560/F640、GU16/Down4。mixed4/mixed8 分别将每第四/第八个物理专家指针指向 `malloc_host` 镜像，其余指向 device USM；这是合成驻留比例，不是模型路由统计。vram 全部位于 device USM，仅作诊断。没有更换量化格式、精度或权重布局。

六个边界进程覆盖随机/大值稀疏输入、组长度1–7，共288条完整专家链。计时顺序为 A1/C1/B1/C2/A2/C3/B2/C4/A3，各臂依次运行三种布局，共27个新进程。每进程48条完整 eager 输出、完整 Q8 字节、非零起点、分散输出、空组及 scratch/output 守卫检查通过；六个图的最终输出也与原对象参考一致。每个 T=1–6 预热16图，保留11批，每批4次48链重放；共1782个计时批次，全部保留。用主机时钟计量提交至图完成，未开启 profiler，没有将事件跨度当作独立 kernel 时间。stderr 分派记录确认每个形状实际进入指定模式。

每个128候选同时对照相邻原对象与相邻同代码256。相邻基线耗时取几何均值，吞吐提升至少1%、基线耗时漂移不超过3%；两个独立128进程、两种混合布局都须通过。绝对吞吐变化小于0.3%按噪声解释，原数值保留。

mixed4/T1 第二轮原对象基线漂移3.924%，该轮对原对象的正值排除。全部混合形状对同代码256的提升均低于1%，两轮范围分别为−0.644%至+0.496%、−0.594%至+0.787%；它们不支持缩小工作组有稳定收益。小于0.3%的变化按噪声处理，其余不足1%的差异也未达到接收门槛。

重建256相对原对象的纯显存收益为3.021%–6.741%，提示两份 helper 的代码生成值得单独检查，但混合驻留下没有任何 T 在全部四个256臂、两种布局中都通过1%/3%检查。这是探索性核对，不能据纯显存结果开启当前模型中的混合调用。此次保留原对象和现有生产配置，35/40 tok/s目标仍未达成；算子输出一致也不能替代模型质量、显存余量或历史间歇故障的稳定性检查。
