# A770：复用专家复制事件，正确性通过，未确认端到端收益

本轮只尝试省掉锁页专家 DMA 后的一次空屏障，直接将 `memcpy` 返回的完成事件交给计算队列。专家等待间隔仍为 8，保留槽位释放依赖、两个解量化缓冲区和 32 MiB 工作区。

**48 项双队列检查通过，45/45 次 HTTP 请求正确，27 次正式完整响应一致；长输入生产基线漂移超过 3% 门槛，候选未采用。生产继续使用 HC inject 8 专家版。**

## 条件与流程

- A770 16 GB、Xeon E5-2696 v4、256 GiB DDR3、PCIe 3.0 x16、Windows；驱动 32.0.101.9034，DPC++ 2025.3.2 / oneMKL 2025.3。
- IQ2_XS、FP16 KV、MTP4、完整草稿词表、short-read 1024、context / prefill 8192，关闭提示缓存。固定请求 5500 个专家槽位，实际均为 5771。
- A1 / A2 使用同一冻结生产 EXE；B 仅重编译 prefill，其余生产对象全部复用。复核确认编译选项一致、GEMM 头文件相同。没有改变数值精度或专家等待间隔。
- 每个新服务先运行三次 tool255，再分别预热 tool258、1K、2K；随后保留三轮交错的 1K、2K、tool258。全部预热与正式样本均保留，没有重试或替换样本；三个服务均退出 0。
- 新增检查覆盖两条有序队列、8 槽环、1 / 7 / 8 / 9 / 17 / 65 次复制、31 至 352257 个 uint32 元素、完整输出和边界保护，分别验证空屏障与直接复制事件。
- 两把共享 GPU 锁覆盖构建、检查和全部测量；执行前恢复 Normal 优先级。相同的独立只读 Sysman 进程每秒采样，未启用 GPU 事件计时。

## 绝对速度

各值为每组每场景三个正式样本的中位数。HTTP 包含完整请求；等效 prefill = 输入 tokens / 引擎 prompt 时间，decode = 输出 tokens / 引擎 predicted 时间。每次均重新预填，专家驻留仍随请求调整。

| 场景（输入 / 输出 tokens） | 组别 | HTTP 秒 | 等效 prefill tok/s | decode tok/s |
| --- | --- | ---: | ---: | ---: |
| 1K（1038 / 23） | A1，生产 | 17.851 | 63.53 | 15.48 |
| | B，复制事件 | 16.202 | 70.51 | 15.94 |
| | A2，生产 | 16.201 | 70.51 | 15.99 |
| 2K（2069 / 25） | A1，生产 | 25.566 | 86.68 | 15.03 |
| | B，复制事件 | 23.573 | 94.43 | 15.34 |
| | A2，生产 | 23.350 | 95.29 | 15.43 |
| 工具（258 / 276） | A1，生产 | 22.782 | 21.57 | 25.62 |
| | B，复制事件 | 22.373 | 22.01 | 25.99 |
| | A2，生产 | 22.236 | 22.13 | 26.27 |

23 / 25-token 短检索的 decode 仅作描述；276-token 工具输出作为 decode 控制。

## 验收与监控

预先沿用 3% 门槛：受控 HTTP / prefill 和工具 decode 的前后生产基线耗时漂移绝对值不超过 3%，候选吞吐回退不超过 3%，至少一个长输入 HTTP / prefill 吞吐提高 3%。

| 场景 | A1 → A2 HTTP 耗时漂移 | prefill 耗时漂移 | 稳定性门槛 |
| --- | ---: | ---: | --- |
| 1K | −9.244% | −9.897% | 未通过 |
| 2K | −8.670% | −9.032% | 未通过 |
| 工具 | −2.396% | −2.516% | 通过 |

候选与后置生产 A2 的长输入速度接近。前后生产基线未保持稳定，不能将候选相对 A1 的改善确认为优化收益。工具 decode 的配对基线为 **25.94 tok/s**，候选 **25.99 tok/s（+0.185%）**，按噪音处理。未进行额外自动缓存兼容服务，未修改生产配置或公开引擎源码。

频率范围取完整 HTTP 请求期间的采样，未对齐到精确 GPU 阶段；工具正式请求均采到 2400 MHz，低频记录出现在长输入请求中。采样可能遗漏短暂变化，监控开销未单独量化，PCIe 流量计数器不可用。**这些记录不足以确定跨进程漂移的原因，也不能证明频率变化造成了耗时差异。**
