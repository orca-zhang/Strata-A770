# 当前完整前端：Short／2K／8K 的 Direct 与 L0 对照

2026-11-04，Windows 10 22H2，Intel Arc A770 16 GB，驱动 `32.0.101.9034`。用户确认机器空闲后运行。

使用同一次完整前端重建、同一份数学模块与匹配的专家替换 margin 1.5，进程顺序为 L0／Direct／L0。没有进行反向长请求对照：本轮先用前后漂移很小的参照定位较大的预填充差距，小幅 decode 差距不建立稳态或长度因果结论。

本轮双方都关闭 suffix draft 和 MTP cost window，只使用 MTP 草稿；绝对速率不能直接拼接到此前 Short 协议。step／last 门槛均为 0.5，cumulative 为 0。

## Decode 与首 token 分开统计

每个进程先运行 Short（丢弃 10 次、保留 5 次），再运行 2K、8K（各丢弃 1 次、保留 3 次）。长请求专家缓存仍可能变化，以下中位数描述有限次请求，不代表稳态。

decode 使用引擎 DONE 净解码时间，排除加载、初始化、准备和预填充；TTFT 使用请求发出至首 token 的墙钟时间。没有内部阶段计时、GPU 时间戳或遥测，GPU 时钟未锁定。

本轮净 decode 的 Direct 差距为 Short −1.8293%、2K −1.5055%、8K −2.2072%，没有随长度明显缩小。预填充时间则分别增加 0.1745%、6.6208%、7.7548%，2K／8K 两侧预填充漂移只有 +0.0222%／+0.1573%。优先定位长请求动态命令路径；这些观测本身尚未证明某段代码造成全部差距。

## Bitmap 可以放在哪里

以下是源码检查得到的候选位置，本轮没有实施或测量 bitmap 的模型吞吐收益。

- 资源去重：`orca-l0/src/drm/arguments.hpp:46` 的 retain_storage 已有 recording_index 快速路径，失败才线性扫描。应先计数回退率；若多列表交错使它频繁失效，再比较每列表 bitmap 与代际标记。资源 ID 必须稳定，回收／复用后不能把新资源当成旧资源。
- 批量专家集合：预填充目前按专家扫描和分组，可用 requested & ~resident & ~inflight 找待加载集合，再用尾零计数遍历置位 bit。bitmap 辅助集合操作；现有 residency_ 的 expert 到 slot 映射仍需保留，它本来已经支持常数时间查询。逐个查询少量 Top-K 时，构建 bitmap 未必划算。
- 参数脏块：只有脏区分散、当前最小／最大范围上传包含大量未改字节时，脏块 bitmap 才可能减少字节。当前 parameter_uploads 已按 slab 合并范围；本轮更突出的观测是大量同步提交／等待，应先验证合并上传或调整动态参数放置。
- 就绪任务：可用 ready／inflight 位集合辅助挑选可组成同形状批次的任务。GPU 完成仍由 fence／sequence 和资源生命周期决定；bitmap 表示就绪集合，不能直接代替硬件同步。当前每次依赖合并最多 16 队列，单纯给这段小数组扫描增加 ID 映射未必节省时间。


## 条件、正确性与复现

固定锚定参数为 read256／decay0.95、实际 5,771 专家槽、1,536 MiB 显存预留、MTP4、V4 缓存及 FP16 双专家预填充。这不是日常平衡参数的吞吐承诺。Short 输入 28 token、自然结束 76 token；2K 输入 2,048、8K 输入 8,000，均生成 64 token，无前缀复用。

69 次正式请求（33 次保留）加 6 次独立 smoke，输出 token ID、终止条件及相同序号的草稿工作量完全匹配。另有 23 次匹配的独立诊断，以及保留失败的三次缩短历史诊断。Direct 的模块检查排除了 SYCL／UR／Intel 用户态运行时。没有测量 PPL，也没有进行 Linux GPU 验证；固定样本相等不能建立全模型质量等价。

在具备同一模型、冻结可执行文件、数学模块、驱动、输入及参数的机器上可按相同条件复现。公开证据包含原始协议、日志、配置、脚本和 SHA-256；二进制及模型不随档案分发，模型数据文件没有在本轮完整重哈希。新目录各只能运行一次，原证据不得覆盖。
