# 结构化 JSON 输出：省去边界扫描（2026-10-24）

`serve/structured.py` 原来先用 Python 逐字符寻找对象边界，再把截取的对象交给 `json.loads`。现在直接用标准库 `JSONDecoder.raw_decode(text, start)` 解析第一个对象，省去手写循环及对象子串复制。代码围栏处理保留；没有对象起始符的输入仍走 `json.loads`，保持完整输入校验和原有 BOM 错误信息。成功路径不再为错误位置复制子串，只有错误时才调整相对位置。

生产改动限于这段解析和一个回归测试；没有新增依赖、正则或原生接口。仍然拒绝重复键、非有限数字、不完整输出和 schema 不匹配的对象；仍按原有规则允许对象前后的说明文字。对象内部的解析、规范化输出和 schema 校验继续执行，不能称为零复制。

计时覆盖完整 `validated_json` 调用：清理包装、创建解码器与严格解析钩子、解码、规范化序列化、对象类型或完整 JSON Schema 校验。输入、validator 构造和正确性断言在计时外。schema 校验器在请求准备阶段创建，这与服务实际调用方式一致。

环境：Windows 10 19045，Xeon E5-2696 v4，CPython 3.11.9 x64，固定逻辑 CPU 42。可选 `jsonschema 4.26.0` 及其依赖只安装在本次构建目录的 `test-deps/`，没有修改项目依赖或默认 Python 安装。

比较本轮改动前后的冻结源码，基线已经包含此前优化。每轮交错执行 7 组 A/B/A，以 B 中位数对比两个 A 中位数的几何平均；A 漂移绝对值超过 3% 弃用。两轮共 23/30 项通过漂移规则。该规则不是置信区间，也不能排除所有干扰；负值表示耗时下降。约 1%～2% 的小幅变化仍按用户约定视作噪声。

有效样本中，短对象耗时下降约 39%～42%，每次节省约 5 微秒；51 KB 文本下降约 94%～95%，每次节省约 4.8～5.1 毫秒。51 KB 文本加完整 schema 的两轮均下降约 94%；128 条记录逐项 schema 校验仅第二轮有效，下降 16.24%。5,000 个整数逐项 schema 校验两轮都因漂移弃用，没有据此作出收益结论。
