# 提示词标记还原移除正则（2026-10-24）

`unmark_think_literals` 现在用 `str.find` 找到标记，按位置稳定排序，再还原文字及 tokenizer 的普通文本范围。删除了默认标记的预编译正则和自定义标记的动态正则。重叠标记仍按映射顺序优先匹配；支持多字符标记、空标记、Unicode、NUL 和孤立代理项；空映射返回原文本和空范围。

没有新增依赖或原生接口。上一轮的 SSE2 反引号和参数扫描保持不变；这次字符串查找的收益没有单独归因于 SIMD。Python 回退中的反引号及参数终止符正则仍保留。

Windows 10 19045、Xeon E5-2696 v4、64 位 CPython 3.11.9；测量进程固定在逻辑 CPU 42。使用本机 IQ2_XS pack 的真实词表（248,320 项）、247,587 条合并规则、聊天模板和 29 个文字标记。修改前后从冻结的完整模块分别加载。每次 A/B/A，每臂 7 个样本，B 中位数对比两个 A 中位数的几何平均；基线漂移绝对值超过 3% 则弃用。共两轮，包含 Python 调用、输出文字和范围列表构造开销。

下表是标记还原函数的耗时变化，负值表示更快：

| 场景 | 字符数 / 标记数 | 第一轮 | 第二轮 |
| --- | ---: | ---: | ---: |
| 一个标记 | 64,001 / 1 | −84.41%，3.442→0.536 ms | −83.87%，3.393→0.547 ms |
| 稀疏标记 | 64,080 / 32 | −83.95%，3.581→0.575 ms | −83.09%，3.428→0.580 ms |
| 密集标记 | 29,000 / 29,000 | −44.55%，49.470→27.432 ms | −4.80%，31.636→30.119 ms |

稀疏场景的函数耗时稳定下降约 83%～84%。密集场景两轮差异大，不声称有固定比例的提升。新算法收集所有匹配位置再排序，额外空间随匹配数量增长；若密集标记的内存成为瓶颈，可改为合并各标记的位置流。
