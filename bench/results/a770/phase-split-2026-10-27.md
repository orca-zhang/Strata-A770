# A770：prefill 用 U4×S4 GEMM，decode 用 GEMV（2026-10-27）

按计算阶段分别探索，已有两次独立进程确认的算子结果。prefill 的较大矩阵采用原始 BF16 直接 repack 的 U4×S4 DPAS；decode 保留原权重与未做 S4 量化的激活，优化 GEMV 连续读取与多行复用。新增检查器，不改变生产引擎、默认分派或配置。

输入来自[已确认的官方原始 BF16](bf16-expert-sources-2026-10-27.md)：主模型 layer0/expert0 的 fused gate/up（N=1280、K=2560）及 down（N=2560、K=640）。没有从 Q2 或 IQ2 重量化。每种矩阵使用 8 个内容相同的独立显存副本；不是 8 个不同专家，也不包含 PCIe 调入。

平台为 A770 16GB、E5-2696v4、Windows、DPC++2025.3.2、Level Zero，设备报告驱动 `1.17.39500+2`。输入为种子 271027 的高斯数据及每 256 项一个 16 倍离群值的第二组数据，再舍入到 BF16。它们不是捕获的模型激活。

## Prefill：一次权重 repack，每次激活 pack，整数补偿与缩放融合

权重为 v002 正 scale radix16 双 U4，含一个 FP32 group64 scale 后的文件载荷为 **8.5 bits/weight**；两个 U4 平面本身占 8 bit。激活用两份 S4 残差，每个 group64 每个输出 tile 共四次 DPAS。不是单 W4A4，也不能按 INT4 峰值推算有效吞吐。当前独立检查器保留了额外辅助缓冲，没有测模型存储或显存节省。

将权重 high/low 的整数项先按 radix16 合并，减去 `136*sum(S4)`，再作分组 FP32 缩放。NC1 每工作项算 8×8；NC2 算相邻两个 8×8 输出 tile，共享激活的读取与元数据。没有把激活量化重复塞进每个输出 tile。计时包括每次激活量化/pack、四 DPAS、补偿、scale 和输出，离线权重 repack 不计时。

基线是现有 standalone BF16 joint_matrix SG8、8×8/K16、FP32 累加的原生 XMX 投影，与预填 native kernel 的基本计算布局一致；没有将它称为所有 GEMM 实现中的最优基线。检查覆盖 T=8/9/16/40/64/128/256，包括尾行。新内核相对同一量化码字的原四乘积实现，最坏完整输出 NRMSE 为 **2.997×10⁻⁷**；相对原 BF16 投影，普通/离群输入的最坏 NRMSE 为 **1.8169%**，通过事先固定的 5%/10% 算子门槛。

## Decode：SG16、128-bit 权重读取、向量激活与多行权重复用

基线是当前 `native_bf16.dp.cpp` 的 `bf16_gemv_fp32_mmvf_multi`，使用原始 BF16 权重、FP32 激活和 FP32 输出。候选不改变这些格式：每个 SG16 处理一个输出行，每 lane 一次加载 8 个 BF16 权重和 8 个 FP32 激活；对 1/4/6 个 token 复用权重，再做 subgroup 归约。初始激活值来自同一批 BF16 舍入数据，随后以 FP32 保存；不是 S4 激活。

候选改变浮点归约顺序，因此没有逐位相同声明。两组输入、三个 T 的完整输出最坏 NRMSE 为 **1.536×10⁻⁷**，低于预设 2×10⁻⁶；CPU64 角点参考、两侧及未用输出哨兵均通过。没有完整模型输出或质量声明。

## 方法、失败记录与复核

三组实验均在计时前冻结协议，同一 EXE 内 ABBA，另用新进程独立确认全部配置，包括失败配置。每轮两臂各自首尾耗时漂移绝对值须 ≤3%；至少 6/8 轮稳定，稳定轮配对吞吐增幅中位数 ≥3% 才通过。吞吐变化为 `sqrt(A0*A1)/sqrt(B0*B1)-1`。无频率采样，不据端点门槛声称 GPU 频率不变。

| 本地隔离目录 | 计时方式 | 结果 |
| --- | --- | --- |
| `build-sycl-a770-phase-split-20261027` | 64 对预热，8 ABBA，每臂逐次提交 64 调用后等待 | 全部未获稳定确认；保留负结果 |
| `build-sycl-a770-phase-graph-20261027` | 每图 16 调用，16 对图预热，8 ABBA，每臂同步重放 32 次 | prefill 六个配置获两次确认；decode 无交集 |
| `build-sycl-a770-decode-gemv-graph-20261027` | 同一 GEMV 算法；每图增至 128 调用，其余次数不变 | decode 六个配置获两次确认 |

图执行在计时前后都将完整输出与各自非图参考逐位比较。图与非图的绝对耗时不能混用；长图是新的独立测试批次，不用它覆盖先前不稳定结果。这里的时间包含主机图提交与等待，不是设备事件计时。共享 GPU/编译锁保证本轮各计时串行；长图批次曾等待另一个工作区实验释放锁，没有停止其他进程。

可复用的检查器为 [`u4s4_phase_check.cpp`](../../../sycl/src/prefill/u4s4_phase_check.cpp)，CMake 目标 `u4s4_phase_check`。它复用已有 U4 pack、DPAS 和 BF16 XMX 参考，仅用于实验；带实权重参数的运行本身就是数值、边界检查。命令图测量源码及完整构建命令保留在上述隔离目录。

```text
u4s4_phase_check.exe raw.bf16 positive-radix16.u4 1280 2560 prefill
u4s4_phase_check.exe raw.bf16 positive-radix16.u4 1280 2560 decode
```

上述为正确性运行；末尾加 `--bench` 才计时。源码版是逐次提交路径；不要将它的计时与上表命令图结果等同。当前只接受 N 为 8 的倍数、K 为 128 的倍数及文档范围内的尺寸。

完整结果保留 **632 条精度记录、1,184 个 ABBA 周期**。它们包含同一权重与固定输入的重复校验，不表示 632 组独立模型样本。[JSON、协议与摘要](phase-split-2026-10-27.json)；离线复核不运行 GPU：

```powershell
python -X utf8 bench/results/a770/check_phase_split_20261027.py
python -X utf8 bench/results/a770/check_phase_split_20261027.py --local
```

后续接入遵循两层判断：先按 prefill/decode 阶段选路线，再按路由后每专家的实际行数和驻留位置选内核。prefill 中的小专家组也需保留 GEMV/小矩阵路径；decode 的少量验证行不直接套用大矩阵 U4×S4。
