# Anthropic 协议转换分配（2026-10-24）

`serve/server.py:anthropic_events` 原来每收到一个正文/推理/新工具事件，就重建相同的四项类型映射；每次打开内容块，又先构造推理、正文、工具三种块及选择字典，再丢弃未选中的对象。现在每个请求构造一次类型映射，并只构造当前需要的块。类型映射仍按原有规则拒绝不支持的事件。生产代码只调整这个函数。

基线为本轮改动前的冻结源码，已经包含上一轮 Anthropic 正文/推理分块收集，以及此前工具参数、JSON 解析和 Responses 索引优化。本轮测量的是在这些优化之上的增量收益，不能直接与更早报告相加。

两轮均有效的非流式结果：100 个交替短内容块耗时下降 **13.81% / 13.40%**（每次省约 51 / 60 微秒），100 个短工具调用下降 **7.38% / 3.89%**（约省 51 / 33 微秒），中文/emoji 推理与正文下降 **11.71% / 8.70%**。约 68 KB 正文按 8 字符分块只在第二轮有效，下降 12.95%；4 KiB 正文非流式只在第一轮有效，下降 9.02%，未作两轮有效收益描述。

流式增益较小，幅度也不如非流式一致：100 个交替短内容块两轮下降 **8.54% / 2.80%**；4 KiB 正文下降 **4.40% / 2.63%**；短推理加正文下降 **4.30% / 3.79%**；推理与正文各 32 KiB 时下降 **2.61% / 2.55%**。普通短正文和单个短工具调用没有稳定收益；长工具参数的非流式变化不到 1%，SSE 两轮都因漂移弃用。本次没有把小幅变化普遍解释为提升。

环境：Windows 10 19045，Xeon E5-2696 v4，CPython 3.11.9 x64，性能计时固定逻辑 CPU 42。两轮各执行 7 组交错 A/B/A，B 中位数对比两组 A 中位数的几何平均；A 漂移绝对值超过 3% 弃用。共 47/56 项通过漂移规则，全部原始样本和弃用结果保留。规则不是置信区间；约 1%～2% 的变化按用户约定视作噪音。未因小幅变化额外重跑。

5,000 组随机差分全部一致：比较完整协议事件序列、逐字节 SSE 编码、最终非流式响应，同时确认输入模型事件没有被修改。差分时仅固定响应 UUID，性能计时使用真实 UUID。覆盖推理/正文切换、空增量、多工具、整块/分块参数、未完成调用、Unicode/emoji/转义、心跳、stop/length/cancel、停止序列、缺少结束事件和缓存 token 截断。另检查不支持的事件仍抛出相同的 KeyError。每个计时场景还在计时前对比协议事件、收集结果和 SSE 字节。

27 项既有测试与新增的 1 项回归检查均通过，无跳过。既有测试覆盖真实 HTTP 的 OpenAI/Anthropic 完整及截断工具调用、强制工具选择、推理预算与 Anthropic usage。新增检查覆盖四种连续内容块、空推理不打开块、截断调用被移除、停止原因和工具 input 字典彼此独立。生产代码差异通过 `git diff --check`。

这是合成事件上的 **CPU 协议后处理** 数据，不含模型推理、分词、模型输出解析、HTTP 网络和外部工具执行；不能换算成 prefill/decode 或真实模型端到端收益。没有测真实请求的事件长度/数量分布，也没有测内存峰值。实际收益取决于协议转换在请求中的占比。

模型配置、生产引擎、tokenizer 和 README 通过不变校验；原生扫描器、结构化解析、Responses 索引和上一轮收集函数也保持基线状态。README 的模型吞吐表没有使用本次 CPU 数据。
