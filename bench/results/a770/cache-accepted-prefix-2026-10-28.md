# A770：仅用已提交推测前缀更新专家热度

A770 16GB / PCIe 3.0 / Windows / DPC++ 2025.3.2。根据[实际内存计数](host-device-metrics-2026-10-28.md)，本组检验过滤未提交行的缓存热度是否能改善热点驻留。**完整 2K/128 筛选未通过：Code −1.119%，Prose −0.522%，没有采用。** 当前用户目标 40 tok/s 仍未达到。

原 verifier 在 GPU 窗口完成后，为窗口全部输入行的专家增加 LFU 热度；首个不匹配草稿之后的行也会计入。候选只将热度递增限制到与实际 greedy commit 相同的输入前缀：第一行加连续接受的草稿行。仍用已有等待后的 token/argmax 和路由 ID；全窗口命中统计、路由 trace、权重、精度、kernel、草稿策略和换入限制均保持。该前缀计算针对本组 greedy 链路，不能直接推广到随机采样或其他接受算法。

初版 `build-sycl-a770-cache-accepted-prefix-20261028/` 的原版 A1 已完成九场景、758 个固定目标、正常退出，全部必需评分有限且精确匹配冻结参考。但验收在读取汇总日志时失败：服务使用 `std::_Exit(0)`，不会执行 `Stats` 析构函数。此失败是计数观测缺失；没有候选质量或性能结论。原始结果保留。

独立 V2 `build-sycl-a770-cache-accepted-prefix-v2-20261028/` 改在每个完整路由窗口之后输出并刷新累计计数，避免依赖析构。计数检查要求窗口序号连续、每次提供/提交行数合法、热度计数与开关一致、裁剪窗口增量准确，以及完整 48 层×10 专家的条目数和命中增量合法。原 40 个 CPU 前缀/边界/输入不变检查通过；新增真实 `_Exit(0)` 检查通过。只重编 verifier，保留原 FP32 重算 prefill 和全部数学对象，两臂使用同一 EXE。

执行顺序为 A1/B1/B2/A2 九场景质量，再决定是否启动原始 2K/full128 性能组。两臂固定实际 6297 个缓存槽、reserve1024、READY 空闲至少 1024 MiB、graph/FP16 KV、实验 `--spec-min-p 0.5`、chain 开启、batch 关闭、裁剪关闭、分析关闭；生产阈值仍为 0.8。缓存候选必须精确匹配原始全部固定目标分数及完整生成输出，才可测量速度。

速度继续使用相邻基线 A/B/A、两场景各至少 1% 收益、基线耗时漂移不超过 3%，以及新的独立确认。吞吐相对变化的绝对值小于 0.3% 视为噪音，全部样本保留；微基准或计数改善不替代整模型验收。

## 热度过滤改变了什么

每个正式进程包含初始化、两次预热和六次保留请求，均为 **458 个窗口、1225 行输入、1044 行提交、588000 个全窗口路由条目**。同一顺序下，三个进程的正式 Code 草稿计数均为 73/92、73/92、73/92，Prose 均为 72/95、71/96、71/98。因此本组未观察到草稿数量或接受数量变化。

| 进程 | 增加热度的行 | 过滤窗口数 | 逻辑驻留命中 | 逻辑未命中 |
| --- | ---: | ---: | ---: | ---: |
| A1 | 1225 | 0 | 486898 | 101102 |
| B1 | 1044 | 123 | 484122 | 103878 |
| A2 | 1225 | 0 | 486898 | 101102 |

候选过滤了 181 行热度，逻辑未命中却比两个相同控制增加 **2.745742%**。未提交的推测行仍执行了 GEMV，它们涉及的专家也可能在后续推测窗口复用；这些计数支持继续按实际执行工作集理解缓存热度。没有再次采集真实系统内存流量，不能把逻辑条目增幅直接当成 PCIe 字节数增幅，也不能从单轮筛选断言所有负面时间差的唯一原因。

冻结生成器会先提交整个接受前缀，再截断最终返回的 token；本组每个正式进程返回 1040 个 token、提交 1044 行。两臂保留相同行为，性能计数中的提交行数不能直接当作输出 token 数。前述质量组的 Short16/T1 协议核对不受这个尾窗差异影响。

完成时的完整协议、输出、遥测和 553 项来源审计通过，表示记录与协议一致，性能门槛仍失败。没有启动独立正收益确认或热请求历史验收，没有生产接入，也未达到 40 tok/s。原始构建、质量、性能、初版失败和逐窗口计数全部保留。
