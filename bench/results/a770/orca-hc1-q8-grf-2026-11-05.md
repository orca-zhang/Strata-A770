# HC 融合 Q8：单映像 128／256 GRF 对照

2026-11-05，Windows 10 22H2，Intel Arc A770 16 GB，驱动32.0.101.9034，oneAPI2025.3。
只对 `fused_gr/image_3.zebin`（gr_up_multi_q8_kernel）增加 `-ze-opt-large-register-file`，
使用完全相同的原始 SPIR-V、ABI、EXE、其他内核与输入；原有编译选项保留。
128 GRF 重编译结果与原映像逐字节一致；候选目录只有该映像及两份追溯manifest改变。
两份 .ze_info 的 payload_arguments 与 per_thread_payload_arguments 完全一致。

| 编译资源 | 原128 GRF | 新256 GRF |
| --- | ---: | ---: |
| SIMD | 32 | 32 |
| GRF | 128 | 256 |
| spill_size | 2208字节 | 0 |
| scratch spill/fill分配 | 4096字节 | 无声明 |
| private_size | 40192字节 | 40192字节 |
| 每SIMT线程global private | 1256字节 | 1256字节 |
| barrier_count | 1 | 1 |

这些是编译元数据，不是实测内存流量、寄存器占用率或每次必然访问的字节数。
256 GRF 去除了报告的寄存器溢出，没有去除按值捕获参数产生的私有内存分配。

沿用无时间戳的 HC 回放，每列表48次，N2560、HC4、LR320，T1/4、三模式、两份变化输入。
顺序固定为 D128→D256→L128→L256→D256→D128→L256→L128，D为Direct，L为L0。
每个模式／输入十次回放，丢弃前三次；960次完整输出／guard检查及96份CPU FP64参考检查通过，
96份完整输出校验和与原映像一致，融合Q8与独立量化逐字节一致，输入和权重不变。
输入上传、录图、清零、回传和验证在墙钟外；墙钟只包围一次整列表提交与最终等待。
以下为融合Q8模式的七次保留样本中位数；反向表格仍按128→256列值，实际执行先256后128。

单项中，T1融合链的Direct用时少25.25%～30.66%，L0少9.13%～14.03%；T4两后端也均减少。
这是包括归一化、Down、Up和混合的热权重HC链，不是单个kernel时间或完整模型成绩。
原样保留所有模式的数据：未改映像的普通HC也有明显漂移，Direct首臂T1普通模式约5.3～6.3ms，
末臂约2.0ms；不能用它抵扣或隐藏漂移，也不能直接据此宣称消除了Direct/L0差距。
本轮只有一个固定顺序窗口，不给稳定性或置信区间承诺。
