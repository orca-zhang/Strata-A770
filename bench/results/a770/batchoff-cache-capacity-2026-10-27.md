# A770：关闭专家批量等待后重测缓存容量

A770 16 GB / PCIe 3.0 / Windows / DPC++ 2025.3.2 / driver 32.0.101.9034。首轮筛选和不改设置的独立确认均通过，**尚未采用为生产改动**。未修改生产，历史两场景约31 tok/s尚未恢复，稳定40 tok/s未达到。

此前容量对照在小缓存的Prose全零后停止。随后同一MoE诊断EXE关闭探针、保留专家链、仅关闭八专家批量等待的两个独立进程，各完成九场景/758固定评分目标，全部有限且评分字典逐项相同，也等于该EXE开探针时的有限评分。两进程均为5771槽、READY空闲2562MiB、退出0。此处复用其冻结EXE与已落盘证据，运行前在共享锁内复核全部来源；不宣称通用修复。

本组保持关闭批量等待及全部探针/融合/剖析，仅改变缓存容量：A请求5500、要求实际5771槽，B请求6000、要求实际6297槽；每臂READY空闲至少1500MiB。同一EXE、原始Code2K/Prose2K各2048输入、完整128输出、min-p0.5、prompt-cache0，其余命令图、FP16 KV和窗口设置沿用已完成融合筛选。所有完整输出必须逐项匹配修正GDN参考。生产为eager、K16/V4、自动缓存及min-p0.8，自动缓存可能已大于本候选；本组收益只属于这里的固定容量对照。

先为两种容量各做Short16初始化和Code/Prose完整输出检查；然后A1/B1/A2，每个独立进程先等待30秒，再Short16、每场景一次预热、三轮交替正式请求。两场景配对中位数吞吐均增加至少1%、相邻基线耗时漂移绝对值不超过3%，才执行不改设置的A3/B2/A4独立确认。保留所有低值、预热和失败，正式计时采用1Hz只读Sysman监控。九场景评分请求的速度不进入本组吞吐统计。

复用既有完整协议重建、输出、容量、遥测和文件哈希审计；补充关闭批量等待的来源门槛。源码和1%/3%配对自检通过，实验在共享GPU锁内串行运行。运行异常只向终端输出分类，完整回溯保存在本地，不打印提示、token或原始评分行。

两容量冒烟共四次长请求、A1/B1/A2的24次长请求及A3/B2/A4的24次独立确认长请求，合计52次，全部匹配修正参考的完整128输出，八个引擎均以0退出。完成时完整T/TB/DONE协议重建、容量、遥测和来源哈希审计均通过，runner退出0；这只覆盖固定请求，不构成通用质量评估或间歇异常的通用修复证明。
