# Responses 输出项索引（2026-10-24）

`serve/responses.py:Assembler.close` 每结束一个输出项，原来都用 `output.index(item)` 从头查找位置。`_open` 始终把当前项追加到列表末尾，外部接收的是深拷贝快照；所有现有调用路径都保持这个约束。现在直接使用已有的 `self.index`，生产代码只改一行，没有新增状态、临时缓存或依赖。这一处索引查找从每次 O(n) 降为 O(1)，累计处理 n 个输出项时免去 O(n²) 次比较；这不是对完整响应处理复杂度的声明。

两轮完整 CPU 处理结果：100 个短工具调用的非流式耗时下降 **9.22% / 6.47%**（省约 0.25～0.30 ms），流式下降 **5.39% / 5.40%**（省约 0.32～0.39 ms）。1,000 个工具调用的压力场景，非流式下降 **49.10% / 47.50%**，流式下降 **34.92% / 34.12%**。普通短回答、短推理以及 1～10 个调用的变化约在 2% 内，按用户约定视作噪音，没有可确认收益。未测真实请求的调用数量分布，不能认为压力场景代表日常收益。
