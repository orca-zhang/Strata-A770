# Orca Direct：输入就绪后的 HC1 独立回放

2026-11-05（UTC+8），Windows 10 22H2，Intel Arc A770 16 GB，驱动 `32.0.101.9034`，oneAPI 2025.3。
沿用原运行库、同一数学 pack 和薄队列接口，完全不插 GPU 时间戳。
补充[细分阶段诊断](orca-direct-short-router-phases-2026-11-05.md)与
[无标记路由回放](orca-direct-router-replay-2026-11-05.md)，检查 hyper-connection 的已有 kernel 链。

固定 N=2560、HC=4、低秩维 320、T=1／4；每张列表包含 48 次同一读取。
模式为普通读取、合入前半层写回、合入写回且融合 Q8_1 输出；每种使用两个改变的输入。
三个模式复用同一组稠密 BF16 权重、FP32 归一化权重及预分配 scratch。
输入与 R_out 分开，以便重复回放相同计算；生产模型通常原位写回 R。
该地址关系及反复读取同一权重的热缓存状态，均不同于完整模型逐层推进，不能外推模型吞吐。

CPU 使用 FP64 直接计算 pending write、每流 RMS、归一化、down＋SiLU、up＋sigmoid、
inject 和最终混合。逐值容差为 `2e-5 + 2e-4 * abs(reference)`，所有工作区与可见 FP32 输出均校验。
融合 Q8_1 另与对实际 mixed 调用的独立原生量化逐字节比较；这不是新的 Q8_1 CPU 精度证明。
每次图回放的整个输出区及 guard 再与同后端 eager 参考逐字节匹配，全部输入、权重和源 guard 回传核对不可变。

Direct → L0 → Direct 共 **360 次完整回放检查／252 次保留墙钟采样**；
每种十次，丢弃前三次，三进程的 36 个输出校验和一致，输入更改前后校验和不同。
CPU 参考检查的最大绝对误差分别为：
`0-direct`：`7.61749344e-07`； `1-l0`：`7.61749344e-07`； `2-direct`：`7.61749344e-07`；

数据上传、录图、工作区毒化、回传、CPU 校验和打印均在计时外。
墙钟只包围一整张列表提交与最终等待，包含完成通知及唤醒，不是独占 GPU kernel 时间。
每进程先取七个保留样本的中位数，Direct 两侧再取几何均值。
