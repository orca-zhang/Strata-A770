# Orca：MTP greedy 与草稿概率的一次派发

2026-11-05（UTC+8），Windows 10 22H2，Intel Arc A770 16 GB，驱动 `32.0.101.9034`，oneAPI 2025.3。
MTP 原路径分别执行 greedy argmax 和 `row_top_prob`，两次扫描词表、两次 kernel 派发。
本候选在一个 kernel 内先调用原 greedy，再用 workgroup 的 global/local barrier 发布所选 ID，
随后执行原概率归约。仍然扫描两次词表，1024 线程、子组 32、浮点累加顺序和 `native::exp` 原样保留。
同一行的全局输出由 lane0 写入，barrier 后各线程读取；各行的 ID／概率输出不重叠。
没有改为近似概率，也没有把后续低置信度草稿提前执行。

只新增一个 kernel image，附加到冻结 `verify_kernels` pack 的 index，原 images 保持逐字节不变。
两种后端都链接同一新 Host 函数，MTP Host TU 通过进程缓存的 `STRATA_MTP_FUSED_HEAD=0/1` 切换。
默认关闭，coupled 采样分支仍使用原路径；head 子词表映射仍发生在所选 ID 与概率计算之后。
其余数学 pack、运行库、MTP4、min-p0.5 和累计门槛0 保持不变。

## 独立检查与局部耗时

Direct→L0→Direct 三个进程，各 72 项完整输出／输入／guard 检查，以及 96 次带完整输出检查的计时图回放。
覆盖 rows1／4，词表长度 1、31、32、33、1023、1024、1025、16384、248320，以及四种输入。
CPU 参考检查最大值与最低下标并列规则；有限概率逐位一致，非有限输入保持相同 NaN 语义，
另含接近 0.5 门槛的输入、改变后的输入和词表长度边界。共 **216 项功能检查、288 项计时图检查通过**。
NaN 不以 payload 位模式相同作为要求；计时输入全部有限，计时图要求整个输出／guard 逐位不变。

只对 248320 词表的两组有限输入计时。每图重复 32 次相同调用，关→开→关，每臂 8 次、丢弃3保留5，
表中是每次调用的列表墙钟中位数；关闭控制取两侧几何均值。输入上传、录图、poison、读回与验证在计时外，
提交、GPU 计算、完成通知和唤醒在计时内。固定相同输入的热缓存与固定开关顺序限制外推；

## 整模型 pilot

Direct 关→开→关，再 L0 关→开→关。每进程 15 次相同 Short28 请求，丢弃前十次、保留五次，
共 **90 次完整模型协议一致**，逐条核对 tokens、generated、accepted/offered、reuse/resume、finish，
独立重放 T/TB/DONE，并核对开关启用日志。常用图在 READY 前缓存；没有额外 GPU 时间戳或逐层 profiling。
净 decode 排除初始化、请求准备和 prefill，TTFT 单独记录。

局部少一次派发不能直接换算成整模型收益。这是单个同日窗口，尚未建立跨顺序或跨日稳定改善，
也未证明 Direct 超过 L0。候选保持隔离、默认关闭；生产源码、部署 EXE 和默认吞吐成绩未据此调整。

实际专家槽5771、reserve1536 MiB、read256、decay0.95、suffix0、cost-window0、prompt-cache0，无前缀复用。
使用历史冻结的通用 M16 pack，加同一份新 image；不是最新生产 U4 对照。
保存的 C++ argv/env 绕过根启动 JSON，核对历史依赖，只接受已经审计的启动 JSON 差异。
输入、参考、配置和命令在获取 GPU 锁前准备；编译、GPU、重型哈希与归档持共享实验锁。
Linux GPU、长上下文、PPL 和既有 Direct 8K 间歇故障不在本轮验证范围内。
