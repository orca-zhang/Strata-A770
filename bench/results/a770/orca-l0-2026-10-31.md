# Orca L0：原生产 SYCL → 双专家采用前版本（2026-10-31）

> 历史冻结结果：0.8／1536 MiB、双专家默认采用前。最新默认实测与旧 SYCL 新基线失败见[更新记录](orca-default-pair-2026-10-31.md)；本页原始数据保留。

原生产 SYCL → 最新 Orca L0 的整版本复测中，四场景 **decode 吞吐变化为 +5.83%～+29.39%**；但 2K／8K 输入处理变慢，**完整请求吞吐变化为 -30.77%～-30.00%**。 **质量等价尚未成立。** 两段冷启动 512-token 固定输入共 1022 个配对目标位置上，原始 PPL 合计 **+6.94%**，去除轮次结束 token 概率质量后的条件 PPL **-7.41%**。两种口径方向不同；本轮各版本生成的内容及草稿工作量也不同，速度差异包含整版本执行与轨迹变化，不能当作纯运行时提速。

## 整版本测试条件

GPU 为 Intel Arc A770 16 GB，驱动 32.0.101.9034；CPU 为 Xeon E5-2696 v4，内存 256 GiB DDR3，Windows 10 22H2；模型为 Qwen3.8-Flash-Next IQ2_XS。基线使用切换前的 `strata-iq2_xs.json.sycl-backup`，可执行文件为 `build-sycl-a770-prefill-cache-tail-production-v3-20261026/bin/strata-unified-all-operators.exe`；候选使用当前主配置，原生可执行文件为 `clean-root-orca-1793380617150969000/build/orca/strata.exe`。

两端模型参数完全相同：自动专家缓存、8192 上下文、8192-token prefill、MTP4 / `spec-min-p=0.8`、完整草稿词表、PCIe fraction 0.16、1536 MiB 显存预留、每次最多换入 32 个专家、prefill 借用开启、提示缓存关闭。分别保留原保存环境：旧 SYCL 使用 `STRATA_VERIFY_EAGER=1`，最新 Orca 使用原生命令图及 `STRATA_ORCA_READY_OPS=1`。这项实验覆盖整个升级，包含内核、调度和实际缓存容量等差异。

运行顺序为旧 SYCL A0 → Orca B → 旧 SYCL A1。每臂轮流执行 Short / Code2K / Prose2K / Long8K，输入分别为 23 / 2048 / 2048 / 8000 tokens；每次生成 64 tokens，temperature 0。每场景每臂首轮预热、三轮保留，共 48 次测速请求、3072 个输出 tokens、36 个保留样本。固定目标质量诊断使用另起进程，计时不纳入性能样本。所有测速输出均非全零且达到 64 tokens。

每个指标先取每臂保留样本的耗时中位数，再以 A0/A1 中位数的几何平均为基线。吞吐变化 = `基线耗时 / Orca 耗时 - 1`；decode tok/s = `64000 / decode_ms`。输入处理与首 token 是不同指标；完整请求按引擎协议请求到完成的墙钟时间计，排除启动、模型加载与 HTTP 服务开销。

每个后端针对 Code2K / Prose2K 的前 512 tokens 各启动一个全新进程，采齐 511 个 teacher-forced 下一 token 分数。共 1022 个配对目标位置（两端各 1022 个分数），检查目标 ID、覆盖、位置唯一性与有限值。原始 PPL 按完整分布的目标 log-probability 计算；条件 PPL 从分布中去除 `<|im_end|>` 的概率质量后重新归一化。合计变化按所有目标位置的平均 NLL 差取指数，不对各场景百分比作算术平均。

预登记门槛只检查条件 PPL：合计不升超过 1%、每场景不升超过 3%，本轮通过。**该门槛通过不等于质量等价**：原始 PPL 上升、两个口径相反，而且仅覆盖两个短前缀。完整 TSV 分数连同原始 SHA256 已嵌入 JSON，可重新计算两个口径。

## PPL 差异的进一步拆解

PPL 越低越好，原始 PPL 上升 6.94%表示这组目标上的退化，不是质量收益。PPL 是平均负对数概率的指数，平均 NLL 约增加 0.067 nat 就会产生该百分比；它不等于答题准确率下降 6.94%。

这两个输入前缀包含 `<|im_start|>user` 聊天头，但评分目标仍在用户输入内容中，尚未进入 assistant 回合。结束回答 token 在 Prose 的 511 个评分位置中，旧 SYCL 有 494 个位置为 top1，Orca 有 496 个；两端平均结束概率都约 93%。去除结束概率后的条件分布回答的是“假定不结束，剩余 token 中目标的概率”，不能替代原始分布的评分。后续质量检查应另行覆盖带完整聊天头的固定 assistant 续写，并保留完整分布的原始 PPL。

| 输入 | SYCL 原始 PPL | Orca 原始 PPL | SYCL 条件 PPL | Orca 条件 PPL | 结束概率惩罚平均变化（nat） |
| --- | ---: | ---: | ---: | ---: | ---: |
| Code2K | 62.129 | 64.187 | 4.166 | 4.124 | +0.042945 |
| Prose2K | 37804.141 | 41845.855 | 101.218 | 87.684 | +0.245111 |

原始 NLL = 条件 NLL + `-log(1 - p_end)`。Prose 上条件 NLL 改善约 0.144 nat，但结束概率惩罚增加约 0.245 nat，最终原始 NLL 反而增加约 0.102 nat。个别目标位置的原始 NLL 差值超过 10 nat；仅替换提交 API 不应把这解释为质量提升。计算路径、精度、缓存与状态差异的具体贡献尚未隔离。后续应在相同参考续写、相同缓存和路径下检查逐 token／逐层差异，并同时保留原始评分。

三臂进程正常退出；可执行文件、内核包、两个配置、执行脚本及辅助脚本的完整性检查通过。Orca 启动与负载后 DLL 审计未加载 SYCL / Unified Runtime / oneMKL。原始报告 SHA256、两个 EXE 哈希、全部输入输出、预热与保留计时、草稿计数、评分 TSV 及模块清单见 [整版本 JSON](../../../sycl/orca/deployed-versions-a770-windows-2026-10-31.json)。实际冻结脚本及参数化工具的原差别记录在 JSON 中。当前公开工具已采用上述原始 PPL 门槛及 assistant 续写，不能逐项复现旧条件 PPL 放行流程；无需新增依赖。

```powershell
python tools/bench_orca_upgrade.py --baseline-config baseline-frozen.json --candidate-config candidate-frozen.json --out build-orca-upgrade-check
```

两个冻结配置需保持模型参数及 tokenizer 相同；本机默认后续已调整，不直接混用当前主配置和旧备份。配置中的本机模型、可执行文件及内核路径需存在；输出目录必须尚不存在。工具串行占用 GPU，保存原配置环境并核对模型参数，评分与测速分离。加 `--quality-only` 仅执行新质量筛查。当前完整引擎数据只覆盖 Windows A770，Linux 构建与 GPU 行为尚未验证。

| 正确性 | 对应请求的完整输出逐 token 一致 |

[批量 MTP 原始数据](../../../sycl/orca/batch-groups-mtp-a770-windows-2026-10-31.json)。普通四请求批量未启用批量 MTP 时，三组对照回退 2.82%～2.97%，记录在 [普通批量数据](../../../sycl/orca/batch-groups-a770-windows-2026-10-31.json)。

另一项独立测试比较自动专家缓存下的 `--batch 0` 与两个预分配 MTP 槽位：8192 上下文、2048-token prefill、MTP4、PCIe fraction 0、禁用 prefill 借用。24 次请求的 1536 个输出 token 及草稿工作量一致，槽位挤占 **701 MiB** 专家缓存，实际驻留从 6184 / 8485 MiB 降至 5670 / 7784 MiB；Short / Code2K 单请求 decode 吞吐分别回退 **3.49% / 5.06%**，完整请求吞吐回退 **3.64% / 0.62%**，decode 基线漂移最大 0.45%。这项测试没有并发请求，不能据此否定并发吞吐收益；四请求的固定缓存实验也不能衡量自动缓存下四槽的成本。[槽位成本数据](../../../sycl/orca/batch-memory-a770-windows-2026-10-31.json)

GEMM 聚合默认启用；服务多请求批量槽位保持可选，默认 0。

## 运行时提交专项

整模型结果之外，独立 demo 还验证了调度和提交层的收益，不能与模型百分比相加：

| 工作负载 | 原对照 | Orca | 结果与边界 |
| --- | --- | --- | --- |
| 400 个依赖内核，每核 64 元素 | SYCL graph 中位数 1.069～1.076 ms | 0.460～0.475 ms | 三个确认进程的稳定配对吞吐 +126.17%～+130.17%；含传输和完成等待；非模型吞吐 |
| 400 个依赖内核，每核 1048576 元素 | 同模块 SYCL graph | 同模块 Orca 回放 | 三进程全部样本中位吞吐 +11.3% / +12.4% / +14.1%；原漂移筛选子集含负值，原始记录保留 |
| 32 个就绪的独立单内核命令列表 | 单独 append，末尾统一等待；CPU 提交 267.6～288.9 µs | 一次批量 append；CPU 提交 30.5～30.6 µs | 两个 SPIR-V 进程完整执行/回读窗口约 4.33× / 4.42×，原生二进制进程 5.00×；不是完整模型 |
| 同样 32 个列表，每列表 16 个内核 | 单独提交 | 批量提交 | 三个新进程完整窗口约 1.83×～2.15× |

第一组方法、逐次 CSV 和含负样本的原判定见 [400 内核提交实验](../../../orca-l0/demo/RESULTS.md)。就绪列表数据与检查见 [批量提交 JSON](../../../orca-l0/demo/api-submission-a770-windows-2026-10-31.json)。单个 400 内核列表的 DDI 函数表直调对比，完整窗口变化低于 0.5%；不能把批量列表收益归因于只绕过一层函数调用。Strata 当前仍逐个提交自己的图，不会通过这个底层 API 自动合并任意依赖的 MTP 步骤。

## 主配置切换与验证

Intel 安装入口默认选择 Orca；本机 IQ2_XS 主配置也已备份并原子切换，现有服务未重启，下次启动生效。保留原模型参数，实际设置为自动专家缓存、8192-token prefill、MTP4、`spec-min-p=0.8`、PCIe fraction 0.16、1536 MiB 预留及 prefill 借用，与上述受控测速配置不同。

Code2K → Long8K → Short → Code2K 共四请求、256 个输出 token 全部匹配已验证参考。启动及工作负载模块审计排除了 SYCL、UR 和 oneMKL，进程正常退出；可执行文件、内核包、配置及脚本完整性检查通过。这是功能回归，计时未用作新增性能结论。[主配置验证与切换记录](../../../sycl/orca/production-activation-a770-windows-2026-10-31.json)

共享 106299-token 草稿子集头也通过两请求串行/批量对照，覆盖 greedy 和带重复/频率/存在惩罚的固定种子采样，两项各 128 个批量输出 token 一致；可执行文件、内核包与子集文件未变。[裁剪词表检查](../../../sycl/orca/subset-vocabulary-a770-windows-2026-10-31.json)
