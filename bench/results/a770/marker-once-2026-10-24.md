# 提示词标记还原改为单次扫描（2026-10-24）

`unmark_think_literals` 的原生路径改为一次前向 SSE2 标记查找，直接写入最终文字和范围列表。删除了上一版按每个标记分别扫描提示词、缓存全部匹配和排序的步骤，也不再构造文字片段列表。输出缓冲、范围对象和字典查询仍有必要的分配。

未安装可选扩展时，以及使用多字符或空标记时，保留一次前向正则迭代，保持重叠标记的映射优先级。没有新增依赖。扩展使用 CPython 的 `_PyUnicodeWriter` 内部接口；本次只验证了 CPython 3.11.9，其他版本尚未验证。

Windows 10 19045、Xeon E5-2696 v4、64 位 CPython 3.11.9，MSVC 14.50 编译；计时进程固定在逻辑 CPU 42。使用本机 IQ2_XS pack 的 248,320 项真实词表、247,587 条合并规则、聊天模板和 29 个标记。**本次基线是上一版逐标记 `str.find` 实现**，不是最初的正则版本。

两轮均采用 A/B/A，每臂 7 个样本，B 中位数对比两个 A 中位数的几何平均；基线漂移绝对值超过 3% 则弃用。计时包括 Python 调用和返回对象构造。下表负值表示耗时下降：

| --- | ---: | ---: | ---: |
| 一个标记 | 64,001 / 1 | −85.09%，0.530→0.079 ms | −84.93%，0.464→0.070 ms |
| 稀疏标记 | 64,080 / 32 | −83.03%，0.585→0.099 ms | 弃用：漂移 +3.71% |
| 密集标记 | 29,000 / 29,000 | −74.44%，29.129→7.444 ms | −72.46%，27.082→7.458 ms |

另用 `tracemalloc` 测单次调用的 Python 分配峰值，各测三次。包括原生 Unicode writer 和返回对象，不包括输入构造；不在追踪分配时计时。它不是进程 RSS：
