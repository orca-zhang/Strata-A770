# Orca L0 / Direct U4 N16 integration — 2026-11-04

Measured on Intel Arc A770 16 GB; driver 32.0.101.9034; Xeon E5-2696 v4; Windows; oneAPI 2025.3. Default executables and profiles remain unchanged. U4 N16 is opt-in. Model measurements use isolated executables with one added U4 Prefill Host object on the frozen source-adopted Orca engine, preserving the existing numerical packs and native policy.

The existing BF16-derived U4 weights and two residual S4 activation planes now run through both Orca transports. Each transport matched 3,302,400 complete GU/Down outputs byte for byte against SYCL, including routed gaps, tail rows, guards and alternating device banks. All 3,234 experts loaded successfully. Host weight payload is 8.33 GiB; two device weight banks total 42.2 MiB, plus activation workspace.

The first Host build failed because the native queue header was included too late. The first model integration then failed with nonfinite activations: skipping U4 experts left holes in the FP16 pair indices. The corrected version computes U4 experts first, removes them only from the native traversal, and retains every original routed output offset. Native FP16 pairs and batching remain enabled. All failed versions and logs are retained.

The checked logic is now guarded in the common Prefill source, with U4 math and a manual real-weight check in `sycl/orca`. The repository source was rebuilt separately: SYCL, L0 and Direct again matched the complete original SYCL outputs and guards; the actual generated Prefill Host TU compiled for both Orca transports. Those checks reuse frozen engine headers/runtime libraries; they are not a new full-current-runtime deployment test.

Quality uses 128 fixed targets from each of Code and Prose, with native/U4/native controls. The diagnostic gate is aggregate PPL change ≤1% and each case ≤3%. Quality timings do not enter the speed comparison.

Performance uses the same executable per backend, native/U4/native, Short23→16 initialization, then three interleaved Code/Prose 2048→128 cycles. The first cycle is discarded. Durations are medians of the remaining two requests; native controls use their geometric mean. Pair tiles, expert batch, MTP4, read256, cache5500 (actual5771), reserve1536 and graph warming stay fixed. Compilation and GPU work hold the shared experiment lock.

After the pair-index correction, 12 quality/performance processes completed normally: 16 U4 long requests and 32 native control long requests. Complete outputs are stable within each arm and native controls match. This is a 2K diagnostic, not a long-context reliability claim.

Positive percentages mean higher throughput. Request duration is host GEN→DONE, excluding startup; it is not an HTTP benchmark. Native controls must remain within 3% drift for a valid speed claim. These are small-cohort observations. Decode kernels are unchanged; generated tokens, routing and speculative acceptance may differ. No new GEMV speedup is established. The existing intermittent Direct 8K issue remains open.

The Orca XMX source adapter also accepts the new SYCL paired-M4 template. Its generated Orca FP16 M4 and BF16 source remains byte-identical to the previously checked version. CPU regression: `python tools/test_orca_xmx_prepare.py`.
