# A770：按阶段剖析批量提交专家计算链

源码保留一项默认关闭的优化：连续提交 gate/up → SwiGLU → down，只在完整专家链末尾等待。IQ2_XS 强制批量 Code256 的五进程对照中，两组配对的预填吞吐增量为 **+18.49%／+17.84%**，基线漂移为 −0.10%／−0.66%，五次各 32 个输出 token 全部一致。

硬件为 A770 16 GB、E5-2696 v4、PCIe 3.0 x16、Windows、驱动 32.0.101.9034、DPC++ 2025.3.2、oneMKL 2025.3。基线为已有直接 XMX R1，包含当时的权重转换向量化。这是相对当前 R1 的增量，不与此前相对 FP32 widening 的历史倍数相乘。

## 剖析依据

先对冻结的 R1 构建做两次独立分析：一次只记录 GEMM 形状，一次把已有阶段标记改成 `steady_clock` 主机时间线。后者没有增加 GPU event barrier；后续检查发现计时器 `on=true` 还会启用块起点／embedding 的已有调试等待，因此原文“没有增加同步”不准确。下表保留历史观测，后续热点判断使用[更新后的当前专家链剖析](xmx-expert-batch-2026-10-24.md)。主机时间包含提交和 GPU 等待，**不是 GPU 内核的独占执行时间**。分析运行与后面的性能运行分开，后面的交替性能对照未开启此剖析器。

| 主机阶段 | 时间 ms | 时间线占比 |
| --- | ---: | ---: |
| gate/up 阶段 | 5780.85 | 38.39% |
| down 阶段 | 3377.95 | 22.43% |
| HC read 阶段 | 2972.52 | 19.74% |
| GDN 输入投影阶段 | 1135.59 | 7.54% |
| dequant 提交阶段 | 681.11 | 4.52% |

总主机阶段时间为 15058.91 ms。专家阶段可能包含此前异步工作及下一轮 staging 的等待，不能把这张表解释为 GPU 算术或内存带宽占比。另行统计的主机 staging 为 776.61 ms，已包含在这条时间线中，不重复相加。

实际路由专家为 11967 组：2379 组来自显存缓存，9588 组经 DMA 搬入。19.88% 是按专家组数计算的驻留比例，不能等同于按 token 路由计算的缓存命中率。形状分析中 T≤8 的两个专家 GEMM 合计 16072 次，支持优先检查大量小调用的提交与等待开销。

因此本轮先减少专家链中途的一次等待，没有扩大缓存、改变缓存行或引入 repack。此前的 K 拆分结果另见[小专家 split-K 筛选](xmx-splitk-2026-10-24.md)。

## 改动与检查

新增 SYCL `Gemm::f16_expert`，覆盖当前模型的 2560／640 专家维度。普通 `f16`／`bf16` 调用继续保留原来的阻塞行为。新入口先验证 XMX 支持、队列顺序和较大的 gate/up 填充需求；不满足条件时不提交工作，调用者使用原有流程。down 的输入宽度更小，使用同一已验证工作区。链末尾仍等待，保护全部输入和中间结果的生命周期。

这是批量提交，三个计算内核仍独立存在。原 8×8 XMX 内核和 SwiGLU 内核都没有改动；FP16 输入、FP32 累加和输出保持原样，没有引入精度折衷。

算子检查轮换八组、合计约 78.6 MB 的 FP16 权重；T 为 1／2／4／6／7／8／9／16／22／32／40／64／65／128／256。比较 GU、FP16 H、down 的完整输出，要求逐位一致，另检查外围 guard、零行、输入变化及工作区零容量、恰好容量、差一字节、多一字节和移动绑定。每进程 380 项，两组各五进程，共 **3800 项通过**。

源码保留独立的 `prefill_xmx_expert_chain_check` CTest；非 A770 返回 skip。该检查也支持 `--bench`，测完整专家链，沿用上述八组权重。计时预热 16 次，取七批、每批 16 次完整调用的中位数，使用相同 128 MiB 外部工作区和 all128 分配池，关闭 profiling。

每回合预设至少六个基线漂移≤3%的形状、中位增量≥3%，且合格形状回退不超过 3%。最后一个确认回合只剩五个合格形状，**严格算子汇总门槛未通过**。其余样本和漂移均保留，没有继续补刷算子数据。最后一行使用的形状集合较小，不能解读为收益又提高了。

随后在模型测量前单独声明：保留算子门槛未通过的状态，仅根据一次独立整模型 A/B/A/B/A 和逐位检查判断是否保留这一可选源码改动。不据此宣称所有形状均无回退。

## 整模型采用依据

同一个私有 EXE，仅切换实验开关。IQ2_XS、同一 Code256 提示、greedy 最多 32 个输出、INT8 KV、context 8192、prefill chunk 256、prompt cache 0、`--short-read 0`。实际缓存始终为 4191 slots／5760 MiB，工作区为 128 MiB、all128 分配池。每次为独立进程，保留磁盘和驱动缓存，没有清空 JIT 缓存。所有编译和 GPU 测试串行持有共享实验锁。

复用冻结的公共引擎依赖，重新编译 GEMM 与 prefill 对象再链接；不是整个脏工作区的全量构建，也不是与已安装生产 EXE 的比较。公开数据见[阶段、算子及整模型摘要](xmx-expert-chain-summary-2026-10-24.json)。

## 使用与复核

重新构建 SYCL 引擎后，同时设置 `STRATA_PREFILL_NATIVE_XMX=1` 与 `STRATA_PREFILL_XMX_EXPERT_CHAIN=1` 启用。两个开关均默认关闭；生产 EXE 和用户配置没有替换。其他形状或无法满足工作区条件时保留原流程。

检查入口为 `ctest --test-dir <SYCL构建目录> -R '^prefill_xmx_expert_chain_check$' --output-on-failure`。公开检查体与上述已经编译、运行 3800 项检查的私有源码完全一致，只增加非 A770 跳过分支，源码一致性已核对。同机另一个多场景长测持续持有 GPU 锁，因此取消了仍在排队的额外 CMake 配置、重编译和 CTest 复跑，未影响对方任务。**新 CTest 入口尚未单独构建和运行**，不将其写作新增通过项，也未声称完整工作区已构建通过。

本机证据审计命令为 `python build-sycl-a770-moe-profile-20261024/audit.py`、`python build-sycl-a770-xmx-expert-chain-v2-20261024/audit.py` 及同目录的 `audit_model.py`。原始输入、对象、EXE、日志均保留，复测使用新目录。
