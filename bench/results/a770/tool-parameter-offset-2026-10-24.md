# 参数扫描起始偏移（2026-10-24）

本轮继续[参数游标优化](tool-call-cursor-2026-10-24.md)：`call_end` 和 `parse_tool_call` 原来仍会先截取参数之后的剩余正文，再调用 `param_end`。现在直接传原字符串和起始偏移，返回绝对位置，去掉这两处后缀复制。原生扫描器沿用已有的有界 SSE2 循环，支持可选的第三个起始位置参数；原有两个参数的调用仍可用。没有新增依赖或正则。

原生函数改用项目已有的 `METH_FASTCALL` 调用方式，减少 Python 参数元组开销。导入时探测偏移支持；已经编译但未更新的旧扫描器会使用 Python 回退，避免源码更新后因参数数量变化报错。本机已重编译并核对当前加载的是新扫描器。

收益集中在多参数压力输入：原生 1,000 参数流式调用耗时下降 **8.9%～10.1%**；整段输入只有第二轮通过漂移规则，下降 **14.85%**。100 参数流式下降 **2.7%～5.9%**。Python 回退的 1,000 参数整段输入下降 **9.4%～10.0%**。这些是合成输入，未测真实请求的参数数量分布。

也有明确测到的代价：含文字终止符和 Unicode 的数组，原生路径两轮慢 **4.47% / 3.10%**；Python 回退的长字符串慢 **2.48% / 1.50%**。逐字符数组第一轮慢 3.52%，第二轮慢 0.19%。因此不能声称普遍提速；原生调用微测没有确定这些完整解析差异的根因。测量不包含模型 prefill、decode、HTTP 和外部工具执行，README 的模型吞吐数据未调整。

Windows 10 19045、Xeon E5-2696 v4、CPython 3.11.9 x64、MSVC 14.50.35717 /O2，固定逻辑 CPU 42。比较本轮修改前后冻结的 Python 模块及各自的原生二进制；基线已包含前几轮优化，没有把各轮百分比相乘。计时包括解析器创建、全部 feed、事件收集与 finish，分块构造及正确性断言在计时外。每轮 7 组交错 A/B/A，B 中位数对比两个 A 中位数的几何平均，A 漂移绝对值超过 3% 弃用；这条规则不等于置信区间。

边界检查覆盖 1/2/4 字节 Unicode 存储、SIMD 边缘长度、起始位置为 0 或字符串末尾、前缀内已有终止符、未完成后继、Unicode 空白、孤立代理字符和 NUL。原生参数接口检查错误的参数数量、类型、负偏移、越界及整数溢出。反汇编仍含 `pcmpeqb`、`pcmpeqw`、`pcmpeqd`、`pmovmskb`，每次向量加载前检查剩余长度。

最终原生相关测试 96 项通过；强制 Python 回退后 93 项通过、3 项原生专项跳过。12,432 组流式差分逐次 feed 及 finish 的事件与状态一致；2,000 组直接解析差分一致，其中 966 个预期损坏输入的异常类型及消息也一致。另用真实旧版二进制检查源码更新后的回退，并对 1、7、整段三种分块核对结果。本轮未重跑全量服务端套件。

`parse_tool_call` 的这次参数扫描已不需要剩余正文副本，但 `call_end` 的空白处理仍有 `lstrip` 后缀副本，完整流程仍有多参数 O(n²) 复制上限。下一步若继续处理此处，应测量按偏移跳过 Unicode 空白的收益，不能直接宣称整条解析链为线性复杂度。

试验目录 `build-sycl-a770-param-offset-20261024/` 保留原始可变参数接口、FASTCALL 候选及最初的回退计时；`build-sycl-a770-param-offset-final-20261024/` 保留最终源码、两轮原生和两轮回退样本、测试日志、旧扩展兼容检查、诊断微测及反汇编。最终版本避免在回退路径起始偏移为 0 时重复校验边界，但没有消除上表中的长字符串退化。配置和生产引擎 EXE 的哈希未变；原生扫描器的源码和二进制是本轮有意更新的部分。
