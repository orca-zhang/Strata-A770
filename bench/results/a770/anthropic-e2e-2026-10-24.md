# Anthropic 真实模型 HTTP 端到端性能（2026-10-24）

本轮完成的四个场景没有测出最近 `anthropic_events` 优化的明确端到端收益。所有配对结果和基线漂移均保留；约 1%～2% 的变化按噪音处理。另有一个 258-token 工具输入在 B 预热时触及 180 秒 HTTP socket 超时，没有 A/B 结论。

A 是最近一次事件转换优化之前的函数，B 是当前函数。两份 server.py 的 AST 除该函数外一致；此前 tokenizer、解析器、收集器等优化均已包含在两臂中。本轮测量这一项的增量收益，不能代表所有历史优化的合计收益。

环境：Arc A770 16 GB、Xeon E5-2696 v4、Windows 10 19045、CPython 3.11.9、IQ2_XS、生产 EXE `0.1.39-sycl`。沿用原配置，FP16 KV、prompt cache 0、MTP max 4、PCIe 分流 0.16、自适应专家缓存开启；运行时验证窗口为 6。主测试自动分配 6355 个专家槽，短工具补测为 6388 个；每个服务内 A/B 使用同一个常驻引擎。仅私有配置的日志路径与本地 HTTP 端口改变，生产配置、EXE 和 README 未替换。

使用项目的两个 GPU 实验锁串行执行。前三个场景共用第一个独立服务；短工具补测使用第二个独立服务。短代码预热 10 次，长回答预热 3 次，SSE 紧接同输入的非流式测试，工具补测预热 10 次。每个场景正式执行三组 A/B/A，共 36 个正式请求、23 个成功预热请求；预热全部保留但排除统计。没有因小幅变化重复计时。

正式请求的输出正文/工具参数、用量与停止原因在各场景九次请求中一致，仅忽略响应及工具调用的随机 ID。所有完成请求的 cache_n 为 0。长回答刻意限制到 256 token，以 max_tokens 结束；短代码和工具请求自然结束。工具调用只生成参数，没有执行外部工具。

HTTP 完整响应从客户端 JSON 序列化及发送请求开始，到接收并解析完整响应、关闭连接；SSE 读到 EOF，并检查 message_stop。包含模板、分词、请求调度、引擎输入处理和生成、协议转换、JSON/SSE 及本地 socket。首正文取第一个非空 text_delta，非流式不报告首 token。启动和锁等待、文件存档、/v1/status 读取及最终对比不计入请求耗时。

等效 prefill 使用输入 token / 引擎 prompt_ms；当前配置下短输入可能走验证窗口路径，不能当作独立大批量 GEMM 吞吐。decode 使用实际输出 token / 引擎 predicted_ms，不能与含 prefill 的整请求输出速率混用。输入长度为 28、36、255 token，没有覆盖 2K/8K 长上下文、并发或完整工具执行。

额外超时记录：258-token 工具输入跨过配置的 short-read=256 边界，在第一次 B 预热中等待 HTTP 响应头达到 180 秒超时，A 尚未测量。该失败没有删除，也没有算作加速或回归；阈值是调查线索，未确定根因。255-token 补测使用更短的用户提示，不能把两者当作相同输出任务计算速度倍数。两个私有服务均通过 QUIT 正常退出，退出码为 0。

测试前后的 38 项源码及受保护文件、3 项 tokenizer 文件校验一致；两轮运行脚本和优化前函数另有哈希记录。原始响应、每个请求的引擎计时、配置、日志和源码哈希见[机器可读记录](anthropic-e2e-2026-10-24.json)。
