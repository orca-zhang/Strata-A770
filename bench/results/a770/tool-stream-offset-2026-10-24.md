# 流式工具参数扫描：使用原字符串偏移（2026-10-24）

本轮只修改 `serve/frontend.py` 的 `OutputParser._scan`，并增加一个回归测试。原来扫描器每次推进都先复制剩余正文；现在函数名、参数头和参数结束判断直接使用原字符串及绝对偏移。参数结束检查已验证完整后继，扫描器利用这个条件推进到下一个标签，避免逐参数截取并 `lstrip` 剩余正文。初始、尚未验证的空白仍交给标准库处理，没有使用 Python 逐字符空白循环。

继续使用现有可选 SIMD 扫描器；没有新增正则、依赖或原生接口，也没有修改原生 C 源码及二进制。局部变量只引用不可变缓冲区，不复制正文。实际输出的参数值仍需切片与 JSON 编码，缓冲区拼接和原始参数重复查找仍然存在，不能声称整个解析器零拷贝或线性复杂度。

两轮完整 CPU 解析计时中，原生路径的密集符号数组（含真实中文、emoji，4 字节 Unicode 存储）耗时下降 **21.9%～24.4%**；含文字终止符及 JSON 转义 Unicode 的数组下降 **5.9%～6.6%**；1,000 参数整段输入下降 **16.7%～16.9%**；100 参数含 Unicode 空白下降 **10.3%～10.9%**。ASCII 与 2 字节中文密集符号数组都只有第二轮通过漂移规则，分别下降 20.15% / 17.81%，不按两轮有效收益宣传。

Python 回退的 ASCII 密集符号数组下降 **13.0%～17.5%**，2 字节中文数组下降 **18.2%～19.3%**，4 字节中文及 emoji 数组下降 **23.7%～25.7%**，1,000 参数整段输入下降 **14.7%～17.8%**。这些均为合成输入，没有测真实请求中的参数数量、值长度和符号密度分布。

普通回答、普通字符串及 1,000 参数分块输入没有明确收益；Python 回退长字符串两轮慢 2.18% / 2.41%，未完成数组的原生路径慢 1.67% / 2.90%。小幅、方向不稳定的约 1%～2% 差异按测量噪音解读，原始变化全部保留；这不是置信区间，也不意味着每种输入都更快。较大的单轮异常另行复核并保留原值，见表后说明。

Windows 10 19045、Xeon E5-2696 v4、CPython 3.11.9 x64，固定逻辑 CPU 42。基线已包含[上一轮调用结束判断优化](tool-call-walk-2026-10-24.md)。计时包含创建解析器、全部 feed、事件收集和 finish；分块构造与正确性断言位于计时外。每轮交错执行 7 组 A/B/A，B 中位数对比两个 A 中位数的几何平均；A 漂移绝对值超过 3% 弃用。负值表示耗时下降。

原生相关测试 98 项通过；Python 回退 95 项通过、3 项原生专项跳过。新增一个混合参数回归测试，覆盖空字符串、原始 JSON、值内文字终止符、部分标签后缀、Unicode 与 4,096 字符长空白、空 feed、逐字符和整段输入，以及最终参数、流式参数和调用 ID 的一致性。12,432 组流式差分逐次 feed 和 finish 的事件及状态一致；2,000 组参数直接解析差分一致（含 966 个相同的预期损坏输入异常）；10,000 组调用结束位置差分一致，共 24,432 组。

首个原型在长字符串、Unicode 字符串和转义字符串中分别慢 4.82%、2.85%、6.20%，因此没有采用。最终版复用不可变缓冲区引用、避免额外的逐块裁剪计算；这个引用不复制字符串。原型及其样本保存在 `build-sycl-a770-stream-offset-20261024/`，最终源码、原始样本和测试日志保存在 `build-sycl-a770-stream-offset-final-20261024/`。[机器可读记录与 SHA-256](tool-stream-offset-2026-10-24.json)可复核冻结源码、测试和计时算术。原生扫描器源码及二进制、模型配置和生产引擎 EXE 的哈希未变。
