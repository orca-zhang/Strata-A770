## 与已有能力的区别

已有 `STRATA_PREFILL_XMX_EXPERT_BATCH` 只把等待降到每八位专家一次，矩阵仍逐专家提交。原型一次提交两位专家的 GU，分别运行原 SwiGLU，再一次提交两位专家的 Down；矩阵内核按两个真实行数之和分配 tile，不把短专家补齐到长专家的总行数。8×8 FP16 XMX 及 K 维累加顺序沿用已有实现，尾块仍补零并限制有效输出。

两位专家共需 80 KiB 的最坏尾块工作区，使用现有 GEMM workspace，不增加常驻权重或设备缓冲区。当前原型仍有两个 SwiGLU 调用，没有声称实现完整 MoE 融合。

历史 oneMKL batch 测试只覆盖 GEMM，没有包含专家转换与传输，且未确认统一收益，不能据此采用或声称本原型优于 oneMKL。这里直接复用已经在本机运行的 XMX 路径，不引入新依赖。

## 冻结检查与计时协议

六份真实 IQ2_S / Q2_0 专家输入来自 Code、Prose 的 layer 0、24、47。按层将 Code 与 Prose 两份样本配成三组，行数分别为 349/668、510/978、1971/1995。这是由真实样本构造的双专家组合，不是实际模型同一次路由的相邻专家记录。

三种路径使用同一 EXE：A 为原完整链、每专家等待；C 为相同链、每两位专家等待；B 为双专家分组矩阵、每对等待。每次都计入 pinned H2D、原 IQ 反量化、GU、原 SwiGLU、Down 和等待。C 用于分辨收益来自减少等待还是合并内核。

逐位比较两位专家的完整 GU、FP16 H 和 Down 输出；另查有限且非零、输出与临时区哨兵、1/7、8/9、8/16、127/129 混合行数尾块，以及零行、缺少/不足工作区时不提交输出写入。真实行数的全部输出同样参与比较。

每组执行八个 A/C/B/B/C/A 周期，每臂 16 对，另开独立进程以反向组序确认。原始计时全部保留；相邻基线和 B 两侧漂移都≤3%才算稳定周期，每轮至少六个稳定周期；B 对 A、C 均独立两轮≥1%后进入模型试验。若 C 有效而 B 未提供增量，优先评估更小的调度改动，不为分组而分组。

算子通过也不能代替完整模型验收。后续仍须原 Code/Prose 2K 输入、完整 128 输出、固定目标评分、长短交错历史、实际采样空闲显存≥1024 MiB，以及单场景两次独立≥1%且基线漂移≤3%的 prefill / TTFT / 总请求对照。[35 tok/s 目标](../../../docs/A770_PERFORMANCE.md)另行检查，不能用 prefill 加速代替 decode 达标。
