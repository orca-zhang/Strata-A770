# A770 XMX 只补尾块：HTTP 对照（2026-10-25）

**后续状态：** [独立生产切换验证](xmx-tail-production-2026-10-25.md)已通过固定容量对照和实际自动缓存检查，本机启动配置已切换。以下保留首轮未通过门槛的测量与判定，原始数据未改动。

将对齐输入的 XMX 补齐操作缩至最后一个 8 行块后，2,069-token 检索请求的 HTTP 配对基线为 **56.104 秒**，候选中位数为 **42.851 秒**，耗时下降 **23.62%**；等效 prefill 吞吐提升 **31.11%**。1K 场景的 HTTP / prefill 基线漂移分别为 3.107% / 3.167%，超过预先设定的 3% 上限，因此本轮整体部署门槛未通过。源码保留这项优化，生产 EXE 和本机配置保持上一轮已验证的版本。

## 条件与改动

硬件为 Arc A770 16 GB、Xeon E5-2696 v4、256 GiB DDR3、PCIe 3.0 ×16；Windows 10、驱动 32.0.101.9034、oneAPI DPC++ 2025.3.2 / oneMKL 2025.3。模型为 Qwen3.8-Flash-Next IQ2_XS，FP16 KV、MTP4、prefill / context 8192、`--short-read 1024`，关闭 thinking 和提示缓存，temperature 0。使用本地 Anthropic `/v1/messages` 非流式接口，不执行生成的工具调用。

基线是[上一轮生产对象集成 XMX 的 EXE](production-xmx-2026-10-25.md)，已经开启 `STRATA_PREFILL_NATIVE_XMX=1`。候选只替换 GEMM 对象，保留匹配 ABI 的 32 MiB prefill 工作区及其余生产对象；没有同时启用后续专家链、跨专家提交、HC inject 或 GDN 试验开关。FP16 / BF16 输入、FP32 累加、原 XMX 运算顺序及队列等待保持原样。

旧实现遇到不足 8 行的尾块时复制整个输入。新实现让完整行块直接读取原输入，只将末尾不足 8 行的部分复制并补零。对实际请求中的 BF16 `T=2068, K=10240`，所需补齐空间从 **40.46875 MiB 降至 160 KiB**，可装入现有 32 MiB 工作区。步长未对齐的布局仍保留原有整块复制及容量不足时的回退。

## 正式 HTTP 测量

顺序为旧版 A1 → 候选 B → 旧版 A2，各启动独立服务。请求缓存容量设为 5500，实际三个进程均为 **5771 slots / 7.74 GiB**。每进程先预热三次 255-token 工具请求，再保留一次原始 258-token 工具兼容检查、三次 1,038-token 检索和三次 2,069-token 检索。全部请求自然结束，没有重试、追加择样或超时。

下表的基线为 A1、A2 各自中位数的几何平均；候选为 B 的三个样本中位数。

| 场景 | 输入 / 输出 tokens | 等效 prefill tok/s | decode tok/s | HTTP 完整响应 |
| --- | ---: | ---: | ---: | ---: |
| 1K 基线 | 1038 / 23 | 37.57 | 17.83 | 28.910 秒 |
| 1K 候选 | 1038 / 23 | 37.80 | 18.19 | 28.754 秒 |
| 2K 基线 | 2069 / 25 | 37.73 | 20.87 | 56.104 秒 |
| 2K 候选 | 2069 / 25 | **49.47** | 21.71 | **42.851 秒** |

候选 HTTP 完整范围：1K 为 28.475～29.049 秒，2K 为 42.208～43.182 秒。范围为最小值至最大值，不是置信区间。候选 2K 的 prefill 中位数为 41.823 秒，decode 为 1.151 秒；各项中位数独立计算，不要求相加等于 HTTP 中位数。HTTP 包含模板、分词、引擎计算及完整响应处理，排除服务启动；等效 prefill / decode 分别以输入量 / 输出量除以对应引擎时间。

| 对照 | HTTP 吞吐变化 | prefill 吞吐变化 | HTTP 基线漂移 | prefill 基线漂移 |
| --- | ---: | ---: | ---: | ---: |
| 1K | +0.542% | +0.625% | +3.107% | +3.167% |
| 2K | +30.928% | +31.113% | +1.813% | +1.443% |

吞吐变化为 `基线耗时 / 候选耗时 - 1`，基线漂移为 `A2 / A1 - 1`。1K 差异按噪音处理；2K 的收益明显超过自身基线漂移。23 / 25-token 输出太短，且每轮 decode 时间有波动，本轮没有确认持续 decode 提升。每进程仅一次的原工具检查也不作为性能证据。

正式保留的 **21 次响应全部通过**，删除随机消息 / 调用 ID 后，同一场景的完整响应在 A/B/A 中一致，包含用量、停止原因和工具参数。全部成功请求均 `cache_n=0`。

## 正确性与部署判定

候选通过 **1728 项**数值、布局、工作区容量、guard 和重新绑定检查。新增检查覆盖 T=7 / 9 / 17 / 2047、FP16 / BF16，以及零容量、少一字节、恰好容量和多一字节的工作区。旧对象在新增的尾块工作区内容检查中按预期失败，候选全部通过；这项旧版失败验证的是补齐策略，不表示旧版算术结果错误。有界随机输入的数值容差仍为 0.005，回退和 guard 要求精确一致。

正式计时前另开诊断服务，以 `--short-read 256` 和 XMX 日志确认实际执行了 FP16 / BF16 路径，以及 BF16 `T=2068, K=10240, padded=true`。该服务的工具和 2K 检索均通过，计时未混入正式结果。四个私有服务均以退出码 0 结束。

采用规则在测量前冻结：完整输出一致；两个长输入的 HTTP / prefill 基线漂移绝对值均不超过 3%；候选没有超过 3% 的回退；至少一个长输入的 HTTP 或 prefill 吞吐改善达到 3%。**本轮 1K 基线漂移超限，整体规则未通过**，未进入条件性的实际自动缓存验证，也未切换生产 EXE。生产配置原始字节与测量前快照一致。

首个本地构建的检查器链接因日志路径冲突未生成 EXE；修正后在新目录重链并完成上述检查，失败清单保留在本地。候选是冻结生产对象的局部重编译和重链接，未宣称完整重建当前工作区。
