# A770 GU/Down：主存与显存的真实内存计数

A770 16GB / PCIe 3.0 / Windows / DPC++ 2025.3.2 / driver 32.0.101.9034 / VTune 2026.4 / Level Zero loader 1.33.1。**主存路径存在高系统内存流量和高停顿；同一权重常驻显存后，两者明显降低。** 这是算子诊断，没有新的整模型性能收益或生产变更，稳定 35 tok/s 仍未达到。

复用已验证的原始 IQ2_S GU/Q2_0 Down 对象和完整输出参考，仅将权重分配从 `malloc_host` 切换为 `malloc_device`。运行时 `get_pointer_type` 必须与放置方式一致。输入、量化、算术、累加精度、N2560/F640、GU16/Down4、240 个真实专家和八个物理集合保持相同。测试 T1/4/6，每个进程通过 72 项完整输出/守卫检查。GU/Down 各精确 2088 次调用，分别包含每种常规工作规模 680 次及另外两种校验规模各 24 次；SwiGLU 的 2088 次调用汇总为一个工作规模行。

## 先校正指标方向

本机 Level Zero 目录查询返回 2128 个组、46580 个条目，去重为 5082 个指标名。目录查询成功仅证明指标被暴露，不能代替采样成功。

- `SYSMEM_BYTE_READ`：GPU 对系统内存的读取，位于 `DataportWrites` 组。
- `HOST_TO_GPUMEM_BYTE_READ`：目录描述为主机读取 GPU 本地内存，方向相反，位于 `DataportReads` 组。
- 目录未找到名称或描述含 TLB 的指标；本组不报告 TLB miss 数。

第一组使用默认 Global Memory Accesses 预设，实际选择了 `DataportReads`，只导出 Host to GPU Memory Bandwidth，不能据此报告 GPU 读取主存的带宽。其两进程数据全部保留，144 项完整输出检查通过。

第二组直接选择同一兼容组内的 SYSMEM、GPU local memory、XVE 和频率计数，复用同一探针 EXE。首次 CLI 因要求 Allow Multiple Runs 而拒绝，未启动目标；失败记录保留。独立 V2 明确允许该选项后完成采集，仍检查每阶段精确 2088 次调用，未用额外重复调用改变统计口径；另 144 项完整输出检查通过。V2 完成时和额外终审均通过。

## 对下一项优化的约束

高主存读取与高占用率同时出现，且驻留显存能明显改变停顿，支持优先减少远程权重访问。它没有唯一证明 PCIe 带宽饱和，也没有排除请求延迟、地址转换或采样归属影响。显存路径占用率下降同时伴随停顿降低；不能只按占用率高低判断速度。

[已完成的 A/B/C 对照](memory-path-2026-10-27.md)中，四种分块双缓冲都未通过独立重复收益门槛。该历史 IQ2_S T1 C30 的四次独立 eager 搬运诊断，按已知 memcpy 有效载荷字节数除以 memcpy 事件时间，得到 8.44–9.58 GB/s；它与本次系统内存读取处于相近范围，但来自不同运行及计时口径，不能当作本次的精确 PCIe 上限。

因此下一步优先检查热点驻留、缺失字节数以及保持草稿接受率的缓存策略；暂不重复全量搬运、盲增线程或未经计数支持的缓存裁剪。[最近裁剪候选](down-retry-fp32-2026-10-28.md)的旧联合组为Code +4.353%、Prose −5.484%，原判定保留。按用户随后更新的单场景规则，新cohort已完成初筛及独立确认：Code +3.996%/+3.746%，独立候选中位数30.42187 tok/s；Prose −6.229%/−6.332%，两场景对应基线漂移均不超过3%。1223个物理显存样本最低空闲1442.117MiB，通过1024MiB门槛。只有Code通过同场景两轮1%性能门槛；完整热历史质量仍等待共享GPU锁，未采用，稳定35 tok/s未达成。低于0.3%的相对吞吐变化仍视为噪音，全部原始样本保留；性能不能替代质量验收。
