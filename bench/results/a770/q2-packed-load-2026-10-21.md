# A770：Q2 打包读取优化（2026-10-21）

采用一处 `Multi<42>::prep` 修改：复用现有 `load8_a2` 读取 Q2 权重，再逐字节解包。整数点积、缩放和浮点归约保持原样。IQ2_XS 模型部分层的 down 同样使用 Q2_0，因此也能受益。

## 最终构建实测

Intel Arc A770 16 GB，Xeon E5-2696 v4，Windows，驱动 32.0.101.9034，DPC++ 2025.3.2，oneMKL 2025.3，Level Zero。单位 µs/次，耗时越低越好；下降比例是专家链延迟下降。

IQ2_S / IQ2_XXS 使用 `strata-iq2_xs.json` 的 GU16 / Down4；Q2_0 使用 `strata-q2_0.json` 的默认 GU8 / Down8。Q2 未继承 IQ2 的调参环境。早期 GU16 / Down4 下的 Q2 数据单独保留在 JSON，未混入上表。

权重取自 IQ2_XS layer 0（IQ2_S）、layer 1（IQ2_XXS）及 Q2_0 layer 0，每种格式 240 个真实专家，分为八组、每组 30 个。激活为固定种子的高斯样本，在计时前量化为 Q8；并非捕获的模型激活。输入 token 数为 1 / 4 / 6，对应 10 / 20 / 30 个专家组、10 / 40 / 60 个激活条目。

计时覆盖完整 gate/up、SwiGLU/Q8、down。普通 in-order SYCL 队列捕获 48 次调用，循环八组专家；每阶段预热 16 次图，取 11 批中位数，每批重放四次图，计入主机提交和等待。两份独立 EXE 直接链接最终基线/候选 IQ 对象，不经过实验派发分支。每种格式按 A/B/A/B/A/B/A 启动七个新进程；每个 B 对应相邻 A 的几何均值，上表再取三组基线和候选耗时各自的中位数。前后基线最大漂移为 1.05%，全部原始数据保留。这不是整模型 token/s 测量。

## 正确性与采用范围

- 最终候选完成 648 组完整输出逐位一致检查，覆盖八组专家、三种 grid_groups、三种输入大小；含非零条目起点、分散输出位置、未使用输出及两侧哨兵。另检查 27 次图重放最终输出。
- 独立 GPU 检查覆盖 8192 个 Q2 半块、全部 256 种编码和地址模 4 为 0 / 2 两种对齐，与独立按字节参考完全一致。
- IQ2_XS 三组固定长提示（2048 / 2048 / 8000 token），每组生成 16 token，基线/候选 token 序列一致。Q2_0 的生成一致性未获确认，详见下面的失败记录；不得把本次算子逐位一致外推为已完成默认生成等价验证。未评价困惑度或整模型吞吐。
- 生成核对显式传入 `--expert-cache 4000`；引擎日志中的有效槽数分别为 IQ2_XS 4191、Q2_0 4000，同模型两边一致。Q2 首次因默认单次分配上限分配失败；放宽分配后，未修改基线在第二个长提示中触发 attention/router 的 GPU 等待超时，短提示也在专家计算前复现。未完成 Q2 默认执行设置的生成对照。
- Q2 短提示核对采用 IQ2 已验证可运行的其他执行设置、较大分配、48 GiB 主内存镜像预算、512 token 上下文，并移除配置中强制的显存余量数值；保留 GU8 / Down8。三组提示各 128 token，各生成 16 token。未控制重复性时，两边仅第一组生成一致，第二、三组有后续 token 分歧，不能按通过处理。再按 [DETAILS 的重复性说明](../../../docs/DETAILS.md) 设置 `STRATA_IQ_MT_MIN=1 --prompt-cache 0 --adapt-swaps 0 --pcie-frac 0`，完成基线/候选/再次基线的三进程核对：两次基线的三组结果全部不能复现；基线/候选仅第二、三组一致。由于基线本身不可重复，生成对照结论为不确定，未获通过。这些结果不能证明生成差异来自读取补丁，也不能证明模型生成等价。完整测试设置和各输出哈希在 JSON 中，用户配置未修改。
- 源码已采用；生产 EXE 与配置未替换。独立生成测试 EXE 共用 2026-10-19 的引擎库，仅 IQ 对象不同，未进行全仓库重新构建。

## 底层指令实验

直接 ESIMD INT8 DPAS 已实测：在多专家图中，耗时为基线的约 1.76～2.51 倍，未采用。独立审计核通过 Level Zero 导出本机二进制并用 ocloc 反汇编，得到：

```text
dpas.8x8 (8|M0)          r22:d         null:d            r13:b             r3.0:b           {$2}
```

这是同类 ESIMD 调用可生成原生 DPAS 的确认；上行反汇编来自独立审计核。SG8 / WG128 在热单专家上看似更快，但多专家图耗时增加约 3%～6%；直接 u2 DPAS 的打包版本未通过正确性，无法得出性能结论。打包读取加乘法位扩展与纯打包读取收益相近，保留改动更小的纯读取方案。

NVIDIA 的 inline PTX 能直接选择 FP16 累加 MMA；A770 DG2 的 FP16 XMX 路径使用 FP32 累加。本次确认能调用原生矩阵指令，也找到读取侧的小幅收益，未测得类似 2 倍的加速。此前 FP16 XMX / GitHub 实现调查见 [前一轮记录](xmx-iq2-q2-2026-10-21.md)。

## 复核

在 oneAPI 编译环境中，从仓库根目录编译并运行唯一新增的 GPU 检查：

```powershell
icx /nologo /EHsc /O2 /MD -Qstd:c++20 -fsycl -fsycl-default-sub-group-size=32 -fsycl-device-code-split=per_kernel /fp:precise -DSTRATA_SYCL_SERIAL_Q8_1=0 -D_USE_STD_VECTOR_ALGORITHMS=0 -I sycl/include -I include -I third_party/ggml sycl/src/kernels/q2_packed_load_parity.cpp -Qmkl=sequential /link /INCREMENTAL:NO /out:build-sycl-a770-q2-dpas-20261021/q2-packed-load-parity.exe
./build-sycl-a770-q2-dpas-20261021/q2-packed-load-parity.exe
```

本机计时源文件、冻结的基线、构建与测试日志位于 `build-sycl-a770-q2-dpas-20261021`。`graph-final.py build` 可重新链接计时程序；原始 run 阶段会拒绝覆盖已有结果，并检查冻结基线，采用源码后不会静默重跑。完整计时、检查、原生指令及源文件哈希见 [JSON](q2-packed-load-2026-10-21.json)。
