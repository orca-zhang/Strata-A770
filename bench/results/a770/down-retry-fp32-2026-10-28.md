# A770 Down：保留原 FP32 路径的整专家重算

A770 16GB / PCIe 3.0 / Windows / DPC++ 2025.3.2。完整 2K 性能筛选未通过：Code 提升 4.353%，Prose 下降 5.484%；没有采用，稳定 35 tok/s 尚未达到。

以上为原冻结联合协议的历史结果。按用户随后更新的单场景规则，Code达到1%初筛条件，仍须独立确认、运行时显存及完整热历史质量检查。新建`performance-single-scene.py`复用同一二进制和已通过的冷质量记录，在全新cohort重测两场景，要求同一场景在两轮配对均通过；不改写下述旧结果。

[上一组](cache-miss-tail-repair-2026-10-28.md)的 10% 裁剪候选评分不重复；其中一次使用 CPU64 小块修复，另一次没有触发修复。后续完整阶段计数又在原专家 Down 复现非有限值。[实际捕获](down-witness-2026-10-27.md)此前还发现两个 8×8 tile 内共 76 个 NaN 和 52 个有限错误。CPU64 修复与原 FP32 XMX 的舍入不同，仅重算含 NaN 的小块也无法覆盖同一专家其他位置的有限错误。

隔离目录为 `build-sycl-a770-down-retry-fp32-20261028/`。保留原 GEMM、IQ、HC、MTP、value、activation 和两个 verifier 对象，仅替换恢复 prefill。每层继续扫描完整专家 Down 输出；若检测到非有限值，将受影响专家去重，用原始 Q2 权重的同一 GPU 解包对象重新生成 FP16 W，经 `Gemm::f16(H,W,Y,rows,2560,640)` 重算该专家的完整输出。在当前冻结的 Level Zero、native XMX 支持条件下，原链的 Down 与这个入口使用同一 `native_xmx_gemm`，FP16 输入、FP32 累加；已保存的实际输入检查通过原生调用日志确认了该分派。其他后端或触发普通 SYCL fallback 的进程不据此宣称同一路径。

重算前检查完整 H/W，重算后检查完整输出；只重试一次。非有限输入、超过 512 个非有限输出、无法归属的路由、U4 输出、不支持的格式或重算仍异常均拒绝请求。它仍以非有限值触发：完全没有非有限值的有限错误不会被此扫描发现，不能称为通用纠错或根因修复。
