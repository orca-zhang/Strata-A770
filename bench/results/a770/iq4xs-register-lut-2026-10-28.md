# A770：IQ4_XS 寄存器查表与标量 SG16 对照

A770 16GB / PCIe3.0 / Windows / DPC++2025.3.2。**寄存器查表两轮均未取得收益。小矩阵标量 SG16 虽通过三/四/六列的独立算子确认，整模型筛选仅为 Code +0.559%、Prose +0.818%，未过联合1%门槛。** 两者均不采用，生产配置与精度保持原样。

候选来自[实际 decode 剖析](decode-gpu-profile-2026-10-28.md)中的 native MMVQ 热点。原版保留冻结对象与 `STRATA_IQ4_XS_SG16=2`：两列使用 SG16，其余列使用 SG32。候选把16项 IQ4_XS codebook 分布在16个 lane 的寄存器中，通过 `select_from_group` 查找各 nibble；标量 SG16 对照保留原查表逻辑。三条路径使用相同整数点积、FP32 算术和逻辑 XOR32 归约；SG16 的 XOR16 经原有 SLM 交换，再做 XOR8/4/2/1。不改变权重布局、字节数或精度。寄存器查表仅在 A770 且输入维度可被512整除时启用，其他情况调用原路径。

权重直接抽取自原模型第一分片，分别核对 GGUF 类型、维度、有效载荷长度和 SHA256；保留文件头哈希及原文件大小、修改时间。四种形状为输出头2560→248320、QKV2560→10240、共享专家上投影2560→640、SSM输出6144→2560。测试每种权重的八个独立 device USM 副本；它是原生稠密矩阵的算子实验，不模拟缺失专家的 host USM 路径或模型缓存命中率。冻结源码中的 native head/dense 加载器本身将这些矩阵上传到显存。

原始链接缺少 `iq_row_bytes`/`iq_mmvq` 两项 IQ 依赖；失败日志和未完成的 `build.json` 保留。随后单独补链接原冻结 `iq.obj`，没有重编候选或原 MMVQ 对象；成功记录在 `build-link-recovery.json`。

九个边界进程覆盖输入512/768/2560、输出7行、列数1–8，576项完整 eager 输出匹配原版；768输入核对候选回退。36个计时进程各检查48项完整 eager 输出及6项图输出，共1728项 eager 和216项图检查，含未使用列、首尾守卫和有限值。45个进程各核对65536种四 nibble 组合的两种 GPU 查表结果及守卫。所有检查通过。

计时顺序为原版 A1 / 标量 C1 / 查表 B1 / 标量 C2 / 原版 A2 / 标量 C3 / 查表 B2 / 标量 C4 / 原版 A3。每臂测四个矩阵、列数1–6，每列预热16图，再保留11批，每批4次48 kernel 图重放，共2376批。计时包含主机提交与图完成，关闭 profiler；每个候选同时与相邻原版和标量对照比较。每个形状/列数的两轮都须达到至少1%吞吐提升，基线耗时漂移不超过3%；绝对吞吐变化低于0.3%视为噪声，保留原数值。

## 小矩阵 SG16 的整模型筛选

仅对 A770、输入2560/输出640、三/四/六列改变主机分派条件，复用原有 SG16 kernel；保留原运算体和全部其他模型对象。私有构建已核对实际链接符号，并通过开关两组各48项 eager 和6项 graph 完整输出检查。与原 FP32 Down-retry 模型做新的 A1/B1/A2，固定请求缓存6000/实际6297槽、reserve1024、正常graph、原始2K输入/完整128输出。实验 min-p0.5，生产0.8未改。

每进程 Short16 初始化、Code/Prose 各一次完整预热、三次交错保留请求；三进程共24次完整2K输出和3次Short输出均匹配原参考。以下是候选中位数与前后基线耗时几何均值的比较，所有样本保留：

| 场景 | 前后基线折算吞吐 | 候选中位吞吐 | 吞吐变化 | 基线耗时漂移 |
| --- | ---: | ---: | ---: | ---: |
| Code2K | 29.289 tok/s | 29.453 tok/s | +0.559% | −0.261% |
| Prose2K | 27.061 tok/s | 27.283 tok/s | +0.818% | +0.025% |

候选保留请求最低为29.365/26.947 tok/s。正值超过0.3%噪音解释区间，但均未满足1%接收门槛，因此不启动后续独立性能确认或候选质量/历史验收。35/40 tok/s未达到，不能将算子约16%–48%的提升作为模型提升。

原 runner 在保存结果后，末尾审计将 Short 初始化误计为第九次 bulk-prefill Down 汇总而退出1；原文件与失败保留。独立恢复审计验证严格日志顺序：Short完成后，八次2K各有预填充、48层Down扫描、请求完成；随后复用其余全部原审计，完整输出、协议、分派、哈希和频率覆盖通过。每进程八次扫描均未触发修复。24个解码区间的1Hz监测样本均为2400MHz、未见节流标志；该观测不覆盖所有瞬间。恢复不重跑、不替换样本，不改变收益结论。
