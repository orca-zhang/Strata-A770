# A770：FP16 路径接入项目与分段复核（2026-10-24）

上一轮的原生 FP16／BF16→FP16 试验路径已接入 `sycl/src/prefill/gemm.dp.cpp`，默认关闭。本轮将 BF16 权重与激活转换合为一个内核，并利用 in-order 队列保留转换→GEMM→汇总依赖，去掉转换后的一次主机等待。K256、K1024 与已有的整段、K512 方式一起测试。

硬件：A770 16 GB、Xeon E5-2696 v4、Windows、PCIe 3.0 ×16；驱动 32.0.101.9034、DPC++ 2025.3.2、oneMKL 2025.3。生产 EXE、生产配置未替换。没有 PCIe 4.0 或 Q2 整模型结果。

| 开关 | 行为 |
| --- | --- |
| `STRATA_PREFILL_HALF_OUTPUT` | 默认关闭；`1` 为整段 FP16 输出，`256`／`512`／`1024` 为相应 K 分段后 FP32 汇总；其他值关闭 |
| `STRATA_PREFILL_HALF_BF16=1` | 同时允许 BF16 输入先在 GPU 转为 FP16，默认关闭 |
| `STRATA_PREFILL_HALF_PROFILE=1` | 调用结束时输出诊断，默认关闭；`body_us` 不含缓冲区析构、回退重算和日志写入 |

仅处理连续输出、beta=0、同一顺序队列上的调用；BF16 输入也须连续。标量点积、填充布局与累加调用沿用原路径。转换或输出出现非有限值时重算原 FP32 路径；有限结果的舍入与下溢差异仍然存在。没有依据输出类型推断硬件累加器类型。

五种模式各完成 1015 项布局／数值检查，共 5075 项。关闭模式与原调用逐位一致；四种候选各有数值不同的用例，保留误差记录。排除布局与 beta 非零调用仍逐位一致，输出边界和队列连续调用检查完成。各模式另外完成 10 项检查，共 50 项，覆盖 FP16 整段输出溢出、分段输出溢出、BF16 转换溢出、溢出值乘零，以及 17 个输出保护元素。

| 模式 | FP16 输入最大绝对误差 | BF16 输入最大绝对误差 |
| --- | ---: | ---: |
| 关闭 | 0 | 0 |
| 整段 | 0.92767334 | 0.877670288 |
| K256 | 0.358291626 | 0.394037247 |
| K512 | 0.56734848 | 0.541259766 |
| K1024 | 0.89642334 | 0.834270477 |

该表相对原 FP32 调用，覆盖 K65～K10240、T1～T256 的本次扩展输入；不与上一轮较少用例的最大误差直接比较。更大的分段不一定提供更好的误差修正；这些绝对误差也不是模型质量指标。

已加入 CMake/CTest 的 `prefill_half_gemm_check`。原逐位一致性测试显式关闭实验精度，专门检查目标显式启用 K512 和 BF16 转换，避免继承外部精度开关。

```text
cmake --build build-sycl --target prefill_half_gemm_check prefill_gemm_parity
ctest --test-dir build-sycl -R "^prefill_(half_gemm_check|gemm_parity)$" --output-on-failure
```

算子对照已完成：同一检查程序分别链接旧／新 GEMM，共 12 个独立进程、192 个计时用例；引擎分配、转换、GEMM、汇总、等待和释放均计时。固定 all128 内存池，3 次预热、7 批 ×3 次取中位数；每个候选与相邻旧版基线配对。旧／新版在相同 K512、整段模式下，全部形状和两种输入类型的完整输出哈希一致。

下表为 BF16 输入相对旧版相同模式的吞吐变化，反映转换调度修改的收益。七个非微型形状中，K512 为 +3.26%～+12.57%，整段为 +2.74%～+19.75%；各自配对基线的最大漂移为 2.49%、0.87%。FP16 输入无需转换，同样七个形状的 K512 变化为 −0.40%～+0.56%，整段为 −0.40%～+3.89%，没有一致的显著改善。

| N × K，T | K512 吞吐变化 | 整段吞吐变化 |
| --- | ---: | ---: |
| 1280 × 2560，40 | +7.13% | +8.89% |
| 2560 × 640，40 | +10.40% | +18.69% |
| 6144 × 2560，4 | +7.36% | +7.56% |
| 6144 × 2560，256 | +12.57% | +12.84% |
| 10240 × 2560，256 | +5.43% | +19.75% |
| 12288 × 2560，256 | +3.68% | +8.67% |
| 320 × 10240，22 | +3.26% | +2.74% |

17 × 65、T4 的微型形状仍保留在原始数据中，未纳入上述范围。部分其他比较的基线漂移超过 3%，不作为稳定提速证据。

扩大分段属于额外的精度取舍。预先写定的筛选规则比较 BF16、T≥22、非微型且两组基线漂移均≤3% 的形状：先分别相对旧 K512 配对，再用新 K512 的配对比率归一化。K1024 的五个合格形状相对新 K512 的归一化增量为 +5.15%～+18.72%，中位数 +9.53%；因此进入整模型复核。K256 更慢，但本次最大绝对误差更小。

算子程序使用 128 MiB 外部扩展工作区；本轮冻结模型 EXE 的 `Gemm::init` 仍为 32 MiB。共享工作区内的另一项修改已把开启 GPU 扩展时的默认工作区增至 128 MiB；本报告不将冻结 EXE 的模型计时视为该项修改后的组合验证。FP16 辅助函数及检查程序与实测源码一致。

模型复核使用 IQ2_XS、固定完整的 256-token Code 输入、INT8 KV、8192 上下文与 4191 个专家缓存槽。相同新 EXE 依次运行 K512／K1024／K512，三次独立冷启动，每次最多生成 8 个 token，关闭精度路径诊断。这里比较同一输入的预填时间和输出前缀，不以短输出的解码计时衡量生成速度，也不据此前缀判断代码正确性或整体质量。

| 顺序 | 模式 | 预填时间 | 生成 token 数 |
| --- | --- | ---: | ---: |
| A1 | 新 K512 | 95.9940 秒 | 8 |
| B | 新 K1024 | 84.3440 秒 | 8 |
| A2 | 新 K512 | 96.1346 秒 | 8 |

两侧 K512 的几何平均为 96.0643 秒，漂移 0.1465%。K1024 相对此基线预填耗时下降 12.20%，吞吐提高 13.8958%（1.139×）。这是新 K512→新 K1024 的本轮增量，不能当作相对默认 FP32 路径的提升，也未测出转换调度单独带来的整模型收益。该结果来自同一提示的一次 A/B/A 筛选，尚未做独立重复或其他输入的确认。

三轮生成 token 均为 `[760, 3766, 1970, 41643, 10551, 264, 4281, 314]`，解码前缀为 `The provided code snippet represents a collection of`。前缀一致只说明这次短输出未发生分歧。K1024 在扩展用例中的最大绝对误差仍高于 K512：FP16 输入 0.8964 对 0.5673，BF16 输入 0.8343 对 0.5413。它是可继续评估的速度／精度选项，保持默认关闭。
