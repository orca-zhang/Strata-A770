# 文本解析的字符串快路径与 SSE2 扫描（2026-10-24）

在上轮行内代码正确性修复的基础上，单反引号使用字符串计数；连续反引号和工具参数终止符可使用 `serve/_text_scan.c` 的原生扫描，避开这两处热路径上的正则。原生实现直接读取 Python 的 1/2/4 字节 Unicode 存储，不做 UTF-8 转换或副本；每次向量读取前检查剩余长度，尾部按字符处理。编译产物反汇编确认含有 SSE2 的 `pcmpeqb`、`pcmpeqw`、`pcmpeqd` 和 `pmovmskb`。

本机为 Windows 10 19045、Xeon E5-2696 v4、64 位 CPython 3.11.9；使用 MSVC 14.50、`/O2 /GL` 编译。采用 x86-64 基线 SSE2，不要求 AVX2；其他架构从同一源码编译标量实现。未编译扩展时自动回退到 Python。逐字符 Python 替代在长反引号、重复参数标签和长空白上出现退化，因此回退保留正则；提示词标记还原的正则也保留。这里没有声称整个项目已移除正则。

构建后，新启动的 Python 服务自动加载扩展；无需重编译模型引擎：

```powershell
python tools/build_text_scan.py build_ext --inplace
python -m unittest serve.test_text_scan serve.test_reasoning_rescue serve.test_reasoning_tools serve.test_mcp.ToolLoop serve.test_server.ToolCallTerminators serve.test_server.ToolCallTagInProse serve.test_server.UnfinishedToolCall
```

构建需要与 Python 匹配的系统 C 编译器及 Python 头文件，使用已有的 setuptools；没有新增运行依赖。本机已完成构建。此处仅验证了 Windows / CPython 3.11.9，尚未验证其他 Python 版本和平台的构建。

测量包含完整 `OutputParser` 的创建、增量解析、事件收集和 finish，也包含 Python/C 调用开销。文本预先按 8 字符分块，分块生成和正确性断言不计时。各版本从冻结的完整模块独立加载，避免旧版本意外调用新版本的参数扫描。每次 A/B/A，每臂 7 个样本；比较 B 中位数与两个 A 中位数的几何平均，基线漂移绝对值超过 3% 则弃用。最终源码测了两轮，并将测量进程固定在逻辑 CPU 42 补测一轮；没有改变其他进程的亲和性或优先级。

正确性验证：

- 与冻结旧实现比较 50,000 次反引号扫描和 160,000 次参数扫描，全部一致，随机种子 20261024。
- 原生路径 67 项全部通过；强制 Python 回退时 65 项通过、2 项原生专项检查按预期跳过；两次运行期间源码哈希均保持一致。
- 检查包含 Unicode 三种存储宽度、NUL、孤立代理项、低字节与目标字符相同的非目标字符、SIMD 边界与尾部、长分隔符及 Unicode 空白。
- 已有逐位置分块、三种本地 HTTP API 的流式/非流式检查和假 MCP 工具循环通过。示例调用保持为文字，示例外的真实调用恰好执行一次。

这些数字只衡量 CPU 文本解析，没有新的真实模型 prefill、decode 或 HTTP 端到端速度结论，README 模型吞吐表未调整。生产配置和引擎 EXE 哈希保持不变。
