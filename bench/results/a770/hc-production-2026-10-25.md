# A770：生产 HC inject XMX 验证（2026-10-25）

相对[专家链批量提交生产版](xmx-batch-production-2026-10-25.md)，将已有 HC inject XMX 实现接入冻结生产对象，并修正尾块工作区预算。固定容量 HTTP A/B/A 和实际自动缓存检查全部通过，**本机启动配置已切换，下次正常启动服务生效**。

## 条件与改动

Arc A770 16 GB、Xeon E5-2696 v4、256 GiB DDR3、PCIe 3.0 ×16、Windows 10；驱动 32.0.101.9034，DPC++ 2025.3.2 / oneMKL 2025.3。Qwen3.8-Flash-Next IQ2_XS、FP16 KV、MTP4、context / prefill 8192、`--short-read 1024`、prompt cache 0、temperature 0、thinking 关闭。本地 Anthropic `/v1/messages` 非流式请求，生成的工具调用不执行。

只重编译 GEMM 对象，保留生产 main、decode、prefill 调度及其他冻结对象和原 **32 MiB 工作区**。HC 的 BF16 `10240 → 4` 投影在工作区内将权重补成 8 通道，复用既有 XMX 内核，再取前 4 通道；仍为 BF16 输入、FP32 累加。每次调用重新整理权重，无持久缓存或新增引擎分配。其他形状、精度、beta、输出行距或工作区不足时保留原路径。未重建整个当前工作区，也未捆绑 GDN 或 INT8 实验。

公开 HC 包装层原来仍按整段输入补齐估算空间，与原 XMX 已采用的尾块补齐不一致。现在对齐行距仅为最后不足 8 行的尾块预留 8 行，非对齐行距仍完整复制。T=2069、K=10240 时，HC 总预算从 **40.69 MiB 降至 393,888 字节（384.66 KiB）**，其中输入补齐为 160 KiB，避免在生产 32 MiB 工作区下误回退。本轮收益包含 HC 接入及预算修正，不单独分摊二者贡献。

## 正确性检查

本轮实际运行 **2647 项检查，全部通过**：1728 项 GEMM、407 项专家链，以及 HC 关闭 / 开启各 256 项。HC 检查扩展至 T=1038 / 2069，并覆盖完整 CPU 双精度参考、对齐及非对齐输入、输出和双工作区保护区、零 / 少一字节 / 恰好 / 多一字节容量、重新绑定、beta=0 的 NaN 目标、131072 等有限 BF16 权重，以及不适用形状和 FP16 的回退。

dyadic 输入与 CPU64 精确一致；随机 BF16 的预设最大绝对误差为 0.005，观测最大值：关闭路径 **0.0000452003442**，开启路径 **0.000223165669**。这不是逐位等价检查；FP32 归约顺序可以不同。独立调度记录确认新路径实际调用 **87 次**，包含 2K 对齐输入使用 393,888 字节工作区。

生产专家批量版 A1 → HC 候选 B → 原生产版 A2，各启动新服务，均请求 5500 个专家槽位，实际为 **5771 slots / 7.74 GiB**。每服务预热三次 255-token 工具，再各预热一次原工具、1K、2K；随后按 **1K → 2K → 原工具** 交替三组。保留全部样本，无重试或择样。
