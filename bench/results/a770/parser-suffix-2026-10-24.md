## CPU 完整解析链对照

同进程 A/B/A，每臂 7 个样本、每样本解析完整文本 3 次，另有一次不计时的正确性预检。A 使用改前快照中的 `_hold`，B 使用两行快速路径，其他解析代码相同；输入按 8 字符分块。每次都验证正文或思考文本，工具场景还验证完整调用及流式 JSON 参数一致。

对照耗时取两臂 A 中位数的几何平均。两轮数据全部保留；每组 A 漂移绝对值超过 3% 时，排除该组的收益结论。两轮共执行 528 次完整解析及内容校验。

共享机器负载未受控。正文和普通工具参数各只有一轮满足漂移条件；思考文本两轮均超限，未得出收益结论。字面标签场景仍会反复扫描工具参数，快速路径没有消除这条路径的高复杂度。

以上百分比仅适用于这些 CPU 解析输入，不代表模型 prefill、decode 或请求端到端收益，因此未加入 README 性能表。

## 未采用的 Nagle 开关

另测试标准库 HTTP 处理器的 `disable_nagle_algorithm=True`，只在实验处理器中切换，生产处理器未改。

使用真实 localhost HTTP 与 `MockEngine`：固定节奏输出分别覆盖 OpenAI Chat、Anthropic Messages、Responses，均测普通 SSE 和 gzip；另测 Chat 的突发输出。每个场景 A/B/A，每臂预热一次，再测 7 个请求。共 192 个请求（168 个正式样本、24 个预热），全部正文、结束事件、gzip 完整性正确，并逐连接检查实际 `TCP_NODELAY` 值。

多数计时超过 3% 漂移门限。满足门限的固定节奏 Messages/gzip 场景，首正文约慢 12.55%，完整请求约慢 1.74%；Responses/gzip 完整请求约快 1.77%，首正文漂移超限。没有得到可稳定采用的收益，因此保留默认网络策略。模拟引擎数据不能视为模型吞吐测量。
