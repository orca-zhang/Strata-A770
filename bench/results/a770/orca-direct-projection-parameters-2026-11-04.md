# Orca Direct：大矩阵参数位置与单算子差距

2026-11-04，Windows 10 22H2，Intel Arc A770 16 GB，驱动 `32.0.101.9034`，oneAPI 2025.3。

[整模型分段诊断](orca-direct-prefill-phases-2026-11-04.md)发现，Direct 的长上下文投影区间增加，抵消更多专家链节省。
本轮只隔离通用 FP16 M4 大矩阵及参数位置，不更换数学内核；**没有运行新的整模型性能对照，也不接入该候选**。

## 隔离和校验

候选仅改冻结运行时的内部状态与参数选择条件，没有公共 ABI 变化；所有已有 Host 对象与数学 pack 复用。
只对名字含 `native_xmx_launch_m4` 且至少 4,096 个 workgroup 的 eager 派发启用现有 device mirror，
保留原有上传、参数缓存、捕获与队列所有权规则。小网格、其它内核和录图策略保持原样。
通过 14 项 CTest、840 项双专家完整输出检查，以及引擎与 BCS 开／关队列检查。

独立算子为 M=2,047／7,999、N=6,144、K=2,560，输入 stride=2,568，FP16 输入／权重、FP32 输出。
这些是代表性大形状，不能替代全部真实模型投影。使用相同的现有 XMX zebin；每次交替两个输出地址，
避免只测不变参数的缓存命中。CPU 参考使用可精确表示的二进制分数，检查完整输出、输入／权重／尾行缓冲全部字节与保护区。

无 GPU 时间戳探针的顺序为 **L0 → Direct 关闭 → Direct 开启 → Direct 关闭 → L0**。
分配、上传、两次带 NaN 毒化的预热检查和额外预热均在计时外；每形状每进程 9 次派发加等待的 Host 墙钟采样。
五进程合计 **90 个样本、60 项完整数据检查**。另外两个诊断进程各通过 12 项数据检查；
关闭／开启分别捕获 28 条 host／device 放置记录，全部是 eager 路径，证明候选确实被执行。
干净进程没有开启放置日志或 GPU 时间戳。

## 参数位置结果

单位 ms；先取每进程 9 次样本的中位数，再对同类两侧控制进程取几何均值。负的耗时变化代表更短。
不把 9 次样本当成 9 个独立进程；单个进程内的样本不能建立跨日重复性。

| M | L0 两侧 | Direct 关两侧 | Direct 开 | 开／关耗时变化 | 关控制漂移 | 开／L0 耗时变化 | L0 漂移 |
| ---: | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| 2047 | 59.8774／59.7971 | 64.7965／63.8534 | 63.4768 | -1.316% | -1.455% | +6.082% | -0.134% |
| 7999 | 231.5045／231.1815 | 248.6094／247.7334 | 250.1510 | +0.798% | -0.352% | +8.130% | -0.140% |

2K 的小幅变化与关闭控制的漂移接近，8K 开启后反而更慢；没有建立参数 device mirror 的稳定收益。
这次局部放置实验没有消除单算子差距，也不能排除其它参数布局、上传批次或工作负载中的影响。

## 独立 GPU 时间戳诊断

随后只改探针 Host TU，复用同一运行时与数学 pack；关闭参数候选，以 **L0 → Direct → L0** 再跑一次。
每次派发前后各写一个原始 GPU timestamp，使用两条独立的 64 字节 host cache line，并保留第三条未用 slot。
每次检查未缺失、36 位回绕、全部保护字及未用 slot。共 **84 个带保护的区间**，其中 54 个为采样区间；
36 项完整输出／来源／边界检查全部通过。归档保留全部采样原始 ticks。

两边统一用名义 19.2 MHz、36 位换算，避免 L0 整数 52 ns 与 Direct 浮点 timer resolution 的差异；
这里不重新校准实际频率，也不声称高精度绝对时钟。标记增加 barrier、提交和 Host 检查，
**这些诊断耗时不能当作新性能成绩**。GPU 标记区间也可能包含 Host 派发与依赖空隙，不等于独占 kernel 时间。

| M | L0 首次 GPU 区间 | Direct GPU 区间 | L0 末次 GPU 区间 | Direct／L0 区间变化 | L0 区间漂移 | 同轮 Host 墙钟：L0／Direct／L0 |
| ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| 2047 | 59.6276 | 62.7856 | 59.6793 | +5.251% | +0.087% | 59.9397／63.0659／59.9292 |
| 7999 | 231.2596 | 247.0596 | 231.2772 | +6.828% | +0.008% | 231.8022／247.3713／231.6700 |

应结合两张表判断差距是否也存在于 GPU 标记区间，不能用墙钟减 GPU 区间直接给 CPU 成本定界。
同一内核的独立大矩阵对照缩小了排查范围，但不覆盖真实模型中的反量化、权重布局、专家 staging 或所有投影形状；
仍需进一步区分缓存／资源／派发状态与标记之间的空隙。M16 通用大矩阵寄存器复用仍未在本轮实现。

## 复现和边界

保持现有部署 EXE、默认配置及运行时源码策略。Direct 仍为实验路径，Orca L0 仍推荐。
本轮没有新的整模型吞吐、PPL 或 Linux GPU 结论，也不关闭已有 Direct 8K 间歇异常。

```powershell
python -X utf8 build-orca-slm-async-20261104/projection_parameter_check.py build --verify

python -X utf8 build-orca-slm-async-20261104/projection_execution_check.py r1 --verify
python -X utf8 build-orca-slm-async-20261104/publish_projection_parameters.py --check
```

新的测量使用未存在的 r2 等目录，不覆盖成功或失败证据；运行和构建都持有共享 GPU 锁。
同条件复现需要相同 A770／驱动、冻结运行时／Host 对象、同一数学 pack、oneAPI 环境与闲置主机。
归档包含源码、补丁、构建／链接命令、原始采样／放置日志和校验数据，二进制以 SHA-256 记录，不分发 EXE／数学模块。
