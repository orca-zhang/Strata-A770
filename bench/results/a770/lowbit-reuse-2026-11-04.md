# A770：U4×S4、U2×S8 的 prefill 分块与小 M 筛选

2026-11-04，Windows 10 22H2，Arc A770 16 GB，驱动 `32.0.101.9034`，oneAPI 2025.3。

已完成低位原生布局的独立 GPU 筛选。U4 缩窄小 M、按形状选择 N8 有收益；U2 的 N16 复用在
M160 prefill 有收益，所测小 M 没有通过收益门槛。**这些是合成整数输入、已打包热显存内核的结果，
不是生产 GEMV、完整专家链或模型 tok/s。没有修改生产分派、模型、配置或部署 EXE。**
独立程序使用 SYCL／Level Zero 提交，不经过 Orca Direct 运行时。

## 格式、对照与计时

U4 使用一张 U4 权重平面、两张独立 S4 激活平面，group64，逐组做 `DPAS−8×sum(S4)`、
FP32 缩放与 FMA 累加。U2 使用 U2 权重和 S8 激活，保留 Q2 的 group64 权重缩放、两个独立
group32 激活缩放，并做 `DPAS−sum(S8)`。未进行重新量化或模型质量比较。

U4 对照沿用既有实验的 M8/N16；U2 对照保留既有 DPAS helper 的 M1/2/4/8、N8 几何，
但所有 U2 臂均使用预打包 B，排除了生产 Q2 的 gather／重排成本。U2 测试缓冲还把 FP32
group64 权重 scale 在两个 group32 中各存一次，有效载荷为 3 bit/权重，原 Q2 为 2.25 bit/权重；
因此这里的相对分块收益不能作为保持原 Q2 驻留容量或搬运字节数的结论。

候选分别为窄 M/N16、M8/N32、共享权重的 M16/N16、窄 M/N8。M 是每专家实际行数，
不是整段 prompt 长度。覆盖 GU 1280×2560、Down 2560×640、HC 320×10240，M1/2/4/8/40/128/160
中的相应组合；小形状另检查不整齐行列、零行和尾部。

首轮 r1 每次等待、读回后再提交下一样本，使用 3 次预热、9 个样本。空对照出现超过 10% 的
偏差，192 个候选夹测中 88 个漂移超 3%，该协议不用于性能结论，原始数据完整保留。

r2 改为每阶段连续提交 64 次预热，再连续提交 31 个带独立输出和 guards 的样本；等待后
逐样本读回，不通过重复覆盖只检查最后一次。只计每个 kernel event 的开始至结束，
不计编译、JIT、量化、预打包、传输、CPU 提交／检查或模型时间。每个形状复用一份 device USM
权重；没有测冷权重／流式读取或缓存命中率。GPU 未锁频，使用共享 GPU／编译实验锁。

r3 加入非幂次缩放 smoke 后，U4 首形状出现 1 ULP 的 CPU/GPU 差异，停止于 smoke，
没有性能进程。原始编译、源码、输出和失败完整保留。最终 r4 使用显式 GPU FP32 FMA、
CPU `std::fma` 和 `/fp:precise`，通过非幂次缩放检查后，使用相同连续提交协议。
此前的 r1/r2 不与最终数学／编译选项合并作性能结论。

每候选由相邻原路径前后夹测，控制取两侧中位耗时的几何均值。r4 使用正／反／正／反顺序
的四个独立性能进程，保持同一冻结 EXE。每个顺序均须吞吐提升≥1%、相邻控制耗时漂移≤3%。
U4 M>4 的 mode1、所有 U2 mode4 是同内核空对照，不允许算作收益。

## 正确性与接入范围

r1 通过 4,888 项完整 CPU 输出／输入不变／guards 检查；r2 通过 14,392 项；最终 r4 通过 28,456 项。
CPU oracle 从独立的行主序整数重建全部输出，检查偏移修正、逐组缩放、两个激活平面和
不整齐的输出 stride。每个保留计时样本都独立检查完整输出；每形状另检查全部输入、scale、sum
及 guards 不变。计时输入使用 2 的幂次缩放；最终 smoke 另使用带非平凡尾数的缩放，仍逐值精确匹配
CPU FP32 参考。包含非零 M1、零行、完整整数码范围及行列尾部，不构成任意浮点分布、量化质量或模型 PPL 验收。

已有 U4 转换器自检、U2 group64 布局／整数点积／采样拒绝自检也通过。生产 decode 仍保留
当前 grouped GEMV；这些结果支持继续检查真实激活、权重、路由覆盖及完整链成本后再选择分块。
未建立生产 GEMV 提速、端到端 prefill／decode 收益或 Linux GPU 结果。
