# A770：长提示恢复检查与 GDN 布局修正

**40 tok/s 尚未达到。生产 EXE 和配置未改。** 本轮为正确性诊断和冷启动筛选，没有完成预热后的重复配对性能验收。

A770 16 GB、E5-2696 v4、256 GiB DDR3、PCIe 3.0 x16、Windows、驱动 32.0.101.9034、DPC++ 2025.3.2。IQ2_XS、完整草稿词表、K16/V4、context/prefill 8192、MTP window 1024、prompt-cache 0。保留原始 Code2K / Prose2K 的 2048 个输入 ID，每次生成完整 128 个 token。

## 正确性

原生产的非有限值诊断、命令图、禁用 XMX 专家批量和普通 eager 四组，各完成 Short16、Code2K/128、Prose2K/128、Code2K/128。12 次完整 2K 请求全部匹配历史参考；非有限值诊断没有报告 residual、PLE 或 GDN state 异常。这不证明此前记录的间歇性全零错误已解决。

复用[已有 GDN 交错输出修正](gdn-ab-xmx-2026-10-24.md)，只替换隔离构建中的 GEMM 对象，保持旧生产 ABI 和 32 MiB 工作区。原路径在 N48/K2560/ldy96 时覆盖另一半行及尾部 padding。独立检查新增实际预填的 T2047：widen、XMX 各通过 158 项，随机输入相对 CPU64 的最大绝对误差分别为 9.81595367e-05、8.58786516e-05；关闭修正时按预期失败于 `alpha overwrote beta half`。

修正后的三组模型探针均完成全部请求，9 次完整 2K 请求没有全零输出。每组两次 Code 输出一致，三个独立进程的 Code、Prose 完整输出也一致。文本可解码且内容连贯；这是有限的可重复性检查，没有通用质量评估。它们与旧参考不同，不能继续把已知错误布局的旧参考当作数学正确性的标准。

## 速度观察

每行是一个新进程，顺序为 Short16、Code、Prose、Code；全部请求保留。缓存会随请求调整，末次 Code 已经比首次更热，没有相同预热程度的配对对照。

| 设置 | 实际专家槽 | 首次 Code tok/s | Prose tok/s | 再次 Code tok/s |
| --- | ---: | ---: | ---: | ---: |
| 原 eager | 6297 | 23.793 | 24.244 | 27.062 |
| 原命令图 | 6297 | 26.245 | 26.872 | 30.197 |
| 修正 GDN，命令图 | 6297 | 26.018 | 26.436 | 29.299 |
| 修正 GDN，命令图，auto/reserve768 | 7577 | 28.493 | 28.861 | 31.913 |
| 上述方案，CLI spec3 | 7399 | 26.108 | 25.492 | 29.842 |

auto 容量由当时可用显存决定。7577 槽启动空闲显存为 638 MiB，7399 槽为 708 MiB；都不是峰值余量保证。spec3 的内部 verify/MTP 容量为 5/3，其他为 6/4。缓存容量及工作量不同，表中数值不用于拆分独立收益，也不作采用依据。

两次尝试 CPU 混合路径均失败：环境变量取值 `0` 和移除变量的语义不一致，第一组只生成一个 token；移除相关变量的组出现全零输出。原始记录保留，不计入有效速度结果。

## 构建范围与后续

检查当前生产 EXE、verifier 和 MTP 对象中的开关字符串，生产不包含 `STRATA_GDN_Q8_TAIL`、`STRATA_QSA_Q8_TAIL`、`STRATA_VERIFY_DESC_CACHE`、`STRATA_MTP_CHAIN_SUBMIT`、`STRATA_MTP_COST_WINDOW`，虽然部分开关出现在配置里。因此不能仅凭配置把后来源码优化归给当前生产。

已准备仅移植现有 GDN 输出内核及 256 GRF 设置的旧 ABI 隔离构建，保留原计划内核和其他接口。准备的差分检查覆盖 SG16/32、窗口接受边界、输出前缀、守卫区、图重放及只读输入。写本报告时，它在等待另一项实验的活跃 GPU/编译锁，尚未编译或验证，不属于本轮已通过的结果。不得据此替换生产。

随后首次编译因误用 CUDA 版 `q8_1_finite.hpp`、找不到 `cuda_fp16.h` 而失败，原目录保留。`gdn-kernel-v2` 改用冻结 SYCL 头文件，已启动新构建；截至本次续查，它仍在等待另一项实验 PID10684 的活跃锁。原阻塞进程 PID6844 已退出，不能继续沿用其身份判断。

另准备 `gdn-tail-v2`：复用原生产 verifier 的冻结源码，仅增加进程级开关、给 GDN 调用传入 Q8 输出缓冲区、启用时跳过独立量化三处修改；对象布局和其他调用保持原样。隔离内核增加现有 Q8 输出分支，准备复用既有 649 项完整差分检查。源码、链接路径、哈希和 Python 语法已检查，尚未编译、执行检查或测速。模型探针新增修正 GDN 参考的严格输出比对，防止仅凭非零输出继续性能实验。

本轮继续采用文章中减少同步、命令图及提高专家驻留的思路；没有移植分布式服务架构。BF16 top-k 的输入格式、DeepSeek 的有界重放前提和机架吞吐口径不直接对应本机模型。后续候选仍需通过完整原始 2K/128 输出、固定缓存和预热后的重复对照，才报告收益或宣称达到 40 tok/s。
