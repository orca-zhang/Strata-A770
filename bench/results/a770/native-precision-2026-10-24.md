# A770：原生 FP16、BF16 与分段 FP32 汇总（2026-10-24）

已完成五轮 IQ2_XS 真实模型对照：强制批量路径的完整 23-token 请求中，原生 FP16 输出与 BF16→FP16 的组合使 prefill 吞吐达到相邻基线的 1.956 倍；K512 分段、FP32 汇总的组合为 1.611 倍。两种候选都正确解释了这道天空为何呈蓝色的问题，措辞和长度不同。这是单题质量观察，没有证明普遍质量不变，也没有测得 Q2 或持续生成速度翻倍。

独立算子上，原生 FP16 输出在多个实际投影形状达到约 1.7～2.1 倍吞吐，分段版降低了部分误差并保留加速。原生 BF16 输出更准确但更慢；`float_to_bf16` 与 `float_to_bf16x3` 初筛没有明显加速。

硬件为 Arc A770 16 GB、Xeon E5-2696 v4、Windows、PCIe 3.0 ×16；驱动 32.0.101.9034、DPC++ 2025.3.2、oneMKL 2025.3。没有 PCIe 4.0 数据。生产 EXE 和配置未修改。

基线在 GPU 将 16 位输入转为 FP32，再调用原生 FP32 GEMM。独立测试预留足够的转换缓冲区，所有形状都能走这条基线；引擎中的工作区容量限制不同。候选分别为：

- FP16 原生输出，再在 GPU 转回调用者需要的 FP32。
- 每 512 个 K 元素做一次 FP16 输出 GEMM，在 GPU 把各段结果累加到 FP32 输出。
- BF16 原生输出，再在 GPU 转回 FP32。
- 保持 FP32 输入/输出，测试 oneMKL 的 `float_to_bf16` 和 `float_to_bf16x3` 计算模式。

输入是相同的周期性二进制有理数，能够被 FP16 和 BF16 精确表示；CPU 独立计算全部参考输出。计时包含输入转换、所有分段 GEMM、输出转换或汇总、主机提交及队列完成；缓冲区复用，不含引擎分配、额外输出搬运、模型权重读取和解量化。

所有测试固定使用 all128 内存池，总预算 512 MiB。每形状预热 3 次，再测 7 批、每批 3 次，取批次中位数。初筛 A/B/A，FP16 两条路径另做独立 A/B/A/B/A；每个 B 与相邻 A 的几何均值配对。GPU 测试串行并检查竞争进程，原始源文件、EXE、脚本、配置快照和日志均有哈希。

每一行都相对本次实验相邻的 FP32 基线，不跨进程组拼接绝对耗时。gate/up 为 N1280/K2560，down 为 N2560/K640，gate 为 N6144/K2560，QKV 为 N10240/K2560，Q 为 N12288/K2560。

FP16 原生输出确认轮中，上表对应项目最大基线漂移分别为 0.03%、2.53%、0.10%、0.62%、0.21%。首个 gate/up 4 行项目出现最高 67.37% 的基线漂移，保留原始数据，但不作为稳定收益。K512 的部分大矩阵候选耗时也明显波动，因此保留两次范围，没有把最快一次当作结论。

两个 BF16 计算模式均完成 A/B/A 全输出与越界检查，样本输出与 FP32 参考完全一致。10 个形状的吞吐变化分别为 −1.61%～+0.69% 和 −0.87%～+2.10%，本轮没有明显收益，不再为它们追加确认轮。这只描述当前 oneMKL/A770 路径，不能据此推断底层是否使用了补偿指令，也没有覆盖任意 FP32 输入的残差补偿精度。

K2560 的参考结果约为 19.28～20.53，原生 FP16 的上述误差约占结果的 0.47%。该样本仅最终转一次 FP16 的最大舍入误差是 0.0078125，因此原生 FP16 的误差还包含其他数值差异。BF16 原生输出在全部样本中与 CPU 参考最后转一次 BF16 完全一致。

这些差异用于衡量速度与精度的取舍，不把数值或 token 不同自动判为不可用。K512 仅改善了这组样本的误差与范围，仍需检查模型实际输出。输出类型与误差表现不能单独证明硬件累加器类型，本轮也没有测量指令峰值吞吐。

私有引擎原型支持整段 FP16 输出与 K512 分段；可选在 GPU 将 BF16 输入转为 FP16。仅处理连续输出、beta=0 的调用；其他布局沿用原有路径。转换或输出出现非有限值时重新执行原有 FP32 路径。该版本用于后续对照，未写入生产配置。

私有引擎的三种模式各完成 486 项检查。未启用候选时无数值差异；两种候选分别有 68 个存在数值差异的用例，均记录而未当作失败。beta 非零、填充布局与标量排除路径保持原结果，边界检查通过。覆盖 K10240 的这组扩展输入中，整段 FP16 的 FP16/BF16 输入最大误差分别为 0.73585/0.64411，K512 为 0.46573/0.48455；不能把前面 K2560 样本的误差当作通用上限。81920 用例在整段模式触发一次 FP32 回退，在分段模式无需回退，均得到正确有限结果。

模型实验使用同一私有 EXE：`build-sycl-a770-half-model-20261024/engine/model/strata.exe`。`STRATA_PREFILL_HALF_OUTPUT` 默认关闭，`1` 为整段 FP16，`512` 为分段版；两种候选同时设置 `STRATA_PREFILL_HALF_BF16=1`，因此模型数据衡量 FP16 路径与 BF16→FP16 路径的组合，未分离各自贡献。基线与候选均开启原有 FP16/BF16 GPU 转 FP32 路径，固定 all128 内存池、FP16 KV、4191 专家槽、`--prefill 32 --short-read 16`，完整 23-token 输入，最多输出 128 token。每轮为独立冷启动，加载不计入引擎 prefill 时间；Windows 的原有首次 prompt priming 保留。

服务模式用 `_Exit` 结束，不执行 `atexit` 回调，因此模型调用数和非有限值回退次数不可用。最初的检查脚本在第二轮成功请求后因缺少这些统计而中止；`model-v2.py` 校验并复用前两轮原始日志、EXE、环境和请求，续跑后三轮。引擎数值、边界与回退检查仍使用未改变的同一 EXE；没有为取得统计而改变计算路径。

三种回答都将原因归于瑞利散射和蓝光比红光更容易散射。整段版回答更短，分段版重新组织了句子；分段版虽降低了算子样本的最大误差，生成 token 却更早发生变化。因此没有将不同长度的生成耗时用作加速证据，也没有用单题结果替代困惑度、代码正确率或长文本质量测试。该测量不覆盖生产默认短输入路径、长输入与 Q2 整模型；候选仍保留为私有试验版，未默认启用。
