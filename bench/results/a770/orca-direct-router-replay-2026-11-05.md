# Orca Direct：输入就绪后的路由独立回放

2026-11-05（UTC+8），Windows 10 22H2，Intel Arc A770 16 GB，驱动 `32.0.101.9034`，oneAPI 2025.3。
[Short 阶段诊断](orca-direct-short-router-phases-2026-11-05.md)里的路由区间包含投影、独立量化和额外标记。
[空时间戳校准](orca-direct-timestamp-cost-2026-11-05.md)已证明标记本身存在后端差异。
本 demo 完全不插 GPU 时间戳，使用现有原运行库、同一数学 pack 和薄队列接口，
将输入、权重、模块、缓冲及录制列表先准备好，再测列表提交与最终等待。

形状为输入维 2560、512 个专家、T=1／4；每个列表包含 48 组相同路由投影，
比较仅投影、投影加两项量化串行、同样三项独立工作并行。
两项量化分别是 Q8_1＋BF16 双输出及原生 Q8_1；并行组在入口依赖输入就绪，出口保留排序屏障。
T=1 的并行模式也用于接口检查，生产引擎的对应分叉条件并不覆盖 T=1。
同一权重被重复读取，缓存状态与完整模型的 48 份逐层权重不同，不能外推模型吞吐。

每种录图复用两个改变过的输入；每个输入回放十次，丢弃前三次。
先 Direct → L0 → Direct，再 L0 → Direct → L0，共 **720 次完整回放检查／504 次保留墙钟采样**。
投影逐值对照精确整数累加得到的 CPU 参考；BF16 输出逐值检查，
两种 Q8_1 图像逐字节比较，再把每次图回放的全部输出和 guard 与同后端 eager 结果逐字节比较。
两种输入和权重连同 guard 均回传检查不可变；六进程的 72 个完整输出校验和一致。
校验和用于跨进程核对，不替代逐元素 CPU 与逐字节图回放检查，也不是独立 Q8_1 CPU 精度验证。

计时只包围一整张列表的提交与最终等待。上传、输出清零、回传、校验和打印在计时外。
表中是 **48 组工作的总墙钟 µs**，含提交、完成通知和唤醒，不是独占 kernel 时间。
每个进程先取七个保留样本的中位数，再对同后端的两侧控制取几何均值。

这是单日的两轮反向后端顺序包围对照，模式顺序固定，没有反向模式顺序或模型复测。
结果只用于判断无需逐算子计时也能否复现独立路由工作的差异；
不能将阶段诊断的“约 45%”当作真实投影内核差距，不能把本表差异叠加到整模型成绩。
并行模式仅改变依赖关系，不能据此证明 EU 与 XMX 或多个物理引擎持续同时运行。
本轮没有修改运行库、数学内核、生产默认或部署 EXE；HC1 独立回放、Linux GPU、
