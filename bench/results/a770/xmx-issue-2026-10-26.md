# A770：原生低位 XMX 与 HC 注入窄矩阵

本轮落地了两项内容：A770 两个实测尺寸的 HC 注入 GEMM 工作组优化，以及可复现的低位整数 XMX 指令基准。没有发现可直接迁移的 Ada 固件解锁路径。以下指令吞吐与 HC 注入 GEMM 耗时分别计量，本轮没有整模型 A/B。

硬件为 A770 16 GB / Windows，显示驱动 32.0.101.9034，SYCL 驱动标识 `1.17.39500+2`，DPC++ 2025.3.2、Level Zero。

## 已采用的工作组优化

HC 注入使用 BF16、N=4、K=10240；已有实现把权重填到 N=8，调用 FP32 累加的 XMX GEMM，再散射四列结果。原 kernel 每工作组有八个子组，其中七个在列范围检查时退出。候选只改为一个子组，沿用原算术、填充、尾块与 workspace。

冻结基线与候选各跑两组新进程 A1/B1/A2/B2/A3，每进程包含原有 256 项 HC 检查和 13 个 T 的计时。某尺寸的四个配对必须全部满足吞吐提高至少 1%、相邻基线耗时漂移绝对值不超过 3%，才可采用。

| T | 四次配对的吞吐提升 | 最大绝对基线漂移 | 采用 |
| ---: | ---: | ---: | --- |
| 1024 | +9.75%～+18.71% | 2.14% | 是 |
| 2069 | +3.74%～+8.28% | 1.31% | 是 |
| 其余 11 个尺寸 | 未全部通过收益或漂移门槛 | 全部数据保留 | 否 |

T=512 虽四次收益为正，其中两次基线漂移超限；T=1038 有一次收益不足 1%，均不推广。[最终分派](../../../sycl/src/prefill/gemm.dp.cpp) 限于设备名含 A770、BF16、N8、K10240、T1024/2069，使用原有 native XMX 开关。HC 注入仍由已有 HC injection 选项控制。

计时包括此 GEMM 调用内的填充、矩阵计算、散射、提交和等待，**不是整个 HC 模块或整模型耗时**。每个 CASE 是原基准七批的进程内中位数，未保存那七个原始批次；十个进程的全部 CASE 中位数、输出哈希与配对均保留。

## DPASW 没有带来吞吐突破

新增 [xmx_issue_bench](../../../sycl/src/kernels/xmx_issue_bench.cpp) 先加载输入，再以八条独立累加链运行重复矩阵指令，最后写回完整结果。计时前后逐元素对照精确 CPU 点积。输入、输出使用 shared USM；event 时间仍包含最初加载和最终写回。

每种输入、local=2/8、4096 work-items、8192 次循环、每进程九个 GPU event 样本。每个组合两组 A1/B1/A2/B2/A3，A=DPAS、B=DPASW，共 60 个进程，使用相同四配对门槛。

| 输入 / 累加 | 全部进程吞吐范围 | DPASW 配对吞吐变化 | 结论 |
| --- | ---: | ---: | --- |
| FP16 / FP32 | 114.46～114.95 TFLOP/s | −0.094%～+0.361% | 未通过 1% |
| BF16 / FP32 | 114.53～114.94 TFLOP/s | −0.106%～+0.126% | 未通过 1% |
| INT8 / INT32 | 229.39～229.87 TOPS | −0.196%～+0.065% | 未通过 1% |

Native 审计确认分别生成 DPAS、DPASW，基准循环内没有 memory send。DPASW 的部分输入寄存器共享在本实验中没有提高有效指令吞吐，不能视作“开启另一半 XMX”。

## 双低位整数接近两倍吞吐

额外检查了无符号码权重与有符号激活的原生 DPAS，均为 INT32 累加。八条累加链、local=2、4096 work-items、九个样本；K32 跑 8192 次，K64 跑 4096 次，**各臂运算量相同**。每个候选两组 A1/B1/A2/B2/A3，以 U8×S8 为控制，共 40 个新进程。

| 权重 × 激活 | 候选吞吐范围 | 四次配对吞吐变化 | 通过门槛 |
| --- | ---: | ---: | --- |
| U4 × S8 | 227.73～227.83 TOPS | −0.867%～−0.776% | 否 |
| U2 × S8 | 227.62～228.03 TOPS | −0.944%～−0.715% | 否 |
| U4 × S4 | 453.72～453.92 TOPS | +97.37%～+98.17% | 是 |
| U2 × S2 | 449.67～450.09 TOPS | +95.86%～+96.35% | 是 |

所有配对绝对基线漂移小于 0.714%。完整输出通过 CPU 整数参考，native 汇编也确认了对应的 u4/s4、u2/s2 输入精度。这是 A770 已有的低位整数能力：仅权重低位时 K 仍为 32；两种输入均低于八位时 K=64，U2×S2 在此指令上没有再比 U4×S4 翻倍。

这些是重复使用寄存器输入的合成指令结果。Strata 的 IQ2 码本、分块缩放和激活量化尚未接到这条路径，精度、转换开销与真实专家链收益仍需独立验证；本轮没有切换模型量化格式。

低位测量的 40 个 GPU 进程全部完成，原统计脚本随后因候选名称与数值字段重名而失败。另写只读分析修正字段名，使用原有全部样本和门槛重算，没有重跑 GPU、补样或删样。此前日志重定向、oneMKL 搜索路径的联调失败也保留在本机原档。

## 与 Ada 项目及下一条猜想的关系

检查的 [gpu-unlock-ada 版本](https://github.com/JustAResearcher/gpu-unlock-ada/tree/a63cf8060f10ef94d29aa0aeaad37b7cf499dac0) 使用 NVIDIA 特定签名 booter、payload 与 speed-select。它报告 4090 的 FP16/BF16→FP32 指令吞吐约翻倍，INT8、dp4a、标量 FP32 不变；其改装 48 GB 4090 的单个量化 MoE 个例没有提速（8K prefill 0.983×）。这些是上游记录。

Intel NEO 的 [DG2 EU fusion 条件](https://github.com/intel/compute-runtime/blob/1fbad6424820865caa8b4722f4d415e0d0ace8ad/shared/source/xe_hpg_core/dg2/os_agnostic_product_helper_dg2.inl#L187) 依赖 DPAS 与工作组形状，不能据此推断一半算力被锁。该核对版本的 [Windows NEO debug-key 开关](https://github.com/intel/compute-runtime/blob/1fbad6424820865caa8b4722f4d415e0d0ace8ad/shared/source/debug_settings/windows/debug_variables_helper.cpp#L12) 返回 false，不能假定 Linux NEO 环境变量可直接使用。

本次还导出了两个冻结旧生产 `native_xmx_launch` 内核，二者使用 DPAS。基准的八条有效矩阵指令前有一条额外指令，旧生产 K 循环中的有效 DPAS 前也有同类指令，其形态与公开 IGC 的 [dummy DPAS workaround](https://github.com/intel/intel-graphics-compiler/blob/b64c27946c18a6f095428145572e902eccb9c806/visa/LocalScheduler/SWSB_G4IR.cpp#L7614) 相符。19 个审计模块均为 128 GRF，metadata 未声明 spill buffer；这里只证明被导出的内核，未覆盖整个引擎。

下一条值得验证的猜想是 **HC 转置成 4×8 tile**：保留 BF16 输入和 FP32 累加，尝试省掉补八列与散射，并检查 repeat-count=4 是否减少该 workaround 开销。公开 IGC 的该插入条件包含 repeat-count=8，但实际生成代码、完整注入 GEMM 和模型表现尚未测量，本轮没有据此删除防护或启用新路径。

## 验证和复现

最终修改源码的隔离构建通过 1728 项 XMX 边界检查、256 项 HC 检查，全部 HC 输出哈希与基线一致。扩展后的基准通过 CMake/CTest 的 131 组精确 CPU 对照、全部五种低位 CLI、非法参数与 INT32 溢出拒绝检查，以及 FP16/低位的偶数样本中位数检查。

使用已配置 DPC++ 2025.3.2 的 SYCL 构建，启用 `STRATA_SYCL_PARITY=ON`：

```powershell
cmake -S sycl -B build-sycl -DSTRATA_SYCL_PARITY=ON
cmake --build build-sycl --target xmx_issue_bench
ctest --test-dir build-sycl -R '^xmx_issue_check$' --output-on-failure
.\build-sycl\xmx_issue_bench.exe fp16 dpas 8 2 8192 9 4096
.\build-sycl\xmx_issue_bench.exe fp16 dpasw 8 2 8192 9 4096
.\build-sycl\xmx_issue_bench.exe u8s8
.\build-sycl\xmx_issue_bench.exe u4s4
python bench/results/a770/check_xmx_issue_20261026.py
```

低位 CLI 固定 DPAS、八条累加链、local=2；默认迭代次数已按 K32/K64 配成相同运算量。一次乘加计两次操作，TFLOP/s/TOPS 均不代表整模型吞吐。[全部数值、配对、源码与证据哈希](xmx-issue-2026-10-26.json)。本机可给数值检查加 `--local`，额外核对冻结证据文件与最终源码哈希。
