# A770 XMX：SLM、软件双缓冲与寄存器复用

2026-11-04，Windows 10 22H2，Intel Arc A770 16 GB，驱动 `32.0.101.9034`，oneAPI 2025.3。

这次独立内核实验找到的收益来自较大分块的寄存器复用。当前两种 SLM 分块与软件双缓冲实现均未胜出，显式 L2 预取也不适合全局启用。**没有采用生产内核、修改默认配置或部署 EXE；不是整模型吞吐或 TTFT 收益。**

## 六个变体与范围

输入为 FP16，输出和累加为 FP32，K 按 16 顺序累加；每个 workgroup 64 work-item、8 个 subgroup、SG8。所有变体请求 256 GRF；没有测量实际寄存器分配、spill、occupancy 或指令重叠。

| mode | 实现 | workgroup 输出块 | 额外操作 |
| --- | --- | --- | --- |
| 0 | 对应现有 M4 XMX 的基本装载模式 | M4×N64 | global 装载 A/B，立即 DPAS |
| 1 | 寄存器提前装载 | M4×N64 | 两组 joint-matrix 片段，提前读下一组 |
| 4 | 寄存器复用 | M16×N64 | 每 subgroup 四个累加片段，复用两个 A、两个 B |
| 2 | 单缓冲 SLM | M16×N64 | BK64，协作装载，stride72，两个 workgroup barrier／块 |
| 3 | 双缓冲 SLM | M16×N64 | 下一块先读入 GRF，当前块计算后写另一 SLM 缓冲并同步 |
| 5 | 显式 L2 预取 | M4×N64 | 每 K64 预取下一块的 A/B，使用 SYCL experimental prefetch |

SLM mode2／3 的暂存区分别为 11,520／23,040 字节，另有 1,024 字节尾块输出空间。它们同时改变分块布局；同布局 mode4 用于区分分块复用和 SLM 暂存。mode3 是 global→GRF→SLM 的软件流水线，不是直接 global→SLM DMA；源码提前发起 load 也不能证明最终 ISA 保留了对应重叠。

测七种形状，覆盖专家 GU、Down 和一个较大矩阵。每个形状按 `0/1/0/4/0/2/0/3/0/5/0` 夹测，各阶段 3 次预热、9 次独立 kernel event 时间戳，取中位数；参照为相邻两侧 mode0 中位数的几何均值。首轮后使用同一冻结 EXE 再跑两轮，相同顺序，未做反向顺序测试。

GPU 时钟未锁定；小形状与 smoke 的两侧漂移有时很大，不把小幅正差写成稳定收益。只计 kernel 开始至结束，不含编译／JIT、传输、CPU 提交或模型工作。分配、地址与队列在每个形状内部复用；没有建立冷权重或流式权重性能结论。

| 40×2560×640 | -5.71%～+1.86% | -9.31%～+13.09% | -65.44%～-63.36% | -72.46%～-69.71% | -5.87%～-0.43% |
| 160×1280×2560 | -0.13%～+2.38% | +94.60%～+96.97% | -67.13%～-66.77% | -74.95%～-74.17% | -3.53%～+1.13% |

寄存器复用在 M160 GU、M160 Down 和 M2048 大矩阵上分别达到约 **1.95～1.97×、1.32～1.37×、2.49～2.54×**，但在 M4／M16／M40 GU 上变慢。不能直接给双专家链套统一大分块，更不能把单核倍数换算成模型 tok/s。应先记录实际专家行数分布，再在原生 FP16 双专家路径上验证按形状选择分块、数值和端到端 TTFT。

M40 GU 的 L2 预取三轮为 +1.54%～+3.54%，其中一轮参照漂移 -4.67%；大矩阵则三轮均退步约 29%。目前不据此采用小形状预取阈值。

第一轮另测较小 M8×N32 SLM 分块，单／双缓冲也都较慢，完整结果保留。这里不能据两个未胜出的实现断言 SLM 对 DG2 无用。额外 global 装载、SLM 写／读、同步、尾块空算及资源占用都可能抵消复用；没有硬件计数器或 ISA 证据去拆分各项成本。

## 与 CUDA 异步内存操作的关系

- SLM 对应 CUDA 的 shared memory，适合 workgroup 内多次复用；本项目量化 XMX 内核原本就用 SLM 暂存反量化权重，不能把它算成新增支持。
- 本机 SDK 的 `sycl/ext/intel/experimental/esimd/memory.hpp` 将 LSC gather／block load 与 prefetch 标为 DG2／PVC 可用，将 2D load 标为 PVC 专用；`sycl/ext/intel/esimd/memory.hpp` 的 2D prefetch 和 named barrier 也标为 PVC 专用。以上是本机 SDK 的接口范围，不是全部硬件能力证明。
- `group::async_work_group_copy` 接口会调用 SPIR-V `GroupAsyncCopy`；API 名称含 async，仍不足以证明 A770 使用了类似 CUDA `cp.async`／TMA 的独立搬运指令。本轮没有测试这个 API，也未测试 ESIMD LSC 内核；mode5 使用的是普通 SYCL 预取接口。
- Host↔device 的异步 copy／BCS 与计算重叠是另一层。本项目已有 copy queue；本实验没有测量或更改那条路径。

此前只改变运行时 preferred SLM 分配策略的负结果，见 `orca-l0/demo/dg2-slm-occupancy-windows-2026-11-02.json`，与本次内核分块实验分开统计。

## 正确性、证据与复现

首次四变体实验通过 144 次全输出／边界检查；六变体初次 smoke／screen 通过 224 次，两次复测再通过 392 次，共 **760 次检查**。逐次以 NaN 污染预热输出，核对非均匀二进制精确输入的 CPU FP32 参考、完整输出、输入／权重及 guards；smoke 含 M13 尾行。它验证这些样本，不代表任意浮点分布或模型质量等价。

保留两次失败编译：先是 matrix 头文件路径不符，再是 event 的 const 调用错误；成功修正另存目录。原始日志、命令、各次 GPU 时间戳、源码与 SHA-256 都在档案中。二进制仅记录哈希，不随档案分发。

可运行源码：[xmx_slm_probe.cpp](../../../sycl/orca/xmx_slm_probe.cpp)。Windows 使用相同 oneAPI、驱动和 A770，在 oneAPI／MSVC 开发终端：

```powershell
icx /std:c++20 /EHsc /MD /O2 -fsycl -fsycl-targets=spir64 sycl/orca/xmx_slm_probe.cpp -o xmx-slm.exe
$env:ONEAPI_DEVICE_SELECTOR = 'level_zero:gpu'
.\xmx-slm.exe --smoke
.\xmx-slm.exe
```

同条件可以复现检查和测量流程；未锁频，具体百分比会随系统负载及驱动变化。Linux 可使用 `icpx -std=c++20 -O2 -fsycl` 编译此独立 demo，但本轮没有 Linux 编译／GPU 数据。

本机冻结证据验收：`python -X utf8 build-orca-slm-async-20261104/publish.py --check`。
