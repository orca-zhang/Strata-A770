# A770 短工具输入超时的配置规避

2026-10-24 晚间测量，10-25 应用到本机配置。原始 258-token Anthropic 工具请求在 `--short-read 256` 下再次达到 180 秒 HTTP socket 超时；改为 `1024` 后，两个独立服务共 6/6 次完成，HTTP 完整响应中位数 **22.016 秒**，范围 **21.401～23.101 秒**。六次工具参数全文、用量和停止原因一致，均自然结束为 `tool_use`，没有执行外部工具。

这次应用的是已有参数，规避该输入进入异常慢的批量预填充路径。没有修改生产 EXE，也没有修复批量路径的根因；更长输入、图像输入和并发未验证。

## 配置与方法

硬件为 Intel Arc A770 16 GB、Xeon E5-2696 v4、256 GiB DDR3、PCIe 3.0 ×16、Windows，oneAPI 2025.3 / oneMKL 2025.3。使用原生产 `0.1.39-sycl` EXE（SHA256 `8f0d866ded297cf5a409e84cf5dd61f437c56c8a89aaeb2a85569265b6a3e122`）、IQ2_XS、FP16 KV、prefill 8192、MTP4、六槽验证窗口、prompt cache 0、PCIe 分流 0.16，专家缓存自动配置。

取得项目两个 GPU 实验锁后，按 **1024 / 256 / 1024** 启动三个全新服务。每进程先执行三次 255-token 工具请求预热，再保留三次同一短请求；之后，新阈值各测三次原始 258-token 请求，旧阈值测一次并保留超时。共 15 个成功正式请求、9 个成功预热请求和 1 个超时。每次成功请求的 cache_n 均为 0。

除阈值和私有日志路径外，三个配置与原配置相同；HTTP 监听独立的本地端口。自动专家缓存随可用显存变化，实际分别为 **6382 / 6324 / 6387 slots**，所以这不是固定缓存的严格性能 A/B/A。只报告完成时间和超时复现，不据此计算软件提速百分比。请求计时期间，测试进程和引擎在正常优先级下运行；排队等待、服务启动及关闭均不计入 HTTP 请求耗时。

原始请求与此前失败完全一致：用户内容为 `record memory locality.`，强制调用 `record`，其输入 schema 为含字符串 `value` 的对象；temperature 0、关闭 thinking、max_tokens 384、非流式。完整模板和强制工具前缀合计 258 tokens，需要预填的前 257 个位置超过旧阈值 256；源码会因此从窗口路径转向批量路径。新阈值复用现有验证窗口处理这些位置。阈值切换解释了所采用的规避方式，不证明批量路径慢的具体根因。

## 实测

表格为每进程三个正式请求的中位数。等效 prefill 使用输入 tokens / 引擎 prompt_ms，decode 使用输出 tokens / 引擎 predicted_ms；各列分别取中位数。

| 进程 | short-read | 输入 / 输出 tokens | 等效 prefill tok/s | decode tok/s | HTTP 完整响应 s | HTTP 范围 s |
| ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| 0 | 1024 | 258 / 276 | 21.63 | 27.36 | 22.076 | 21.955～23.101 |
| 1 | 256 | 258 / 未完成 | — | — | 180.035 后超时 | 单次失败 |
| 2 | 1024 | 258 / 276 | 22.18 | 27.99 | 21.577 | 21.401～22.532 |
| 新阈值合并六次 | 1024 | 258 / 276 | **22.13** | **27.49** | **22.016** | **21.401～23.101** |

原本正常的 255 / 17-token 工具对照，三个服务各三次正式请求全部完成。HTTP 中位数按进程顺序为 **12.083 / 11.763 / 11.763 秒**。本轮只预热三次，自适应缓存和 decode 计时仍在变化，不据此判断短输入吞吐回归或提升，也不与此前预热十次的 10.634 秒直接相减。

HTTP 耗时从客户端序列化并发送 JSON 开始，包含模板、分词、调度、引擎输入处理和生成、协议转换、完整响应读取与 JSON 解析；请求返回后读取 `/v1/status` 的时间不计入。非流式接口不报告首 token 延迟。旧阈值没有完成相同输出，因而没有可用的精确加速倍率，也没有 decode 提升结论。

三个服务最终退出码均为 0。旧阈值超时后通过 QUIT 关闭服务时，日志记录了 `I/O operation on closed file`；该取消/关闭错误原样保留，不将其描述为完全无错误退出。两个新阈值服务正常关闭。生产 EXE 和服务器源码的冻结哈希在测试前后保持一致。

## 应用与复核

本机生成的 `strata-iq2_xs.json` 已将 `args` 中的 `"--short-read", "256"` 改为 `"--short-read", "1024"`，服务重启后生效。该配置含本机路径，未加入版本控制；README 记录了供其他机器复现的参数。全局引擎和安装器默认值保持原值。

启动同模型、prompt cache 0、short-read 1024 的独立本地服务后，可运行：

```text
python tools/check_a770_tool.py --url http://127.0.0.1:8096
```

此检查以 60 秒 socket 超时重放原始请求，验证 258-token 用量、工具名、非空字符串参数、自然结束和关闭的提示缓存，并输出 HTTP、等效 prefill 和 decode 数据。地址使用测试服务的实际端口。

[机器可读结果、完整请求/响应、配置及哈希](short-read-fix-2026-10-24.json)。本机复核：

```text
python -X utf8 build-sycl-a770-short-read-fix-v2-20261024/publish.py --check
```

原先未取得 GPU 锁的准备目录 `build-sycl-a770-short-read-fix-20261024` 没有发送模型请求，已标记为 preparation-only。实际测量使用上述 v2 目录。此前 HTTP 事件转换优化的历史记录保持原样；其配置/README 哈希对应修复前状态，不能用修改后的活文件冒充旧快照。
