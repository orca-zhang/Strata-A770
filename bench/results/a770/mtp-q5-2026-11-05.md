# A770：Q5 MTP 草稿专家

2026-11-05，Windows，Intel Arc A770 16 GB，oneAPI 2025.3，IQ2_XS。
在当前 U4/M16 数学配置下，保持 min-p=0.5，纯 MTP 接受率从 **632/875＝72.23%**
提高到 **650/855＝76.02%**，增加 **3.79 个百分点、18 个接受 token**。
Q5 专家比默认 Q2 多占 **975 MiB**。源码提供可选路径，默认仍为 Q2。
后续按实际配置计入缓存缩减、预热后重复三次，Code2K 完整请求吞吐仅提高 **0.09%**，
Prose2K 下降 **0.64%**。本轮不支持替换当前 Q2 默认配置。

## 改动与条件

复用已有 Q5_0 native grouped expert 和 Q8_1 激活路径，没有新增 GPU kernel 或依赖。
`tools/mtp_pack.py --experts q5_0` 使用已有 gguf-py 量化器；`tools/mtp_rt.py` 写出
`experts.q5_0.bin`，gate/up/down 分段排列。SYCL/Orca 通过
`STRATA_MTP_EXPERTS=q5_0` 选择；也接受 `q2_0`、`q8_0`，保留原 Q8 环境变量兼容。
默认 Q2 的字节布局保持不变。Q5 与 Q2 的比较包含各自的激活量化和已有专家内核，
不是只隔离权重位宽的实验。

下面两个采纳率组均为三个新进程 Q2→Q5→Q2，依次运行相同的九个贪心任务。
每进程先运行 Chinese16 初始化，再各测一次；无 suffix lookup、前缀复用、分析器。
固定 `--expert-cache 5000`，三个进程均为实际 **5243 slots / 7201 MiB**；
MTP4、完整 248320 词表、window1024、四流 RMS、FP16 KV、reserve1536 MiB。
同组的 dense 权重、输出头、主模型、输入顺序和置信参数一致。
编译、转换与模型请求串行持有共享实验锁。

当前配置组使用已部署 U4/load4/M16 的对象和当前 HC256 images，仅替换 MTP Host 对象。
它保留 9402 个 U4 专家、min_rows16 等参数。Q5 在 READY 时可用显存为 2080 MiB；
这是启动读数，不是运行期间最低值。可选配置也固定 5000 cache 请求；
这些结果不能直接当作默认 5500 cache 请求配置的整机性能收益。

## 当前配置，原置信门槛

累计门槛为零，逐 token 与最后一步门槛均为 0.5。两次 Q2 的输出与接受/提议计数完全一致。

| 任务 | Q2 接受/提议 | Q5 接受/提议 |
| --- | ---: | ---: |
| Code2K | 73/90 | 79/94 |
| Prose2K | 62/96 | 63/91 |
| 中文短答 | 27/44 | 28/45 |
| 中文缓存解释 | 78/110 | 79/110 |
| 中文数据库解释 | 74/114 | 79/105 |
| 英文 TCP 解释 | 70/113 | 71/105 |
| 英文迁移计划 | 75/109 | 77/104 |
| Python 区间合并 | 85/105 | 85/105 |
| SQL 排名 | 88/94 | 89/96 |
| 汇总 | **632/875（72.23%）** | **650/855（76.02%）** |

SQL 的比例略降，Python 不变；总体改善不代表每个任务都改善。
这里没有提高置信门槛，且实际接受数增加。

同轮 decode 吞吐相对两侧基线几何均值，九项为 −0.95%～+9.08%；
两侧基线耗时漂移为 −1.70%～+0.24%。每个场景每进程只有一次保留请求，
没有充分的逐场景预热和独立重复，故不据此宣布稳定吞吐收益。

## 无置信过滤的预测检查

另一组使用冻结的非 U4 数学配置，逐 token、累计与最后一步门槛全为零；
最多三个草稿，尾部按剩余输出预算裁剪。缓存容量与上述相同。
它与当前配置组的主模型预填舍入不同，两个组之间不作直接比较。

| Q2 前 | Q5 | Q2 后 |
| ---: | ---: | ---: |
| 672/1186（56.66%） | 683/1148（59.49%） | 672/1186（56.66%） |

这一组的提高为 **2.83 个百分点**，接受数增加 11，说明收益不只来自置信过滤。
两组共 **54 次测量请求、6456 个输出 token** 与各自 Q2 参考逐 token 一致；
六次 Chinese16 初始化的完整协议也保留。范围为 21～2048 输入、最多 128 输出，
仅贪心；没有采样、8K、自动缓存或其他 GPU 的验证结论。

## 实际配置的性能对照

另测当前 `strata-iq2_xs.json` 与可选 `strata-iq2_xs-mtp-q5.json`，采用 Q2→Q5→Q2。
这次计入 Q5 的缓存代价：Q2 请求 5500 cache，实际 **5771 slots / 7922 MiB**；
Q5 请求 5000，实际 **5243 slots / 7201 MiB**，少 528 slots。
除 EXE、MTP runtime、专家选择和缓存容量外，参数与环境配置相同；
均使用当前 U4/min_rows16/M16、HC256、min-p=0.5、suffix=0。
测量前后配置、EXE、runtime、专家 profile、测量程序与公共测量工具的 SHA-256 均未变化。

每个新进程先做 Chinese16 初始化，再交替运行 Code2K、Prose2K 各四次；
第一轮预热不计成绩，其余三轮取中位数。两次 Q2 的中位数取几何均值作为基线。
每次输入 2048、输出 128 token，完整请求耗时包括预填、解码和协议交付，不含进程启动。
速度变化按基线耗时 / Q5 耗时 − 1 计算。

| 任务 | Q2 decode ms | Q5 decode ms | decode 吞吐变化 | Q2 完整请求 ms | Q5 完整请求 ms | 完整请求吞吐变化 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| Code2K | 4138.5 | 4095.2 | +1.06% | 19117.1 | 19100.1 | +0.09% |
| Prose2K | 4175.7 | 4257.0 | −1.91% | 18704.8 | 18825.0 | −0.64% |

两侧 Q2 基线的 decode 耗时漂移分别为 −0.20%、−0.56%，完整请求为 −0.68%、−0.19%；
包括预填、首 token 和交付吞吐的全部指标，绝对漂移也不超过 0.88%。
按首批交付后到末批交付测量，代码交付吞吐提高 1.32%，散文下降 1.88%。
Q2 草稿接受/提议仍为 Code2K 73/90、Prose2K 62/96；Q5 为 79/94、63/91。
24 次完整请求的 **3072 个输出 token** 全部与 Q2 逐 token 一致；
三个 Chinese16 初始化也一致，三个进程均正常退出。

本轮开始前确定的替换门槛是：两项任务的 decode 与完整请求吞吐均至少提高 1%，
两侧基线绝对漂移不超过 3%，且输出一致。**Q5 未达到门槛，保留当前 Q2。**
采纳率提高没有在这两个实际配置负载上带来足够的速度收益；最终正文保持一致，
这里不主张回答质量改善。没有单独分解专家计算和缓存缩减各自的耗时，
也不能由此推断更长输出或其他显存容量的结果。

## 使用与复算

本机可选配置：`strata-iq2_xs-mtp-q5.json`，主配置保留。
它使用独立 EXE、Q5 runtime 和上述固定缓存；启动方式沿用现有服务器：

```powershell
python sycl/serve/server_intel.py --engine strata --config strata-iq2_xs-mtp-q5.json --port 8080
```

该可选配置另做了独立启动检查：Chinese16 初始化后生成 Code2K 的完整 128 token，
输出、79/94 草稿计数及完成原因均与实验候选一致；该请求不计入上述 54 次汇总。

在其他已编译新源码的 SYCL/Orca 环境，先从已校验的 BF16 张量生成新 runtime，
将 `--mtp` 指向它，并在进程启动前设置 `STRATA_MTP_EXPERTS=q5_0`：

```text
python tools/mtp_pack.py --src <mtp-tensors-directory> --experts q5_0 --out <new-q5.gguf>
python tools/mtp_rt.py --gguf <new-q5.gguf> --out <new-runtime-directory>
```

CPU 自检覆盖 Q2/Q5/Q8 布局、输入拒绝、Q5 量化及 GGUF→runtime 实际转换。
下面的离线复算直接重放所有保存的 T/TB/DONE 协议，核对输出、计数、缓存和两侧基线：

```powershell
python tools/test_mtp_rt.py
python bench/results/a770/check_mtp_q5_20261105.py
```

[完整协议、输入、计数与源码/构建/权重哈希](mtp-q5-2026-11-05.json)。
本机重测使用 `build-mtp-quality-20261105/run.py <new-result-name> 0.5 --current`，
输出目录必须是新目录；原始日志、首次缺失 Intel LIB 路径的链接失败及修复后日志均保留。
实际配置性能对照使用 `build-mtp-quality-20261105/practical.py <new-result-name>`；
该轮的原始完整协议、全部请求计时、配置/输入/文件哈希和冻结程序存于 JSON 的 `practical` 字段，
同一个离线检查也复算三轮中位数、两侧基线和替换门槛。
