# A770：MTP 早停与同大小 Q2 激活校准

2026-11-05，Windows，Intel Arc A770 16 GB，oneAPI 2025.3，IQ2_XS。
当前 U4/min_rows16/M16、HC SG16 部署下，单独早停、激活校准和两者组合均未达到预先固定的默认替换门槛。
**用户随后选择采用组合版，现已设为本机默认，并保留原配置备份。** 这是使用偏好的选择，原测量门槛和未通过的结果保持不变。
单独校准的代码/散文完整请求吞吐名义增益为 +0.58%/+0.84%，
九场景接受率由 72.23% 到 72.81%，实际接受 token 总数仍为 632。这一轮不能证明稳定提速或最终回答质量改善。

## 当前部署的性能结果

三组独立 A/B/A 对照均使用当前 `engine/u4n16-orca-l0-m16-hc-sg16/strata.exe` 和对应 images。
A 为原 Q2、累计门槛零；B 分别只改变累计门槛、Q2 专家权重，或同时改变两者。
主模型、dense/输出头、逐 token 与最后一步门槛 0.5、MTP4、suffix0、FP16 KV、prompt cache0 均保持一致。
缓存请求 5500，实际 **5771 slots / 7922 MiB**；校准专家文件仍为 **707,788,800 字节（675 MiB）**。

每个新进程先运行 Chinese16 初始化，再交替运行 Code2K、Prose2K 各四次；
首轮预热，后三轮各取中位数，两侧 A 的中位数取几何均值。
每请求 2048 输入、完整 128 输出 token。每项试验保留全部 24 请求、3072 输出 token 及初始化记录。
完整请求从发送 GEN 到接收 DONE，包括预填、解码与协议交付，不含进程启动。
吞吐变化按基线耗时 / 候选耗时 − 1 计算；不同试验使用各自两侧基线。

预先固定的默认替换门槛：**代码与散文的 decode、完整请求吞吐均至少 +1%，
两侧基线绝对漂移不超过 3%，完整输出一致。** 三项均未过门槛；没有放宽门槛或重跑筛选较好样本。

## 采纳率与完整输出

额外通过 `serve.server.engine_args`、`child_env`、`StrataEngine` 的真实引擎适配层检查四种配置。
每进程先 Chinese16 初始化，然后运行相同九个场景；这部分检查不作为性能成绩，未经过 HTTP 层。
四种配置共 36 次请求、4304 输出 token，均与历史原 Q2 完整输出一致，四个进程正常退出。
原 Q2 的全部接受/提议计数也复现；早停可选配置实际启用了 draft/verify 累计门槛。

最终正文保持一致，这些实验没有给出回答质量提高的结论。

## 激活校准的实现与数据

`tools/mtp_pack.py --q2-imatrix <moments.npz>` 新增可选离线量化路径，不新增依赖。
NPZ 中 `gate_up_proj` 与 `down_proj` 为逐专家输入通道二阶矩；本模型尺寸分别为 512×2560、512×640，
必须有限且非负。格式仍为 Q2_0，18 字节/64 权重；不传该参数时保留原量化字节。
候选以原 Q2 为种子，搜索正负 FP16 缩放并做四次局部加权拟合，只保留实际存储缩放下的加权误差改善。
全零 importance 保留原字节。GGUF metadata 记录二阶矩文件 SHA 与量化方式。

独立采集 EXE 只重编译 MTP Host 对象，读取每次已完成草稿的真实输入、专家路由和 SwiGLU 中间激活。
12 条独立中英文/代码提示各生成 96 token，未与九项评测输入完全重复。
Chinese16 初始化、Code2K/Prose2K 两项完整输出审计均排除在二阶矩之外。
排除前 10,129,464 trace 字节后，保留 **1056 次草稿、10,560 次专家路由观察**。

**324/512** 个专家至少出现八次，覆盖 **94.63%** 的路由观察；42 个完全未出现。
少于八次的 188 个专家逐块核对为原版字节；其余专家的二阶矩以八个伪观察收缩。
对角二阶矩是此实现的简化，未使用全 Hessian；采集含读回开销，只用于量化校准。
专家文件 SHA-256：`801ed8890d2b38163902f9403b033f06840fc50b0a5e76267213015b357a8f94`。

CPU 检查覆盖默认固定字节、加权误差、负缩放、零权重回退、非法输入，以及真实 NPZ→GGUF 打包；
原 Q2/Q5/Q8 布局和 Q5 GGUF→runtime 检查继续通过。
另与提交版原 Q2 函数比较五种尺度、81920 个随机权重，默认字节一致。
这些 CPU 检查验证实现，不用于证明模型提速。

## 本机采用配置

主配置 `strata-iq2_xs.json` 已采用校准 Q2＋累计门槛 0.5，沿用当前 HC SG16 引擎、5500 缓存请求和原有启动脚本。
它与独立配置 `strata-iq2_xs-mtp-combined.json` 完全一致，下次启动服务时生效。
原配置备份为 `strata-iq2_xs-before-mtp-combined-20261105.json`；回退时将其复制回 `strata-iq2_xs.json` 后重启服务。
`strata-iq2_xs-mtp-early.json` 为早停实验配置，累计门槛 0.5，独立日志，已通过上述九场景适配层检查。
`strata-iq2_xs-mtp-calibrated.json` 使用稳定目录
`G:/GitHub/Strata-data/mtp/rt-q2-activation-calibrated-20261105`，三个 runtime 文件硬链接到已测权重，独立日志。
迁移后另做 Chinese16 初始化及 Code2K/Prose2K 完整 128 token 生成；输出、完成原因和 75/92、62/91 草稿计数均复现，进程正常退出。
文件 SHA-256 前后相同，主配置未改变；记录位于 JSON 的 `optional_calibrated_profile` 字段，不计入上述性能或九场景汇总。
组合版复用同一稳定权重目录和独立日志，另做了 Chinese16 初始化及 Code2K/Prose2K 完整输出检查。
输出、完成原因及 73/89、59/80 草稿计数与原组合实验一致，缓存仍为实际 5771 slots，进程正常退出。
检查后备份原配置并原子替换主配置；部署配置、哈希和采用原因位于 JSON 的 `optional_combined_profile` 字段。
此检查不计入上面的性能或九场景汇总。单独校准与单独早停仍可通过各自配置使用。

```powershell
python sycl/serve/server_intel.py --engine strata --config strata-iq2_xs-mtp-combined.json --port 8080
```

其他机器可使用已有 BF16 张量和对应二阶矩生成独立 runtime，将配置的 `--mtp` 指向新目录：

```text
python tools/mtp_pack.py --src <mtp-source-directory> --experts q2_0 --q2-imatrix <moments.npz> --out <new-q2.gguf>
python tools/mtp_rt.py --gguf <new-q2.gguf> --out <new-runtime-directory>
```

`mtp-source-directory` 必须含 `mtp-manifest.json`；不需要设置新的运行时专家格式变量。
本机校准程序、二阶矩和冻结采集源码位于 `build-mtp-quality-20261105/activation-calibration-r2/`。
首次采集在编译前因链接工作目录错误退出，失败记录保留在 `activation-calibration/`；第二次使用已验证的链接目录。

## 历史结果与复核

较早 HC256 引擎的同方法早停对照也未过门槛：Code2K decode +0.45%、完整请求 −0.71%；
Prose2K decode +1.10%、完整请求 −0.11%。该记录保留在 JSON 的首项 `experiments`，不代表当前 HC SG16 的速度。
另一项 [Q5 草稿专家实验](mtp-q5-2026-11-05.md) 提高采纳率但多占 975 MiB，计入缓存缩减后也未过默认门槛；
它使用较早引擎，不能直接与本表横向比较。

```powershell
python -X utf8 tools/test_mtp_rt.py
python -X utf8 bench/results/a770/check_mtp_q2_optimization_20261105.py
python -X utf8 build-mtp-quality-20261105/calibrate_q2.py selfcheck
```

[完整输入、配置、协议、计数、冻结测量程序与文件哈希](mtp-q2-optimization-2026-11-05.json)。

`weighted.py <new-result-name>`（组合加 `--early`）；它们要求原 Q2、累计门槛零的基线配置。
