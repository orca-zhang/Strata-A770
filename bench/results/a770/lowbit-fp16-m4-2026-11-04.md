# A770 FP16 M4 repair and low-bit model check — 2026-11-04

Measured on Intel Arc A770 16 GB; driver 32.0.101.9034; Xeon E5-2696 v4; Windows; oneAPI 2025.3. Model results use the matched legacy SYCL engine. The executable remains isolated; production executable/configuration were not replaced. This follows the [queue-ownership crash repair](lowbit-crash-fix-2026-11-04.md).

The frozen FP16 expert fixture (T703, N1280, K2560) repeatedly produced nonfinite and wrong finite outputs with M8 matrix products. Device input/weight bytes remained unchanged. Two M4 accumulators now share each B load inside the original eight-row output tile. The current-source dispatch applies this workaround only to A770 FP16; BF16 keeps M8 shapes and its existing special dispatch. Eight-row padding and tail handling remain valid. The physical driver/hardware cause is not established, and no final ISA dump was used to prove the emitted instruction sequence.

Every candidate submission checks the complete output against independently recomputed CPU64 error bounds and checks guards. Plain M4 passed 147,456 calls; paired M4 passed 131,072. All six M8 controls failed. This is a measured workaround for these A770 cohorts, not proof of universal numerical reliability.

A hot-resident component comparison uses the same fixture, four ABBA blocks, 64 warmups per phase and 31 retained profiling-event samples per phase. All 496 retained outputs and guards pass; operands remain unchanged. Paired M4 improves throughput over plain M4 by 38.64% to 38.96%. This is not a whole-model speedup.

The isolated model build passes 56 exact CPU-reference cases covering FP16/BF16, tails, BF16 strides and input/output/workspace guards. The actual current checkout passes the same check separately. All four quality processes complete, and native/U4/U2 raw score TSVs are byte-identical to previously healthy M8 runs.

Performance uses native / U4 N16 / U2 Down / native, with the same corrected paired-M4 GEMM in every process. Each process runs Short23→16, then three interleaved Code/Prose cycles (2048→128). The first long cycle is discarded, and displayed durations are medians of two retained requests. Native controls use their geometric mean. Prompt reuse, inner profiling, timing flags and telemetry are disabled; compilation and all GPU work use the shared experiment lock. Full outputs are stable within each arm, and native controls match. Together, quality and performance complete 32 long requests across eight processes without a crash.

Positive percentages mean throughput increases. Request time is host GEN→DONE wall time, excluding startup, not an HTTP benchmark. Prefill and request control drift must each stay within 3%. These are small-cohort observations without a reverse-order confirmation. Decode arithmetic is unchanged; token/routing/speculative-acceptance differences mean decode rates cannot establish GEMV speedup. U2 replaces raw-Q2 Down only, with per-call group32 S8 packing included; U4 uses original BF16-derived weight assets and two residual S4 activation planes. Offline U4 preparation is excluded.

The prior FP32 widening workaround was rejected after an approximately 200-second 2K request. Plain M4 quality passed but suggested a performance cost; it is retained alongside the paired implementation. The paired component benchmark children exited 0, but its wrapper exited 1 when Windows temporarily blocked lock deletion. That cleanup failure is retained separately. Lock cleanup now retries PermissionError and rechecks ownership; a CPU-only regression verifies retry and foreign-owner preservation. At continuation the stale lock was already absent, so no lock was deleted or process terminated.
