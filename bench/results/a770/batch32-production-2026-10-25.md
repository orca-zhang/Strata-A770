# A770：专家提交间隔 8 → 32，正确性失败，未采用

候选仅将生产 prefill 的专家等待间隔从 8 扩至 32，沿用 HC inject XMX、FP16/BF16 输入、FP32 累加及 32 MiB 工作区。**2K HTTP 预热出现错误输出，未进入候选正式计时，生产保持 8 专家版。没有确认新的 HTTP、等效 prefill 或 decode 收益。**

测试机为 Intel Arc A770 16 GB、Xeon E5-2696 v4、256 GiB DDR3、PCIe 3.0 x16、Windows，DPC++ 2025.3.2 / oneMKL 2025.3。IQ2_XS，实际专家缓存固定 5771 slots / 7.74 GiB，FP16 KV、MTP4、完整草稿词表、short-read 1024、关闭提示缓存。服务使用相同 Python API；共享 GPU 锁覆盖编译和测量，模型运行时为 Normal 优先级。

## 原始 HTTP 实验

测前固定 A1（生产 8）/ B（候选 32）/ A2（生产 8）。各进程先请求 tool255 三次，再依次预热 tool258、1K、2K；之后原计划保留三轮 1K、2K、tool258。不重试，不替换低值或失败样本。

| 阶段 | 已完成请求 | 正确请求 | 结果 |
| --- | ---: | ---: | --- |
| A1，生产 8 | 15 | 15 | 预热和正式请求均通过 |
| B，候选 32 | 6 | 5 | 第六次，即 2K 预热失败 |
| A2 / 自动缓存兼容检查 | 0 | 0 | 未运行 |

失败请求输入 2069 tokens，预期完整 JSON / end_turn / 25 个输出 tokens；实际返回连续 128 个感叹号并以 max_tokens 结束。引擎未报 GPU 异常，两个私有服务均正常退出。该请求的原始 prompt / predicted 计时为 21504.5 / 4041.6 ms，处理的是错误输出，不能用来计算有效吞吐或加速。

独立专家链检查通过 **464 项**，覆盖完整 GU/H/Y、保护区、工作区边界、混合形状及 1/8/32 专家等待间隔。其双解量化缓冲和补齐工作区复用发生在同一 in-order 队列，未覆盖完整模型的跨队列暂存和主机缓冲生命周期。算子检查通过不能替代 HTTP 正确性。

## 另行正确性定位

使用相同工具链和参数重编译原生产 8 专家 prefill，复用其余 HC 生产对象；随后将新编译 8 专家和原失败 32 专家 EXE 分别放入全新服务，重放上述六次预热请求。对照源文件逐字节等于接受过的 8 专家源码；编译头文件与候选一致。重放仅检查正确性，完整响应须等于原 A1，不计入原性能实验，不允许据此部署。

| 独立重放 | 请求 | 与原 A1 完整响应一致 | 服务退出码 |
| --- | ---: | ---: | ---: |
| 新编译 8 专家控制组 | 6 | 6 | 0 |
| 原失败 32 专家 EXE | 6 | 6 | 0 |

本次 12 次重放全部通过，**未复现原始 2K 异常，根因仍未确定**。这些结果不能将原失败归因于重编译、扩大等待间隔、跨队列复用或已知 oneMKL 布局问题，也不能证明 32 专家路径稳定。保留首次失败，候选仍未采用；本次正确性重放不计算 prefill / decode 收益。

原实验与定位实验使用不同目录，保留完整失败响应、服务退出码、配置快照和文件哈希。[精简数据与定位结果](batch32-production-2026-10-25/results.json)不包含本机绝对路径或原始响应。
