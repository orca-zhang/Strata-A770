# 工具调用参数游标（2026-10-24）

本轮只优化 `serve/frontend.py` 的 `parse_tool_call`：在原字符串上推进位置，复用已找到的分隔符位置，减少参数头和剩余正文的切片及重复查找。参数值、schema 类型转换、重复参数后值覆盖前值、未闭合输入及异常行为保持原有语义；新增一个小回归测试。没有新增正则、依赖或 SIMD 代码，现有可选原生扫描器继续使用。

收益集中在参数较多的调用。两轮完整 CPU 解析计时中，100 参数耗时下降约 **3.5%～4.8%**；1,000 参数整段输入下降 **8.1%～11.4%**，8 字符分块下降 **6.4%～7.0%**。这是合成压力输入，不能据此推断真实调用中多参数场景的占比。

Windows 10 19045、Xeon E5-2696 v4、CPython 3.11.9 x64，固定逻辑 CPU 42。基线已包含[上一轮参数增量扫描与字符串编码优化](tool-parser-2026-10-24.md)，两版使用同一个未修改的原生扩展。计时包括创建解析器、全部 feed、收集事件与 finish；分块构造和正确性断言在计时外。每轮交错执行 7 组 A/B/A，B 中位数对比两个 A 中位数的几何平均；A 漂移绝对值超过 3% 弃用。最终两轮全部 40 个结果通过此漂移规则；该规则不等于置信区间。表中负值表示耗时下降。

普通文本没有明确收益，部分控制项仍小幅变慢：未完成长数组两轮为 +0.82% / +1.56%，整段长数组第二轮为 +2.19%。不能声称全面提速。本轮只测了 CPU 解析，没有测模型 prefill、decode 或 HTTP 端到端吞吐，README 的模型吞吐数据未调整。

曾尝试在 `OutputParser.feed` 中复用流式函数名；该组合版本的逐字符数组两轮慢 +2.58% / +2.38%，因此撤回这个额外分支。游标单独保留后，隔离轮为 −0.21%，最终两轮为 −2.49% / +0.29%，没有复现连续约 2.5% 的退化。原型和撤回版本记录保存在 `build-sycl-a770-call-cursor-20261024/`，最终采用版本保存在 `build-sycl-a770-call-cursor-final-20261024/`，没有覆盖旧记录。

游标只减少复制次数；`param_end` 仍需要一个剩余字符串切片，因此多参数情况下仍有 O(n²) 复制上限，未宣称线性复杂度。源码已用 `ponytail:` 注释记录这个限制和支持起始偏移的后续方向。本轮采用最小改动，没有扩展原生接口。

原生路径 95 项通过；强制 Python 回退后 92 项通过、3 项原生专项跳过，覆盖解析器及相关 OpenAI、Anthropic、Responses、MCP 行为。新增测试覆盖 Unicode 空白、字符串 `001`、重复参数、值中的文字标签、引号、反斜杠、中文、非 BMP 字符、未闭合值和损坏的头部。12,432 组流式差分（原生／回退各 6,216）逐次 feed 及 finish 的事件与状态一致；另有 2,000 组直接解析差分，其中 966 个预期损坏输入的异常类型和消息也一致。本轮没有重跑全量服务端套件。

最终目录保留修改前后源码、原始样本、日志及 SHA-256。[机器可读记录](tool-call-cursor-2026-10-24.json)包含全部最终结果和撤回实验位置。配置、生产引擎 EXE 及原生扫描器的哈希未变；证据检查针对冻结的测试源码，`--live` 额外核对本轮修改的两个当前文件。
