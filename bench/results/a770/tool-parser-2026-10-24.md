# 工具参数增量解析与字符串编码（2026-10-24）

本轮只改 `serve/frontend.py` 的五个调用位置并增加一个标准库导入：

- 非字符串参数等待结束时，如果新增文本没有 `>` 或 `=`，跳过不会产生新事件的 `_scan()`，避免重复截取和扫描整个累积值。完整的 `</parameter>`、后续 `<parameter=` 或 `</function>` 至少需要新到达其中一个字符；`=` 单独到达也必须立即处理。
- 参数名、字符串值片段和已知为字符串的未完成参数尾部，直接调用 `json.encoder.encode_basestring_ascii`。它是 CPython `JSONEncoder.encode` 在 `ensure_ascii=True` 时使用的同一个原生函数，省去通用 `json.dumps` 的分派。对象和数组继续走原来的 JSON 编码路径。

参考了 [json-iterator v1.1.12 的 `WriteString`](https://github.com/json-iterator/go/blob/v1.1.12/stream_str.go#L311) 的字符串专用路径，以及 [Sonic v1.15.4 的 `quote`](https://github.com/bytedance/sonic/blob/v1.15.4/native/quote.c#L3) 中扫描时拷贝普通文本、从已处理位置继续的做法。适配到这里的是减少无效扫描、已知类型直接进入原生字符串编码函数；本轮没有重写转义器，也没有新增 SIMD 实现。既有 SIMD 标签检查继续使用，没有在 Python 层新增逐字符预检、匹配缓存或依赖。

源码通过 Go 国内代理取得，Sonic 的版本元数据为 v1.15.4（2026-09-10）；json-iterator 使用固定版本 v1.1.12。模块 ZIP、实际阅读的文件、来源 URL 和 SHA-256 保存在 `build-sycl-a770-raw-scan-20261024/references/`。此前 GitHub 和 Go 官方代理的 TLS 失败记录也保留在该目录。

Windows 10 19045、Xeon E5-2696 v4、CPython 3.11.9 x64，固定逻辑 CPU 42。基线是本轮两项修改之前的完整冻结模块，已包含上一轮推理工具调用的扫描优化。两版复用同一个未修改的可选原生扩展；本次 CPython 字符串编码函数来自 `_json`。测量包括解析器创建、全部增量 feed、事件收集与 finish，分块构造和正确性断言不计时；使用合成文本及本地工具模式，没有执行外部工具。
