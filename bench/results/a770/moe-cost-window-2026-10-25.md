# MoE 成本窗口：2K 图执行验证（2026-10-25）

**成本窗口未采用。** 两轮相邻对照中，Code2K 吞吐下降 **7.826% / 3.568%**，Prose2K 下降 **3.941% / 3.149%**；相邻基线耗时漂移绝对值最大 **0.492%**，均满足预设漂移门槛。全部 40 次 2K 请求生成完整 128 token，共 **5120 个输出 token** 逐个等于冻结参考。本轮未修改生产 EXE、配置或默认开关。

## 平台与范围

Intel Arc A770 16 GB、Xeon E5-2696 v4、256 GiB RAM，沿用文档中的 PCIe 3.0 x16 平台。当前 CIM 核对的显卡驱动为 32.0.101.9034。DPC++ / oneMKL 2025.3，Level Zero，精确浮点选项。

使用已有 `native-xmx-20261024/integration` 冻结图引擎及其 128 MiB 预填工作区。IQ2_XS 模型、FP16 KV、完整 248320 行草稿与目标词表；MTP4、逐步置信度门槛 0.5，预填和上下文上限 8192，prompt-cache 0。请求 expert-cache 5500，五个进程都必须核对实际 **5771 槽**。主机镜像、缓存适应及默认 suffix lookup 保留。

二进制核对发现，当前生产 EXE 与上述冻结 EXE 都没有成本窗口开关。隔离构建从冻结主程序接入当前源码已有的 `choose_mtp`、成本开关及末轮成本观测过滤，配套复制已有 `DraftPolicy` 实现、头文件和检查；其他引擎、内核和预填对象保持冻结。同一重编译 EXE 用开关 0 / 1 对照，只归因这一开关差异。

## 固定方法

执行顺序为 **A1 / B1 / A2 / B2 / A3**，每组使用新进程；A 关闭成本窗口，B 启用。共享 GPU／编译锁串行运行，关闭 profiling 与阶段计时。每个进程先运行 Short16 初始化，再各预热一次 Code2K、Prose2K，随后交错运行三轮保留请求。两种输入均为原始 2048 个 token，每次生成完整 128 个 greedy token；保留预热、全部样本、原始协议、错误日志和文件 SHA256。

两轮 B 在两种输入上都必须满足吞吐提高至少 1%、相邻基线耗时漂移绝对值不超过 3%，且全部输出等于既有冻结参考，才达到本轮保留门槛。控制组也须逐 token 等于参考。该规则在编译和计时前写入 `protocol.json`。
