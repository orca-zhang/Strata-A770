# A770：区分 Host、Device、Shared 内存池（2026-10-24）

独立确认未发现比三类都扩池更快的稳定配置。仅把 Shared RW 可池化上限提高到 128 MiB，可以保留大矩阵 GEMM 的性能；初筛中约 1%～2.5% 的额外收益没有稳定复现。生产配置未改，本轮没有整模型 IQ2/Q2 性能结论。

硬件：Arc A770 16 GB、Xeon E5-2696 v4、Windows、PCIe 3.0 ×16；驱动 32.0.101.9034、DPC++ 2025.3.2、oneMKL 2025.3。没有 PCIe 4.0 数据。

沿用[上一轮](dense-pool-2026-10-24.md)的两个独立测试 EXE，只改变 `UR_L0_USM_ALLOCATOR`。输入为生成的 FP16，输出保持 FP32；不包含模型权重加载、解量化、调用者传输和生成。这里比较的基线是三类都扩到 128 MiB，不是原来三类都为 64 MiB 的配置。

| 配置 | Host 上限 MiB | Device 上限 MiB | Shared RW 上限 MiB |
| --- | ---: | ---: | ---: |
| all128，基线 | 128 | 128 | 128 |
| host128 | 128 | 64 | 64 |
| device128 | 64 | 128 | 64 |
| shared128 | 64 | 64 | 128 |

四种配置总池预算均为 512 MiB，capacity 均为 8，slab 均为 64 KiB。独立运行库跟踪验证实际解析值，不计入性能测试。Shared RO 保留运行库默认值。仅 Shared 扩池的完整设置为：

```text
UR_L0_USM_ALLOCATOR=1;512M;host:64M,8,64K;device:64M,8,64K;shared:128M,8,64K
```

初筛按 all128/host128/all128/shared128/all128/device128/all128 运行。host128 在 QKV、Q 的四种形状上吞吐下降 7.75%～10.74%，device128 下降 6.81%～12.24%；这些项目的最大基线漂移为 2.21%。Shared128 对应变化为 +0.17%～+2.50%，因此追加独立确认。
