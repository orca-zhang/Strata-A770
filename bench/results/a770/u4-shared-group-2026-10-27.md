# A770：专家分组、共享激活打包与排序

机器：A770 16 GiB、E5-2696 v4、256 GiB RAM、PCIe 3.0 x16、Windows、oneAPI 2025.3。2026-10-28 的 host-prefetch 私有候选已通过冻结质量门槛和两轮完整请求的记录值门槛：prefill 约 +14～15%，完整请求约 +10～13%。Prose 独立确认的完整请求仅 +10.00064555%，过线余量小于计时量化误差，不能承诺稳定高于 +10%；总体 PPL +0.64561% 也不属于用户定义的 0.2% 噪音。详见文末最终审计，尚未采用到生产。

用户新增判读口径：低于 0.2% 的精度或速度下降记为噪音，保留原始值；恰好 0.2% 不属于这个区间。按此口径，既有总体 PPL +0.19054% 记为噪音，单案例 code 的 +1.01330% 仍需单列。显著提速继续由两案例的完整请求及独立确认验证，prefill 与总吞吐都要求至少 +10%。

隔离原型支持最多 8 个专家一组。每个专家保留自己的权重、实际行数和原始输出槽，不删除路由选中的专家。当前内核按各专家的实际行数铺平，并非按组内最大行数补齐；仅改变专家顺序不会减少乘加量。

新的共享路径每层将原始 FP16 token 激活打包成两张 S4 残差平面一次。GU 通过路由的原始 token 索引读取这些打包数据，各专家复用同一份激活；随后复用原有 fused SwiGLU→FP16→S4 与 down。权重仍为原始 BF16 直接转换的单 U4 平面。两组 8 槽权重缓冲保留复制/计算重叠，槽位消费完成用计算队列 barrier 标记。decode 未改变。

在 A770 上，六份真实 FP16 捕获加两个裁剪副本、64 次专家调用已通过完整 GU/down 逐位比较。测试包含反向的非连续 token 索引、两个专家共享原 token 存储、独立尾行补齐、输出间隙与 guard、双缓冲复用、非有限输入拒绝及恢复。使用原逐专家 U4 链作为参考。此检查证明组件正确性，不是整模型质量或速度验收。

排序提供 ID、行数、累计激活权重三种实验选项。累计权重是一个专家在所有已选择路由中的权重之和，只影响执行优先级。行数与分数相同则按 ID 打破平局，所有专家继续参与最终原顺序归并。score 模式在已有 router 等待前读回权重，再按专家求和，没有增加显式 host wait。实际 GPU 时间仍需测量。原路由采样只有计数，没有权重，不能用于宣称 score 排序收益。

同一离线路由按行数降序后，Code/Prose 的组数分别为 290/289，比 ID 顺序各多一组；实际补齐计算行数相同。因此不默认认定按行数排序会更快。
