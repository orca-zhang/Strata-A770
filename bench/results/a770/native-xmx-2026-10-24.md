# A770：FP16 / BF16 直读 XMX，FP32 累加

本轮将已有 16 位输入直接送入 XMX，省去完整权重转成 FP32 的步骤。累加器和输出仍为 FP32；BF16 使用原生 BF16 输入。测量平台为 A770 16 GB、E5-2696 v4、PCIe 3.0 x16、Windows、驱动 32.0.101.9034、DPC++ 2025.3.2、oneMKL 2025.3。

已接入 SYCL 源码，默认关闭。最终同一 EXE 的 IQ2_XS 强制批量 Code256 对照中，预填吞吐为 FP32 路径的 **7.424×**，预填与解码合计为 **6.880×**；三次 32 个输出 token 一致。该结果仅覆盖这一个提示和测试设置，生产 EXE 与配置未替换。

## 实现与回退

复用 SYCL 已有的 `joint_matrix`，不增加依赖。SG8，每工作组八个子组，8×8×16 分块：激活按行读取，权重用原存储的列主序视图读取，直接写 FP32 输出。

`STRATA_PREFILL_NATIVE_XMX=1` 启用，默认关闭。分派在原生半精度和 FP32 widening 路径之前，要求：

- 驱动报告支持对应 FP16/BF16 输入、FP32 累加及输出的矩阵组合；最终接入还检查 SG8 支持。
- 有序队列、`beta=0`、连续输出，N 为 8 的倍数、K 为 16 的倍数。
- 不足八行或输入步长不能直接读取时，用已有工作区补齐激活；容量不足则回退。

末尾不足八行的输出通过局部暂存和边界判断写回。其他形状、累加到已有输出、带输出步长和不支持的设备沿用原路径。保持调用完成时输出可用的行为。

量化权重仍由原来的解量化代码生成 FP16，再调用本路径。本轮没有将 IQ2/Q2 解量化融合进 XMX，也没有改变解码用的 MMVQ 内核。

## 两组独立算子对照

每组五个独立进程，顺序 A/B/A/B/A；每进程 16 个用例，共 80 个。每例检查完整输出后预热三次，再取七批、每批三次完整引擎调用的中位数。两侧均使用 128 MiB 外部工作区及相同 all128 分配池；分析日志关闭。

预先规定：剔除不支持 XMX 的 N17 微型形状；相邻基线漂移绝对值须不超过 3%；每个 dtype、每轮至少三个合格形状，吞吐增量中位数至少 3%，任何合格形状不得回退超过 3%。全部配对数值与排除项保存在[数值摘要](native-xmx-summary-2026-10-24.json)。

| 对照 | 输入 | 第一轮合格数／中位吞吐倍率 | 第二轮合格数／中位吞吐倍率 |
| --- | --- | ---: | ---: |
| 完整 FP32 widening GEMM | FP16 | 7／9.316× | 7／9.461× |
| 完整 FP32 widening GEMM | BF16 | 6／9.385× | 7／8.371× |
| 原生半精度分段 K1024 | FP16 | 6／5.923× | 6／5.789× |
| 原生半精度分段 K1024，含 BF16→FP16 | BF16 | 6／6.161× | 4／2.514× |

第二组的所有合格配对至少为 **2.404×**。该组预先规定先选择所有形状、失败才尝试 T≤64；所有形状模式通过，未增加 T 上限。部分小形状基线漂移超限，不能将表中中位数理解为所有用例稳定获得同样倍率。倍率属于完整 GEMM 调用，不能外推为整模型倍率。

这两组冻结构建的 FP32 回退保留了较早的两处主机等待。实验开始时核对过当前源码仅移除了这两处等待；最终接入与下方同一 EXE 的模型对照保留该已有改动。

## IQ2_XS 整模型对照

使用同一 Code256 输入、greedy、最多 32 个输出 token、INT8 KV、context 8192、prefill chunk 256、prompt cache 0、`--short-read 0` 强制批量预填。三次独立冷进程 A/B/A，实际专家缓存固定为 4,191 slots／5,760 MiB，两侧均为已核对来源的 128 MiB 预填工作区；共享 GPU 锁与进程检查通过，计时关闭分析器。冷进程保留驱动已有缓存，没有清空磁盘 JIT 缓存。

模型使用 streamed experts、prefill borrow、PCIe share 0.16、adaptive swaps 32、MTP window 1024；请求 spec4，INFO 报告窗口 6／mtp_max 4。两侧采用相同 all128 分配池。普通配置可能用短输入逐窗口读取，该路径不由本次批量 GEMM 测量覆盖。

先比较冻结的 K1024 分段版本和新 XMX 版本，耗时单位为毫秒：

| 指标 | K1024 A | XMX B | K1024 A | B 相对两侧基线吞吐倍率 | 基线耗时漂移 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 预填 | 85134.1 | 24798.9 | 85712.4 | **3.445×** | 0.68% |
| 解码 32 tokens | 1521.4 | 12232.4 | 1607.1 | 0.128× | 5.63% |
| 引擎预填＋解码 | 86655.5 | 37031.3 | 87319.5 | **2.349×** | 0.77% |

吞吐倍率用两侧耗时的几何平均除以候选耗时。三次 32 个输出 ID 全部一致。候选的首次解码明显变慢，原因未定位，且解码基线漂移超过 3%；这轮不支持解码提速结论。合计计时不含模型加载和 API 排队。

最终版本使用同一 EXE、两侧关闭半精度分段，只切换 XMX；保留当前源码已有的等待移除。复测结果如下，单位仍为毫秒：

| 指标 | FP32 A | XMX B | FP32 A | B 相对两侧基线吞吐倍率 | 基线耗时漂移 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 预填 | 125181.7 | 16868.8 | 125287.6 | **7.424×** | 0.085% |
| 解码 32 tokens | 1572.7 | 1562.1 | 1548.9 | 0.999× | −1.51% |
| 引擎预填＋解码 | 126754.4 | 18430.9 | 126836.5 | **6.880×** | 0.065% |

三次 32 个输出 ID 全部一致。预先规定的预填吞吐增量至少 3%、基线耗时漂移不超过 3% 的门槛通过。前轮的首次解码明显变慢未在同一 EXE 复测中重现；本轮解码基本相当，也不将短前缀的结果解释为持续生成提速。两轮是独立实验，不能将倍率相乘。

引擎通过隔离重链构建：替换 GEMM、核对一致的 128 MiB prefill 对象，其余引擎依赖在每组对照中固定。这不是整个脏工作区的全量构建，也不是与已安装生产 EXE 的对照。更早的半精度模型记录使用了 32 MiB prefill 对象；本次两侧均另换成核验过的 128 MiB 对象，不能跨记录直接相减。

## 数值检查

冻结候选通过 1,825 项数值与布局检查：普通 1,015 项，以及大型普通分配、共享 arena、超过 4 GiB 偏移各 270 项；两侧另通过共 40 项范围及重新绑定检查。

随机输入为约 [-1,1]，覆盖 FP16/BF16、不同输入和输出步长、输出偏移、beta 0/1/−0.25、工作区使用链及边界保护：

| 指标 | 最大绝对差／误差 |
| --- | ---: |
| 新路径与原 FP32 路径完整输出比较 | 0.000869750977 |
| 新路径相对 CPU FP64 抽样参考 | 0.000427796912845 |
| 原路径相对相同 CPU FP64 抽样参考 | 0.0000853492529131 |

每例八个 CPU FP64 样本。XMX 形状的检查界限为 0.005；回退形状保持逐位比较，非有限结果和越界仍失败。0.005 是这组有界输入的检查门槛，不是任意模型数值范围上的误差保证。

算子计时使用可精确表示的二进制分数输入。新路径的完整输出与 FP32 基线及 CPU 全量参考哈希一致、最大误差与 RMS 均为零。随机数据的归约顺序有差异，不能称为普遍逐位一致。

最终合并版本保留已有的两处等待移除，并增加 SG8 能力检查。该版本另通过 **4,012 项检查**：关闭 XMX 的 1,015 项逐位对照、开启后的 1,015 项数值／布局对照、1,692 项边界／工作区检查、270 项超过 4 GiB 偏移检查，以及 20 项范围／重新绑定检查。诊断日志确认 FP16 和原生 BF16 都实际分派到新内核。

新增边界覆盖 T=1/7/8/9/15/16/17、N=8/16/24/64/72、K=16/32/48/64/80、BF16 的 K+8/K+13 步长、输出偏移、beta、空／短缺／恰好／多一字节工作区及重新绑定。边界前后保护值均保留。

## 使用与复查

用包含本次改动的 SYCL 构建，设置 `STRATA_PREFILL_NATIVE_XMX=1`；删除该变量或设为 `0` 恢复原路径。开关在进程内缓存，切换后需重新启动引擎。`STRATA_PREFILL_XMX_PROFILE=1` 可打印实际分派的形状；计时保持关闭。

复用 [gemm_parity.cpp](../../../sycl/src/prefill/gemm_parity.cpp) 的 `--xmx` 模式，随机 XMX 结果按 0.005 检查，并额外对 CPU FP64 抽样；不带该模式仍要求逐位相同。`--xmx --boundary` 增加块边界和工作区容量检查。CMake 注册了 `prefill_xmx_gemm_check` 和 `prefill_xmx_boundary_check`；已有精确对照及半精度检查明确关闭 XMX，避免继承外部开关。

完成 SYCL 构建后，可运行：

```text
ctest --test-dir <SYCL-build> -R "^prefill_(gemm_parity|half_gemm_check|xmx_.*)$" --output-on-failure
```

本轮通过隔离构建运行上述检查逻辑及额外高地址检查；未声称对整个工作区完成全量构建。测试 EXE、编译对象和最终源码的 SHA256 见数值摘要，原始实验文件保留不变。

## 证据范围

- 模型测试为 IQ2_XS pack，其中专家包含 IQ2_S / IQ2_XXS / IQ1_M，down 为 Q2_0；没有独立 Q2 模型测试。
- 只有 PCIe 3.0 的测量；没有 PCIe 4.0 结果。
- 算子测试支持此路径的速度与数值行为；32 token 前缀一致也不能替代长文本、编码正确性或通用质量评估。
- 原始配置、请求、token IDs、环境快照、构建命令和日志保留本机；公开摘要仅保留数值、验证范围及哈希。
