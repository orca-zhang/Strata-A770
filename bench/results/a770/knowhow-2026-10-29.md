# A770 decode：当前能落地的优化经验

2026-10-29，Windows、A770 16GB、PCIe 3.0、驱动32.0.101.9034、oneAPI 2025.3。
模型为本机 IQ2_XS pack；GU 实际有34层 IQ2_S、11层 IQ2_XXS、3层 IQ1_M，Down 为 Q2_0。
下述结论不外推到其他格式或生产默认参数。

## 1. graph 已启用，也要检查它实际如何提交

当前最有实测支持的改动是复用已有 UR 提交路径：immediate command lists、driver in-order、counter events 与 graph immediate append。
同一 EXE 的整模型 Code2K128 初筛/独立复测为 +2.765941%/+2.668767%，Prose 为 +2.454723%/+2.901650%；
相邻基线漂移均小于0.24%，完整请求采样空闲显存至少1597.504MiB。
这是组合效果，尚未分拆各开关贡献。

本次候选沿用已安装2025.3 adapter，不需要新依赖；仅在模型子进程中设置以下组合：

```json
{
  "UR_ADAPTERS_FORCE_LOAD": "C:\\Program Files (x86)\\Intel\\oneAPI\\compiler\\2025.3\\bin\\ur_adapter_level_zero.dll",
  "UR_L0_USE_IMMEDIATE_COMMANDLISTS": "1",
  "UR_L0_USE_DRIVER_INORDER_LISTS": "1",
  "UR_L0_USE_DRIVER_COUNTER_BASED_EVENTS": "1",
  "UR_L0_CMD_BUFFER_USE_IMMEDIATE_APPEND_PATH": "1"
}
```

应用queue为in-order还不够，graph描述自身也须满足in-order条件，counter事件才能走对应路径。公开UR源码记录Windows DG2默认关闭immediate的历史驱动限制；本机组合的适用性来自下面的实际调用、速度与质量检查，不能从开关名或源码默认值推定。`STRATA_VERIFY_EAGER`须从子进程环境中移除，值为字符串`0`也会使冻结引擎选择eager。性能测量不启用`UR_L0_DEBUG`。

真实模型API诊断及独立检查已通过，两臂均完成Short16、Code2K128、Prose2K128且完整输出匹配：

| 实际模型进程 | graph immediate append | 传统队列提交 | event-reset append |
| --- | ---: | ---: | ---: |
| 默认提交路径 | 0 | 192944 | 11533 |
| 候选提交路径 | 514 | 0 | 0 |

候选同时记录driver in-order及counter见证。计数是实际API入口，覆盖加载、prefill、decode及清理，不代表单次重放或仅decode的调用数，也不能据此推断GPU内编码的全部同步操作。
`UR_L0_DEBUG=1`仅用于诊断，未用于上面的性能测量；API调用数下降不能等比例换算成加速。

四个冷质量进程已全部通过：9场景/758固定目标精确等于冻结参考，必需概率有限，聚合PPL变化0，均为6297槽。
四个连续会话进程也全部通过：每进程1040个完整输出token匹配参考，最后256条评分四轮精确一致。
实际模型API、服务器引擎和实际DLL验证均已通过。已生成独立可选`strata-iq2_xs-runtime-append.json`；使用同一配置补验时，Short16、Code2K128、Prose2K128完整输出匹配，6297槽、READY空闲1856MiB，引擎正常exit0。三个实测2025.3 DLL的原生路径和SHA256均一致，生成及独立`server-dll-recovery.py --check`通过。默认配置摘要仍与冻结记录相同。
本组参数含 spec-min-p0.5、graph、固定缓存及独立EXE；没有测得它相对当前生产默认配置的收益。

复核及原始资料见 [runtime记录](runtime-paths-2026-10-29.md)。

在仓库根目录、无额外测试环境覆盖的PowerShell中，可使用现有服务器入口：

```powershell
Remove-Item Env:STRATA_VERIFY_EAGER,Env:UR_L0_DEBUG -ErrorAction SilentlyContinue
python -m serve.server --engine strata --config strata-iq2_xs-runtime-append.json --host 127.0.0.1 --port 8080
```

服务器验收通过`server.StrataEngine`执行上述三条完整请求；这次补验不作为新测速。保留冷/热质量和API证据，仅补跑一次服务器引擎来同步捕获直属子进程DLL，详细故障及恢复记录见runtime文档。

## 2. 复用单位是同专家的权重解码，先看真实重复次数

按专家分组后，同一权重行可服务多条输入，保持每条输入的累加及归约顺序。
不同专家的权重不能因为激活分数接近就共用解码；按分数排序主要改变执行顺序。
当前 IQ2_S 已有多输入路径，IQ2_XXS 尚逐条解码，但已有可复用的 Split16 load/apply。
隔离候选只接上这个现成解码器，没有重新量化模型。

对保留的真实路由，计算11个 IQ2_XXS 层的每行逻辑解码准备次数：

| 场景 | 原逐条 | 两条一组 | 四条一组 | 每专家仅准备一次的理想值 |
| --- | ---: | ---: | ---: | ---: |
| Code2K | 16170 | 12959 | 12165 | 12165 |
| Prose2K | 16720 | 13532 | 12711 | 12696 |

两条复用已覆盖理想可省工作的80.175%/79.225%。扩大到四条只额外省原工作量约4.910%，却需要更多同时存活的累加器。
56.382%/58.086%的输入条目没有同专家伙伴。
同一个编译后kernel的寄存器资源由静态代码决定；其中单条分支也可能承担更宽路径的资源代价。
因此先测两条复用，结合实际机器码的GRF、spill和吞吐决定是否值得扩大。

以上是逻辑准备次数，不是显存/PCIe字节、时间占比或tok/s。
隔离GPU筛选已结束：六个边界进程、27个计时进程、1782个保留批次的完整输出/Q8/守卫检查通过，但没有任何T通过双对照、两轮及mixed4/mixed8条件，不采用、不进入整模型。相对同源码未复用helper，mixed4第二轮所有T均回退0.581%–1.542%；纯显存相对原对象最高约+22%不能归因于复用。实现、完整范围及独立复核见 [IQ2_XXS结果](gu-iq2xxs-pair-2026-10-29.md)。
复核旧记录后确认，这个方向并非首次试验：[10月21日的复用实验](expert-reuse-2026-10-21.md)已测过E4/E2及E2-only版本，因单输入回退未采用。
当前候选直接用Split16 apply，旧版通过MultiW的两个整数累加器完成点积，二者并非同一源码；本轮另测混合驻留及1/2/3条目的组合。
原逐条dot还包含打包读取和整数符号展开，而Split16 load保留另一套展开代码。原冻结GU launch还携带`use_root_sync`，helper省略该属性；原对象与helper不是纯重编译对照，不能把二者差额全部归给复用。helper与pair对照没有支持复用收益。现有root-sync小探针也未提供正常graph下的性能归因，不据此新增删属性候选。
新增CPU分析复用原始路由/输出/哈希审计，生成及独立复核均通过：

```powershell
python -X utf8 build-sycl-a770-gu-iq2xxs-pair-20261029/pair-ceiling.py --check
```

## 3. 去掉spill不等于加速，资源策略应按格式和输入数选择

原生资源核对显示强制256 GRF能消除六个候选实例的spill，但全局256 GRF整模型独立收益只有Code约+0.64%、Prose约−0.15%，未过门槛。
寄存器增加会改变并发；不能把“spill变0”作为性能验收。
当前主要 IQ2_S GU/Down 本来无spill，也不应为其他小实例统一改变资源策略。
详见 [原生资源与已关闭候选](neo-igc-hotspots-2026-10-29.md)。

## 4. 单算子倍数要乘以可影响的关键路径份额

若某算子占总耗时5%，其耗时降为四分之一，整体理论加速为
`1 / (0.95 + 0.05 / 4) = 1.039`，约3.9%。这里5%只是算例。
若工作原本与CPU或传输重叠，实际收益还会更小；额外解码、重排、分派及寄存器开销也要计入。
当前eager累计kernel占比和ETW调度包络不能当作正常graph关键路径份额。
最终判断继续用完整2K输入/128输出、相邻基线与独立复测，而不把多个单算子百分比相加。
