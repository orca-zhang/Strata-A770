# Direct 差距：缓存替换策略与复制引擎分离对照

后续[日常参数验证](orca-direct-daily-margin-2026-11-04.md)发现热度差 1.5 在
1024/0.5／累计门槛 0.5 下反而使 Direct decode 下降 8.62%，所以没有修改日常默认。
下文 +10.29% 仅适用于本报告的冻结锚点条件。

2026-11-04，Windows 10 22H2、Intel Arc A770 16 GB、驱动 32.0.101.9034。
沿用[旧固定 Short 锚点](orca-direct-anchor-2026-11-04.md)，本轮确认了一个主机策略差异：
**Orca L0 的专家缓存替换热度差为 1.5，Direct 为 0.5**。
只将 Direct 的这一个常数对齐到 1.5，原 EU 复制路径从 **50.52 提升至 55.72 tok/s（+10.29%）**。
这里调整的是专家缓存替换条件，与 MTP 草稿概率门限无关。

复制引擎的额外收益较小。原热度差 0.5 下为 **+1.07%**，对齐到 1.5 后为 **+0.69%**。
后者 Direct／L0 为 **54.86／56.58 tok/s，Direct 仍低 3.04%**。
因此本轮没有证明原生路径比 L0 更快，也不能把之前的整版本差距全部归因于 API 层。
三个实验独立进行，以下收益只与各自的同期对照计算，不跨组拼接速率。

## 一、只对齐专家缓存策略

冻结原 Direct 的主机对象、原 EU 复制运行时及全部数值内核，仅重编主程序，
把 DG2 分支的 `c.first < v.first + 0.5f` 改为 `+ 1.5f`。
原 L0 编译分支已经使用 1.5；两个后端相同的 CLI 参数没有覆盖这个编译期差异。

| 新进程 | decode 中位数 tok/s | 保留范围 tok/s | TTFT 中位数 ms |
| --- | ---: | ---: | ---: |
| 原 Direct，前侧 | 50.5319 | 50.3812～50.6397 | 880.08 |
| Direct，热度差 1.5 | **55.7185** | 55.5150～56.0844 | 875.50 |
| 原 Direct，后侧 | 50.5084 | 50.4146～50.7987 | 876.59 |
| 同期 L0 | 57.8431 | 57.3671～57.9710 | 862.53 |

Direct 夹测基线为两侧中位数的几何平均 **50.5202 tok/s**，候选提升 **10.2896%**，
前后基线速率漂移 **−0.0465%**。候选相对本组 L0 仍低 **3.6730%**；
这里 L0 只有一个进程，不是对称的 L0 夹测。四个进程共 60 个完整请求。

## 二、原缓存策略下，只切换复制引擎

将已经校准的 BCS 补丁合入原锚点运行时，保留其 lease pool、参数及地址缓存优化。
变化限于 `dg2.hpp`、`recording.inl`、`runtime.cpp` 和新增的 BLT 包定义。
适配头只改变队列的复制角色选择，主程序只改变两处单 GPU 专家补入队列创建。
全部 **80 个主机编译单元**重建；69 个依赖新适配头，没有混入旧头定义。
没有导入后续专家并行调度或其他数值内核实验。

同一个候选 EXE 以启动时缓存的 `ORCA_DG2_BCS_COPY=0/1` 切换 EU／BCS，
三处明确请求的复制队列使用该选择，没有依赖队列创建序号。
GPU 基础检查通过 **1,632 项填充内容／边界检查**、12 项跨引擎依赖检查、
114 项完整缓冲区检查及 1,920 个回放样本。它们检查正确性，不作为模型吞吐收益。

七进程次序为 L0／原 Direct／重建 EU／BCS／重建 EU／原 Direct／L0，共 105 个完整请求。

| 本组指标 | tok/s |
| --- | ---: |
| 原 Direct，夹测参考 | 50.5824 |
| 重建 EU，夹测参考 | 50.5807 |
| BCS 候选 | **51.1234** |
| L0，夹测参考 | 57.4115 |

BCS 相对同一 EXE 的 EU 对照 **+1.0728%**，相对原 Direct **+1.0695%**，
相对 L0 **−10.9528%**。EU／原 Direct／L0 的前后速率漂移分别为
**−0.2990%／−0.1862%／−1.2014%**。BCS 保留范围 49.9836～51.4000 tok/s，
全部样本保留；不能将这一点估计视为稳定的跨负载收益。

## 三、统一热度差后，再切换复制引擎

仅把第二组候选主程序中的热度差改为 1.5，保留其统一重建的头文件、其他主机对象、
运行时和数值内核。两个 Direct 臂仍使用同一个 EXE，仅启动时的 EU／BCS 选择不同。
次序为 L0／EU／BCS／EU／L0，共 75 个完整请求。

| 本组指标 | decode tok/s | TTFT ms |
| --- | ---: | ---: |
| Direct EU，夹测参考 | 54.4805 | 946.84 |
| Direct BCS | **54.8578** | 935.19 |
| L0，夹测参考 | **56.5774** | 932.74 |

BCS 相对 EU 的吞吐点估计为 **+0.6926%**，相对 L0 为 **−3.0395%**。
EU／L0 速率漂移 **+0.5319%／−0.7121%**；EU／L0 的 TTFT 漂移为
**+2.7053%／+1.1427%**，本轮不确立 TTFT 改善。
小幅 BCS 增益与单次波动、基线漂移接近，不据此启用默认 BCS 路径。

## 四、专家补入量与阶段诊断

另开诊断进程，每个进程十次预热、三次保留。只在成功提交专家补入后汇总其调用次数和
`blob_bytes`，与原有阶段计时、路由计数一起记录。以下为最后三个请求的中位数，
不是上述 clean 吞吐样本，也没有将带计时的速率并入收益。

| 诊断构建 | 专家补入次数／请求 | 补入逻辑 MiB／请求 | 验证 ms／窗口 | 草稿 ms／窗口 | 显存路由命中率 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 原 Direct EU，热度差 0.5 | 640 | 843.5547 | 62.24 | 12.14 | 94.0666% |
| Direct EU，热度差 1.5 | 0 | 0 | 59.93 | 7.72 | 95.1434% |
| Direct BCS，热度差 1.5 | 0 | 0 | 59.84 | 7.73 | 95.1434% |
| L0，热度差 1.5 | 0 | 0 | 58.06 | 7.16 | 95.1434% |

原策略在每个热态请求仍触发 640 次专家补入，合计 **884,531,200 字节**。
对齐热度差后的最后三次请求均没有专家补入；显存命中由 34767／36960 增至 35165／36960。
这为[之前定位的补入与 MTP 调度干扰](orca-direct-gap-2026-11-04.md)给出了明确的主机策略原因。
这里是专家补入 API 的逻辑 H2D 数据量，**不是实测 PCIe 流量，也不是引擎全部复制或 D2D 次数**。
零补入只描述这一固定输入预热后的样本，不能外推为随机请求无需补入。

对齐后的 Direct 和 L0 均为零专家补入，路由命中数也相同。Direct BCS 仍多约
1.78 ms／验证窗口、0.57 ms／草稿窗口，20 个窗口分别约 35.6 和 11.4 ms。
验证 CPU 提交合计仅 1.944／0.668 ms／请求，约 1.276 ms 的差异不足以解释这些阶段差距。
阶段耗时包含等待与驱动调度，不能据此称为纯内核算术变慢，也不应继续用专家补入解释全部残差。

诊断初版在首组全部 13 次请求正常结束后，因带小数点的标签触发文件后缀替换而读错日志名。
失败阶段、三份已编译程序和所有原始日志均保留；续跑直接复用这 13 次完整请求，
没有为修复解析错误重跑 GPU 样本。公开归档包含失败记录与续跑脚本。
四组诊断共 52 次完整请求；加上 clean 样本，全轮 **292 次请求、22192 个输出 tokens** 均一致。

## 固定条件和统计口径

每个 clean 进程十次预热、五次保留。共 **240 次完整请求、80 个保留样本**，
每次 28-token 输入、76-token 自然输出、57／57 草稿接受、`reused=resume=0`。
使用引擎 DONE 的 `decode_ms`，排除模型加载、初始化、请求准备、图准备、预填充、HTTP 和排队；
TTFT 单列。没有内部逐阶段计时、GPU 时间戳或监控采样混入这些 clean 样本。
所有预热和保留请求均核对完整输出，不删除离群值。

Qwen3.8-Flash-Next IQ2_XS、FP16 KV、5771 专家槽／7922 MiB、显存预留 1536 MiB、
context／prefill 8192、MTP4、step／last min-p 0.5、累计阈值 0、`short-read=256`、
`adapt-decay=0.95`、每轮最多补入 32 个专家、PCIe fraction 0.16。
所有运行共享原来的 1341 文件内核包和初始专家 profile，不读取或保存新的学习 profile。
这不是日常 `short-read=1024`／`adapt-decay=0.5` 参数的测量。

Direct 在启动和负载结束均通过模块审计，没有加载 Level Zero、Intel GPU 用户态驱动／编译器、
SYCL、UR、oneMKL 或 OpenCL；L0 也核对了其实际运行库。
GPU 时钟未锁定，夹测漂移不是置信区间。单组固定输入的热态结果不能外推到随机问题、
长上下文或冷请求；本轮没有新的 PPL 或 Linux GPU 结论。

