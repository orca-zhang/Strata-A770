# A770：IQ4_XS 的 GRF256 对照

A770 16GB / PCIe3.0 / Windows / DPC++2025.3.2。**共享投影2560→640、五/六列在独立双基线确认中取得约15%–22%的算子收益。尚无整模型收益，不接入生产。** 该实验针对[实际 eager 解码](decode-gpu-profile-2026-10-28.md)中观察到的 IQ4_XS spill，采用已安装的 Intel `grf_size<256>` 内核属性。

原版 A 保留冻结 nativeMMVQ/IQ 对象与 `STRATA_IQ4_XS_SG16=2`。同 helper 的 C 显式指定 GRF128，B 指定 GRF256；两者均为 SG32/WG128，保留原 `WideIQ4XS` 运算体、整数点积、FP32表达式、XOR32归约及权重布局。只改变寄存器配置，三至八列生效，一/二列保持原版。

初筛覆盖真实输出头2560→248320、QKV2560→10240、共享投影2560→640及SSM输出6144→2560，各使用八个 device USM 副本。九个边界进程与36个计时进程通过完整输出检查，保留2376批：边界576项 eager，计时1728项 eager及216项 graph，包含守卫、未使用列和有限值。A1/C1/B1/C2/A2/C3/B2/C4/A3 各臂均保留全部11批、每批4次48-kernel图重放；每列先预热16图。计时包含主机提交和图完成，关闭 profiler。

初筛通过 QKV六列与共享三/五/六列；每个组合两轮相对原版和GRF128均须至少提升1%，各配对基线漂移不超过3%。绝对吞吐变化低于0.3%视为噪音，所有原数值保留。无其他形状/列数组合通过。

随后仅预选这四个组合，另开18个新进程，重复完整九臂双基线，保留1188批；864项 eager和108项 graph 完整输出均匹配冻结参考。其他列保留诊断，不参与选择。

| 独立组合 | 相对原版第一/二轮 | 相对同helper GRF128第一/二轮 | 结论 |
| --- | ---: | ---: | --- |
| QKV六列 | +0.780% / +1.768% | +1.127% / +1.610% | 首轮对原版不足1% |
| 共享三列 | +11.270% / +5.829%* | +11.554% / +8.799% | 第二轮原版漂移排除 |
| 共享五列 | +16.896% / +17.358% | +15.148% / +16.438% | 算子通过 |
| 共享六列 | +21.635% / +19.053% | +22.252% / +18.291% | 算子通过 |

`*`对应基线耗时漂移−4.273%，不能算作独立通过。共享五/六列的全部四个配对漂移均不超过2.523%。未以平均值掩盖失败，未放宽1%门槛。

提取和首个反汇编成功后，原审计误将名称中重复出现的模板参数计算了两次而停止。失败文件保留；单独恢复脚本只解析外层 launch 模板，复用原十二个二进制，不重编译或替换样本。其余反汇编、实际资源和哈希检查通过。没有采集本候选实际线程占用率或硬件访存计数，不能把 spill 的减少解释为唯一加速原因，也不能由此全局开启GRF256。

## 对当前模型的意义

已有 eager 采集中未出现640行/五列，640行/六列为114次、累计4.795ms，约占9.572915秒计算kernel累计时间的0.050%。该工作规模可能包含不同输入维度，因此这也不是候选2560→640的精确占比。正常graph的逐kernel覆盖尚未通过，不能将上述份额外推为正常graph或整模型加速上限。

本轮保留这项窄范围算子结果；没有新建该候选的整模型测速或质量验收，不声称其能满足整模型1%门槛。更广的小矩阵[SG16方案](iq4xs-register-lut-2026-10-28.md)刚完成原始Code/Prose 2K/full128筛选，收益仅+0.559%/+0.818%。继续优化应优先选择实际耗时较大的主存缺失和专家链。生产未改，35/40 tok/s尚未达到。
