# 工具调用结束判断：减少逐参数复制（2026-10-24）

本轮只修改 `serve/frontend.py` 中的 `call_end`，并增加一个小回归测试。参数结束检查 `param_end` 已保证终止符后是空白及完整的 `<parameter=` 或 `</function>`；现在利用这个条件，通过原生字符串查找推进到下一个标签，在原字符串上判断标签，不再为每个参数截取并 `lstrip` 整个剩余正文。首尾的空白处理仍使用标准库，部分标签的等待判断只截取至多一个标签长度。

没有新增依赖、正则、SIMD 实现或原生接口；现有 SIMD 扫描器的源码和二进制均未改变。保留首尾的常数次切片，没有宣称完整解析器完全零拷贝或整体线性复杂度。

两轮 CPU 完整解析计时中，原生路径的 1,000 参数整段调用耗时下降 **6.6%～10.6%**，8 字符分块下降 **5.1%～6.7%**。100 参数含 Unicode 空白的整段输入下降 **5.7%～6.0%**。Python 回退的 1,000 参数流式调用下降 **4.2%～5.1%**；整段输入只有第一轮通过漂移规则，下降 5.37%。这些是合成输入，未测真实请求的参数数量分布。

普通场景没有一致收益。约 1%～2% 的小幅变化、以及跨轮方向反复的差异按测量噪声处理，不逐项宣称提升或退化；这是实用解读口径，不是统计置信区间。原始变化全部保留。不能用本轮对照声称上一轮所有退化都已恢复，也不将各轮百分比相乘。

最初试过逐字符跳过空白。四处各 4,096 个 ASCII 空白的单参数输入中，该版本从 0.1361 ms 慢至 2.3859 ms（+1653%），因此撤回。最终版本继续让标准库处理长空白；原生 ASCII 长空白两轮变化为 −1.00% / −0.03%，Unicode 长空白为 −6.33% / −4.34%，没有保留逐字符版本的大幅退化。

Windows 10 19045、Xeon E5-2696 v4、CPython 3.11.9 x64，固定逻辑 CPU 42。基线是[起始偏移优化](tool-parameter-offset-2026-10-24.md)之后的冻结模块。计时包含创建解析器、全部 feed、收集事件及 finish；分块构造及正确性断言在计时外。每轮交错执行 7 组 A/B/A，B 中位数对比两个 A 中位数的几何平均；A 漂移绝对值超过 3% 弃用。
