# Orca Direct：有限自旋后转事件等待

2026-11-04，Windows 10 22H2，Intel Arc A770 16 GB，驱动 `32.0.101.9034`，oneAPI 2025.3。
本轮检查 8 µs／32 µs 的有限自旋是否能改善 Short，同时记录进程 CPU 成本。
它沿用[通用 M16 已验证构建](orca-generic-projection-m16-2026-11-04.md)的 Host 对象和数学 pack，
只重新构建 Direct runtime 的一个源码文件，并重新链接 EXE。没有采用独立的完成证明复用候选。
Direct 的三种设置共用同一 EXE，分别设置 `ORCA_DG2_WAIT_SPIN_NS=0/8000/32000`；
L0 使用上一轮新默认 EXE 和同一个数学 pack。

## 等待语义和检查

进程内只解析一次预算；没有增加 completion 字段，编译期断言其大小保持 48 字节。
仅在缓存和首次 fence 读取尚未完成后自旋。循环每 16 次 fence 探测检查预算及取消状态；
发现完成后仍经过原来的有序读取，超过预算则沿用原来的 TLS 事件、D3DKMT 注册和阻塞等待。
总超时仍从最早的等待起点计算，超时为 0 时不自旋。
这是软预算，包含时钟检查粒度，不能保证线程被系统抢占时的硬实时上限。

三种设置各通过 14 项 CTest，共 **42 项**，覆盖超时／observer、旧事件唤醒、host gate、
多队列、recording、release／reclaim 和分配恢复。
另通过 **360 个 FP16/BF16 形状、2520 项双专家完整输出检查、三组 BCS 队列检查**，
并拒绝非法预算。每组核对实际测试名称，不能用“未找到测试”的成功退出代替验证。
当前源码、默认等待、生产配置和部署 EXE 均未更改，候选保持隔离。

## 对照与计量

输入 ID、完整参考输出、七组配置和所有请求命令均在等待 GPU 锁之前准备。
固定实际 5771 专家槽、1536 MiB 预留、read256、decay0.95、MTP4/min-p0.5、
cumulative0、suffix0、prompt-cache0；Direct 固定 dependency-only1／BCS1。
每进程丢弃十次 Short28，再保留五次；每请求生成 76 个 token。
完整核对 token、生成数、草稿采纳／提供数、复用、resume 和结束条件。
READY 单列，DONE 净 decode 不含初始化、准备和预填充，TTFT 沿用原客户端。

CPU 计数仅在保留段前后各读取一次 Windows `GetProcessTimes`，
相减后除以五，得到**每完整请求的所有线程 CPU 时间**，包含预填充与 decode。
它排除初始化和十次预热，不是净 decode CPU 时间，也不是 GPU 利用率。
FILETIME 的 100 ns 单位不表示实际统计分辨率。
计时过程中没有内部 profiler、GPU 时间戳、填毒或新 GPU 诊断。
所有编译、GPU 验证和重型归档校验使用同一共享实验锁。

## 两轮结论与 CPU 范围

r2：8／32 µs 相对事件等待的吞吐变化为 -0.030%／-0.130%；Direct 事件等待相对 L0 为 -4.400%。每完整请求 CPU 时间为 45.286 ms／2175.000 ms，Direct 相对 L0 减少 97.918%。

r3：8／32 µs 相对事件等待的吞吐变化为 -0.019%／-0.026%；Direct 事件等待相对 L0 为 -2.130%。每完整请求 CPU 时间为 46.771 ms／2259.375 ms，Direct 相对 L0 减少 97.930%。

两种预算都没有在两个顺序中建立吞吐改善，因此不采用这项等待改动。
Direct 事件等待与 L0 的 CPU 时间差距在两个窗口中重现；它包含整条请求的预填充和 decode，
不是净 decode CPU 或功耗评测。8／32 µs 间的小 CPU 差异与控制漂移较大，不能据此选最佳预算。

## 独立等待 API 的 CPU 归因

另将原新默认 Direct／L0 的 main 入口各重新编译一次，加入进程内等待 API 观察器；
runtime、Host 库与数学 pack 都复用冻结原件，未把带诊断的耗时纳入上述成绩。
每后端十次预热后保留五次，合计 **30 次请求完整匹配、60 个阶段**。
每次可见等待调用前后读取线程 FILETIME，阶段边界读取进程 FILETIME；
线程嵌套只给最外层调用累计 CPU，避免求和重复。范围包含等待 API 的内部／驱动调用，
不意味着已经取得 vendor 内部的 CPU 栈或分辨每条内部指令。
观察器只修改应用进程的导入项和后续动态解析，没有给 driver DLL 添加补丁。
跨阶段结束的调用单独记录；线程计账粒度和观察器自身开销均会影响小数值。
